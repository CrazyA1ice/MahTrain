# MahTrain M3.25：流局查花猪付款范围对照与零和审计（v0.37）

本轮延续 M3.24 的四人对战可用性迭代，开始推进规则结算的可核验性。当前只增加**两套互斥假设下的对照预览**，不修改胡牌或杠钱流水，也不宣布正式结算规则。

## 范围争议

原 M3.3 只对“牌山耗尽时仍未胡牌的活跃玩家”试算查花猪、查大叫。但血战结束后的支付资格存在一种可能的差异：**已胡退出的玩家，是否仍可向花猪收取8倍赔付**？

因此同时列出：
- A：**活跃者之间试算**（原行为）；花猪只向其他非花猪活跃者支付 `8 × 房间系数`。
- B：**已胡玩家可收花猪赔付试算**（新增对照）；保留A中的全部付款，额外增加每个活跃花猪向每名已胡玩家支付 `8 × 房间系数`。

两版中的**查大叫**均只在仍未胡牌的活跃玩家中结算，且金额沿用已有真实听口和最高封顶番的推算；本轮未做获胜者复核听口、增收大叫赔付等没有依据的假设。

## 安全边界

- `scope_comparison.posted=false`；每个场景自身 `posted=false`，仅为只读数值，不能写入 `win_ledger` 或 `kong_ledger`。
- 每个场景根据逐笔 `transfers` 独立计算四家 `balances`，强制零和检查。
- 如果包含缺门公开副露、非稳定有效手牌等待确认情况，**不输出金额场景**，避免制造不可靠的数字。
- 已经合法胡牌的玩家在场景B中只作为花猪赔付的收款者；不被当作尚未听牌的付款者，也不会被要求再次听牌。
- 不改变原有M3.3的 `proposed_transfers` 和 `preview_balances`，为现有 UI/API/测试提供向后兼容。

## 测试

- 两套对照的逐笔金额、每位座位余额与零和审计；
- 不在查大叫中额外引入已胡玩家；
- 对未核验/不合法输入拒绝结算场景；
- 旧流局查牌与规则基线全部保留。

实际正式血战流局积分入账仍需先确定已胡玩家是否参与花猪赔付、缺门公开副露是否计花猪等口径。规则确认后可以复用本次已经检验过的转移账本作为基础。
