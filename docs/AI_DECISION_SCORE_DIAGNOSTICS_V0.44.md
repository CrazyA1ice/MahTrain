# MahTrain M3.32：决策质量与规则A正式积分的同组种子联合诊断（v0.44）

在用户确定的川麻流局方案A、M3.31 的 **baseline / basic / advanced / challenge 四策略配对初始洗牌、四座位轮换** 实验之上，新增赛后**聚合**诊断，研究“最低向听切牌多，不一定正式积分更高”的描述性现象。保留先前每局胡牌、失分以及结果复盘功能，不再模拟额外比赛。

## 1. 只使用同一组结算完整的对局

先用 M3.31 的 `controlled_four_policy_scores` 严格校验四人零和、四轮席位平衡、固定房间规则与正式方案A结算。只有 `official_score_analysis.per_seed` 中的**完整有效洗牌种子**才进入本轮决策指标统计。若其中任一局流局时存在待核验牌形，该种子四轮同时剔除，避免积分结果与决策评价的分母不一致。

本轮没有通过浏览器补取私有牌面，也不会从 JSON/SQlite 历史档案拼凑不完整种子。切牌分析数据已经存在于真实自对弈的**服务器私有临时轨迹**，先检查可信类型、每一条事件对应的AI座位，再汇总指标。API 只发总数、比率和解释文字，不发每次决策的暗牌、有效张阵列、额外牌墙或其他对手手牌。

## 2. 同行对照指标

| 指标 | 精确定义 | 注意 |
|---|---|---|
| 方案A正式积分 / 座位出场 | 正式胡牌净额加真实流局查花猪/查大叫已入账净额，除以该策略有效四轮座位出场数 | 使用真实零和账本，不能把模拟杠钱加进来 |
| 最低向听切牌率 | 服务器牌效评估器判定 `shanten_regret == 0` 的实际出牌数 / 该策略出牌次数 | 代表本项目内部评估结果，不是绝对正确的麻将决策 |
| 局部最优切牌率 | 当前评估器 `locally_optimal` 实际切牌数 / 出牌数 | 与最低向听不同，属于本项目预设规则 |
| 选后有效张均值 | 实际切牌的 `effective_tile_count` 累加 / 出牌数，计数已经考虑自身与公开可见牌 | 不是将来一定能摸到的牌，也不是真实胡牌概率 |
| 已观察放铳责任事件 / 百次弃牌 | 该策略所在座位作为 `source` 被别人胡牌的次数 ×100 / 该策略总弃牌次数 | 一炮多响可有多次责任；**不是风险模型输出或概率估计** |
| 切牌样本数 | 四策略在已核验种子中各自真实切牌的数量 | 不同策略可能切牌次数不同，均值用真实样本量而非固定次数 |

若有效种子=0或出牌数=0，不生成假的 0% 或 0有效张。前端显示“无可用样本”，CSV 保留空字段。其他正式积分部分仍按照原协议保留0净额的可能性（四家真实零和），不可将零积分与缺失样本混淆。

## 3. 不一致情况（不是因果）

以**每个有效独立洗牌种子**为一个对照单位，将某档 AI 与独立牌形基线比较：
- 该策略最低向听率高于基线，但方案A每种子正式积分低于基线的种子数量。
- 该策略最低向听率低于基线，但每种子正式积分反而高于基线的种子数量。
- 仅当两策略在该种子都有切牌时才计入分母。并列时不归入两类反向现象。

此项只检查同批样本下两个指标的方向是否不同，不把它归因于某次出牌，也不能证明某策略优秀/低劣。造成分差的可能机制包括选择的听口质量、公开副露竞争、实际放铳、胡牌番数、不同策略引起的未来牌墙分叉，以及当前规则原型的局限。

## 4. 操作与安全

启动 `python web_server.py`，在“**M3.9 独立规则基线与三档AI对照**”使用原有实验入口。完成后在 M3.31 结算积分结果下新增 **M3.32 联合指标表**、三档 AI 对基线“切牌指标好而分数低”数量，以及“导出四策略联合指标 CSV”。

CSV 只包含策略标签、种子数量、总出场、正式分、聚合切牌比率/次数、观察到的责任事件数，**不包含任何玩家的私有轨迹和手牌**。

## 5. 回归测试

```bash
python -m unittest discover -s tests -v
node tests/test_ai_independent_scores_dom.js
node --check web/ai_baseline.js
```

单元测试涵盖可核验/不可核验种子的相同分组、四座位积分审计、最低向听与正式积分背离场景、无切牌的空指标、放铳责任事件及错误类型/不匹配座位的拒绝，以及前端0样本显示与CSV隐私。

**局限**：该功能不估计反事实决策奖励，不训练风险模型，不声称可以从两场不同行动轨迹中识别严格因果关系。进一步研究应在固定较大种子数量下分别做可证伪的局部策略消融，而非根据单个合并分数立即调参。
