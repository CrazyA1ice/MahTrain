# M4.50：在新洗牌上验证中盘与前盘碰／过收益差

## 研究依据：不再根据旧测试挑选参数

用户提供M4.49的24个独立原shuffle安全汇总：17个自然出现首次合法可碰而原Challenge过牌的检查点；24场自然对局和68场完整真实分支，均值+21.25，方向9正、8负、7相等。公开牌墙分类（按当时剩余张数）：前盘≥40，10簇，碰减过平均−59分，3正7负；中盘20～39，7簇，平均+157.14分，6正1负；后盘少于20，0簇。该差异是在已经看到M4.49结果后发现的，属于探索发现而不是事先提出且已证实的结论。

因此本轮只冻结一个新样本假设：**中盘首次合法碰却过的真实终局净收益均值高于前盘**。不因更早的M4.47(+20)、M4.48(−30.83)、M4.49(+21.25)总体正负变化训练或调整策略，也不直接开发中盘碰牌的线上候选。

## 预注册样本和行动选择

- 全新48个独立原自然洗牌种子，建议区间**93600～93647**；每个种子四家继续原样使用Challenge。只有首次自然合法可碰但原Challenge选择pass时，记录其普通行动者视角可见的公开墙量分类。
- 与M4.49完全相同的两组未来墙、每组强制pass和peng，四个分支从真实同一局面及相同AI随机状态开始，全部使用真正FourPlayerOpening引擎执行完胡/杠/流局并核对净积分。世界0原墙的pass分支净额必须逐座位与未干预原自然对局完全一致。
- 无目标机会的种子也计入48个完整自然shuffle；对比前盘和中盘时只使用确实出现相应首次合法机会的shuffle，两个墙世界只在同一簇内求平均，不能视为独立。
- 前盘剩余≥40，中盘20～39，后盘<20。**固定唯一主对比为中盘组碰减过均值－前盘组碰减过均值**。分组必须各至少有8个独立自然shuffle，否则输出“insufficient_group_support”、不展示对比均值和Bootstrap区间。
- 如两个分组都达到预设最低数，按独立原shuffle簇分别组内重抽样4096次，采用运行前固定随机种子450，输出组间差及描述性95%分位区间。只在该探索性区间下界大于0时标记本轮的样本方向支持原假设，但仍不是总体EV证明或新的正式策略。
- 任一个单独阶段独立样本少于8时，只输出数量，隐藏平均净分、中位数以及正/负/零个数，避免从少数局面中泄露终局行为和制造不稳健结论。

## 历史研究不重用和断点机制

程序核验M4.49训练模型指纹、冻结的M4.49两份代码SHA256和原24个M4.49私有结算分片，通过全部原始24簇重算安全JSON后核对；再顺M4.48、M4.47、M4.46、M4.45和M4.34、M4.37/39/41/42/43/44来源计划确认历史种子不重叠。不能把先前已看过的24个分层结果混在新48簇中。

新的M4.50私有计划冻结源码摘要、所有来源、种子范围、早中晚阈值、最小独立样本数与Bootstrap参数。只在一个原shuffle自然对局和4个必要分支全部真实结算后，原子保存一个SHA-256校验的私有分片；--resume只复用完整有效的簇并拒绝更改源码/参数/模型来源。源码摘要只校验意外改动一致性，不是数字签名。

新的safe JSON不含具体洗牌种子、牌名、手牌、未来墙、对手暗手、权重或私人文件路径。研究结果仍只是原Challenge当前首次过碰分歧下的已实现完整局面条件分支，不得视为未知真实墙的无偏普遍行动期望、严格因果估计或AI强度证明。

## Windows PowerShell本地运行

在MahTrain根目录：

~~~powershell
cd D:\ChatGPT\MahTrain
git switch main
git pull --ff-only origin main

python examples\run_pong_phase_confirmation.py --train-dir data/selfplay/m434-smoke --prior-m449-dir data/selfplay/m449-pong-strata-24 --seed-start 93600 --out-dir data/selfplay/m450-phase-48
~~~

**确认93600～93647此前没有用作其他未登记的本地实验seed。** 所有真实对局在本机计算，私有历史文件仍需保留于data/selfplay中，无需额外支付GitHub Actions费用。如果程序异常中断，在同一命令最后加上--resume。不要删改已完成的私有分片，或改变来源/代码/seed后在同一目录续跑。

完成后：

~~~powershell
Get-Content data/selfplay/m450-phase-48/safe_pong_phase_confirmation.json
~~~

**只分享safe_pong_phase_confirmation.json。** 不要上传PRIVATE计划、私有分片、隐藏牌墙与模型权重。

## CI验收与解释

~~~powershell
python -W error::SyntaxWarning -m unittest discover -s tests -p "test_m450_pong_phase_confirmation.py" -v
~~~

CI以模拟完成对局结构快速检查48簇/最多240场调用合约、真实M4.49历史SHA检查、断点恢复、最小组样本保障；还在固定测试种子中真实运行FourPlayerOpening及既有四条完整终局分支，验证真实规则路径。CI的240场合约桩**不代表替用户执行了240场真实游戏**。真正新48seed的结果必须由上面的本地命令产生。

如分组差异在新48seed上得到相同方向，只能把其视为更值得研究的局面假设。随后仍应单独预留新数据做有公开牌况可见风险、番值、现有策略约束的独立训练/确认，不能从这次新测试样本直接构建一条经验证更强的“中盘碰牌规则”。
