# MahTrain M3.1：四人弃牌碰杠胡响应与墙尾补牌（v0.13）

> 开发里程碑：**已实现四人血战的碰杠胡牌权裁决和赢家退出的规则子集**，但**尚未完成正式结算、天听全过程、流局查花猪/查大叫、三档策略AI及多人账号座位认证**。四川血战 v0.4 配置保持 `draft / enabled=false`，不能作为真钱游戏、正式联机比赛或已验收的完整四川血战引擎。

## 1. M3.1 新增的可执行规则

在 v0.12 四家发牌、同时换三张、换后同时定缺的基础上，状态机 `FourPlayerOpening` 新增：

1. **弃牌响应窗口**：别人打牌后所有仍活跃、且不是弃牌者的玩家，均需通过 `claim_options(seat)` 和 `respond_discard(seat, action)` 提交一次“过 / 胡 / 碰 / 明杠”（只允许当时合法的动作）。收齐后统一决断，未收齐不能进入下一家摸牌。
2. **合法自摸或点炮胡**：实际调用 `is_legal_win` 验证四组面子加一对将或门清七对，同时检查所声明缺门、已锁定副露和四张实体牌限制，不允许玩家自行申报不合法胡牌。
3. **一炮多响**：同一张弃牌可以被多个合法玩家选择点炮胡，记录多个赢家。胡牌者之后退出摸切，其他活跃玩家继续。凑够**三家已胡**立刻结束摸打。
4. **胡 ＞ 明杠 ＞ 碰**：多个合法响应冲突时先处理所有胡；没有胡时明杠优于碰；同级竞争使用离弃牌者顺时针最近的座位（规则尚待后续进行全面裁决细则验收）。碰后直接拥有切牌权，**不能再摸一张**。
5. **明杠**：取他人弃牌＋自己暗手三张，固定为副露四张，立刻从**牌墙尾部**补一张，再切牌。
6. **暗杠**：自己拥有四张同牌时可以锁定暗杠，补牌也从**牌墙尾部**拿。对其他人公开牌面时，暗杠的具体牌种不在公共 `melds` 中暴露；本人能看到自己的暗杠牌。
7. **补杠**：原有碰刻后自摸第4张，可声明升级。必须先进入**抢杠胡响应窗口**：别人合法胡则补杠撤销，原碰刻保留，额外第四张成为实体弃牌；无人抢胡时才升级成四张杠并从尾部补牌。两种路径均保持108张物理守恒。
8. **牌权与实体牌守恒**：引擎始终核验4张同牌上限/共108张，已被碰、杠转入副露的弃牌不再作为自由弃牌重复计数，包含**0号座位领走的弃牌**。冻结副露区不可再任意切出。暗手牌以万→条→筒、组内1→9升序展示。
9. **摸切结束**：三家胡牌后 `finished`，不再摸打；牌墙耗尽且无法下一摸时 `wall_exhausted`，但查花猪/查大叫和余额清算**尚未接入**。

对于上一里程碑的 `pass_all_claims_demo()`，保留为**老版演示专用**兼容接口，它不是对真实响应的实现；M3.1 的新试验模式只调用逐家合法响应接口。

## 2. 网页增加 M3.1 响应试验区

在仓库根目录：

```bash
git pull origin main
python web_server.py
```

打开 `http://127.0.0.1:8765` 并按 `Ctrl+F5`。

进入 **「四人血战 · 碰杠胡响应试验（M3.1）」**：

- 你只操作**0号座位**；其他三家仍然是确定性选择策略的**脚本对手，不是训练过的 AI**。它们按“有胡则胡，否则杠、否则碰、否则过”的规则作简单决定。
- 先看牌、选四张中的三张同色牌换出（**准确为三张**）、四家交换、再选择定缺；完整换牌和定缺过程按已确认规则执行。
- 轮到自己切牌时，点击自己的牌；如果自己当前合法可胡，出现“确认自摸”；如果允许暗杠/补杠，出现对应按钮，杠牌前有二次确认。
- 当别人弃牌时，如果你能选择胡、明杠或碰，页面会提示合法选项与“过”；**必须手动决定**，系统不会替你乱碰或错过胡牌。补杠时可能出现抢杠胡窗口。
- 页面分别展示自己的暗手牌、不可再操作的副露/杠区、公开弃牌、各家暗手张数、已胡玩家、近期公开事件，以及剩余牌墙。不会把另外三家暗牌、尚未交换牌、未来摸牌或尾牌顺序返回给浏览器。
- 每次脚本行动后最多连续运行有限步，脚本不负责合法的用户决定；所有人用随机能力令牌识别一个本地试验局，客户端提交座位ID不会令其获得其他人的手牌或行动权。
- 老版 **“四人血战 · 开局规则演示（M3预览）”** 仍保留供单独学习发牌、换牌和定缺；原来的单人14轮、四种单题、错因复盘与 SQLite 均保持独立。

## 3. 关键技术模块与测试

| 路径 | 本轮职责 |

## 4. 仍未实现，不能误判为已完成

- **番数与积分结算账本**：金钩钓、清一色、天听等结构的独立评分算法已存在，但 M3.1 尚未把每次点炮、自摸、杠、抢杠与各座位的正式余额账本可靠联动；特别是杠上炮“杠作废”、已入账杠钱撤回等未确认环节，不能编造收益。
- **天听完整生命周期**：闲家换牌后基准听口、稳定摸切后复核、碰牌强制取消、杠牌保留资格等，需接入完整状态历史。
- **牌墙耗尽查花猪、查大叫**：只实现状态终止，不向任何人强制划款。
- **牌型/响应边界**：缺门牌强制先出、部分过手胡细则、抢杠支付对象等仍待确认。M3.1 对缺门牌禁止碰/杠，但没有私自实现未确认的“必须先切缺门”的强制出牌政策。
- **真实三档 AI / 多人联机**：另外三家只是规则合法性保证下的固定优先级脚本，无法代表基础/进阶/挑战AI的实际棋力。对局会话只保存在本地Python进程内存中，不能当作在线多玩家账户服务或正式比赛。

**下一阶段建议**：M3.2 增加天听轨迹、明确且可验证的胡牌事件上下文，随后设计结算账本；每个争议规则边界先补固定牌例，再接入 AI。
