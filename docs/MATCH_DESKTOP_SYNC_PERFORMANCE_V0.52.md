# MahTrain M3.40：四面牌河、牌背偏好、定缺徽章、语音同步与延迟拆分（v0.52）

本轮只优化**桌面**四人血战体验，不做移动端重新布局，不改胡牌、番数、自摸加底／加番、查叫和杠钱规则。

## 桌面牌桌

- 四边牌河按实际出牌座位旋转。本人（下方）正向、对家（上方）倒向、左侧横向90°、右侧横向-90°；只作用于公开牌河牌面，不改变桌面牌序、被碰杠拿走的占位或实际胡牌裁决。
- 牌河区域改为自动扩展，不显示右侧的内层滚动条。桌面大牌河超出时由中心网格增长，而不是把弃牌切掉；保留整张宽牌桌的必要水平浏览。
- 桌面上、左、右三个 AI 暗牌背适度放大。牌桌选项增加四种牌背配色：翡翠绿／宝石蓝／朱砂红／琥珀金。仅改变 CSS 颜色，不改变暗牌内容或随机种子。
- 定缺公开后，四个座位增加显眼的带边框“缺万／缺条／缺筒”徽章；未定缺时不显示；左、右、顶部 AI 均可直接识别。

## 语音与对局推进

- **出牌只念牌名**（如“七条”），不再说“某某号打七条”。碰、杠、胡仍播报动作名称；暗杠不报私有牌种。
- 牌面动画先显示服务器已经确认的公开动作，语音再开始。播放器同时等待最小画面驻留时间 **和** 浏览器语音合成的 `onend/onerror` 才前往下一帧。
- 若系统没有 TTS、用户关闭语音，自动解除语音等待。浏览器语音引擎既不触发结束也不报错时设有约2.5秒保护阈值，避免无限冻结；手动跳过动画会中止对应声音并跳过该段等待。
- 服务端的人机对战不再一次请求完成数十个 AI 操作。用户动作立即提交，后续由客户端在上一帧与播报结束后依次调用 `match_continue`，服务器每次至多推进**一个**已核验规则转移。这确保真正不会在上一张牌播报完毕前执行下一家的下一步。
- 仍沿用服务端四家规则状态机、已胡退出、公平 AI 视角、抢杠裁决。自动研究／AI 对局实验代码不使用该交互 API，因此不受影响。

## 卡顿诊断与改善

原先一次出牌可能等待整条 AI 行动链：机器人摸牌、弃牌、其他机器人响应、碰杠、再次摸牌……服务端运行结束浏览器才收到结果并启动回放。这个流程不仅造成波动，还让语音被下一个动作的 `cancel()` 打断。新方案缩短了**首次响应的计算范围**，把连续 AI 行为变成逐步可见的操作，待当前声音和动画结束才继续。

同时降低无人操作阶段服务端重复计算本人听牌提示的开销。每一步响应单独返回服务器 `server_elapsed_ms`，页面直接显示“服务器本步计算 ×× ms”，方便将服务器计算与浏览器端的语音／动画耗时区分。该计时不涉及墙牌、暗手和种子，不应被误当成网络 RTT 或端到端完整响应时间。

## 回归重点

```bash
node --check web/match.js
node tests/test_match_voice.js
node tests/test_match_playback.js
node tests/test_match_board_dom.js
python -m unittest discover -s tests -v
```

核查：定缺公开前不冒出徽章；换牌背不发送对局请求；其余三家暗手仍不可见；音频尚未结束时播放器不会迈向下一家；服务器仅在无人类待决选项时接受 `match_continue`；返回公开帧上限、SQLite 档案与旧 AI 实验保持兼容。

**客观限制**：浏览器 TTS 发声启动延迟受操作系统与安装声音影响，不能保证零延迟，需当地浏览器真机体验；2.5秒保护阈值以不死锁为优先，极慢语音引擎可能被截断。更新不保证任何环境每一步动作的网络总耗时完全一致。
