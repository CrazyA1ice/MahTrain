# M3.76 · 經典 Majiang UI 中文碰杠胡决策和键盘出牌

## 本轮修复的可见问题

此前 E 方案的动作按钮只有笼统的「碰」「杠」「胡」「过」，并且自己有暗杠/补杠选项时直接显示 `杠 m4`、`杠 p7` 等底层牌码，不能明确知道刚才是谁打的哪张牌，也不能直观看到是暗杠还是补杠。

在**不增加牌桌上方任何动态动作条**的前提下，本轮仅增强原本就位于 Majiang 牌桌中心的固定大小操作面板：

- 碰杠胡请求出现时，明确显示「3号AI打出五筒 · 请选择碰、杠、胡或过」，可选按钮仅由 **Python 服务端合法 `claim_options`**决定，按「胡、明杠、碰、过」呈现。「过」始终是明确用户选择，而不在可胡牌时自动跳过。
- 抢杠胡请求出现时，明确显示「2号AI补杠八条 · 是否抢杠胡？」，只显示服务器允许的「抢杠胡、过」，不误把抢杠阶段变成「碰、杠」。
- 自己有杠牌选项时，明确区分「暗杠 四万」「补杠 七筒」。是否真能杠仍由服务端 `kong_options` 和 `choiceAction` 双重许可决定；可以不杠，直接点击自己的手牌打出。
- 修复实质接口错误：Python 后端在普通碰杠和抢杠胡阶段**都使用 `claim_submitted`**表示已提交选择，旧前端错误尝试读取不存在的 `rob_submitted`。现在统一依据服务器真实字段限制重复响应。
- 键盘选牌支持先 `Tab` 聚焦实体手牌、按 `Enter` / 空格选择、再按一次确认出牌；选择后原版 Majiang `Shoupai.redraw()` 会替换实体 GIF DOM，本轮主动将键盘焦点恢复到**同一个原始手牌索引**，防止重复按 Enter 因丢失焦点而无效。
- 键盘 `Esc` 清空当前出牌或换三张的选择，而不向服务器发任何命令。保持两张相同牌的物理索引，最右摸到的牌和手牌中同名旧牌，分别发送 `from_draw:true/false`。

## 不改变的行为

- Majiang UI 原生四人桌面、原版实体牌面、56格四向牌河，以及上轮已验收的固定桌面几何全部保留。
- 普通出牌仍然不在牌桌上方弹条；已有语音播报继续独立运行，AI 不等待语音时长。
- 常驻「已胡」标记、四家净收支与番型/杠钱、真实已结束牌局同标签页刷新恢复均保留。
- Python 四川血战规则、定缺、换三张、AI 策略及任何计分均不改动。

## 自动验收

`frontend_2d/test/action-choice.test.mjs` 对照 Python 真正的响应字段测试已提交与未提交抢杠胡、只能过、不允许自家碰弃牌、可选胡/碰/明杠与自己暗杠/补杠中文按钮，并验证展示层不修改 Python 视图。

`frontend_2d/test/browser-action-choice.mjs` 在真实 Chromium 中加载编译好的 Majiang UI，并使用合法响应结构的固定 HTTP 数据驱动按钮点击：可自摸+两种杠→AI打出五筒的胡/明杠/碰/过→AI补杠八条的抢杠胡/过→键盘 Enter/Esc 出牌和区分两张 `s8` 的摸切/手切。逐阶段核对实际向 `/api/action` 发送的指令及牌桌坐标未变。

现有真实 Python 完整对局、牌河满格、AI 已胡常驻和服务器结算测试也随 CI 继续执行。浏览器按钮测试的数据是确定性的**服务端形状夹具**，不是把所有罕见抢杠胡都宣称已经自然对局复现。
