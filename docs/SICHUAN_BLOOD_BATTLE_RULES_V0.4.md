# MahTrain 四川血战到底规则说明 v0.4（当前规则草案）

> **最新规则优先级**：v0.4 综合用户 2026-10-16 进一步确认，**替代 v0.3、v0.2 和 v0.1**。旧规则不得作为训练或对战依据。  
> **状态**：规则说明已整理；部分未定义细节仍待确认，配置仍为 `draft / enabled=false`。  
> **配置**：[v0.4 JSON 草案](../configs/rulesets/sichuan_blood_battle_v0.4.draft.json)。  
> 标注为「待确认」的细节不擅自推定。

## 1. 基础规则

- 四人，真人 1 名与三名 AI；只有万、条（索）、筒（饼）三门，共 27 种、每种 4 张、合计 **108 张**；没有花、风、箭牌。
- **不允许吃**，允许碰、明杠、暗杠和补杠。不能碰自己定缺花色的牌。
- **每局强制换三张**：四位玩家同时选出 3 张相同花色牌，按本局随机方向交换（顺时针、逆时针、对家）。
- **换牌后强制定缺**：必须**先发牌、看自己的手牌、完成换三张后**，四家同时以盖牌方式作出定缺声明，不存在“未看牌提前定缺”。胡牌时不得持有自己定缺的花色，且不能同时有三门花色。
- **天缺**：在完成换三张后，若手牌里只有两门花色（第三门已经没有牌），称为“天缺”，可以直接定该缺少的花色。天缺只描述定缺阶段的手牌状态，**不额外生成不存在的牌，也不跳过看牌与换三张**。
- **一炮多响**：一人点炮可以有多个赢家，每位赢家分别与点炮者结算。
- **血战到底**：已胡的玩家退出摸打，其他活跃玩家继续；3 人已胡（只剩 1 人）或牌墙摸尽时结束摸打。
- 每局随机指定庄家；随机公平目标为 VRF + 可验证公平、种子可追溯，具体协议尚未实现/确定。

## 2. 发牌及游戏流程

1. 庄家 **14 张**，其他三人每人 **13 张**；墙剩 **55 张**（108 - 14 - 13×3）。原始文本的 68 张已校正。
2. **玩家先看已发到自己手里的牌**，各自选三张同色牌并同时换三张，每局随机方向；不改变各自手牌总数。
3. **换牌结束后四家同时盖出定缺标记，选择自己本局不能保留的花色**；这不是摸牌之前的决定。若换后只有两门牌则视为**天缺**，可直接声明手中不存在的花色。声明记录为本局缺门，不从实际手牌再额外扣掉一张牌。
4. **庄家已持14张，先出牌**，不能多摸一张；其他人按顺序摸一张、出一张。
5. 被出牌后合法操作：**胡（支持一炮多响）＞杠＞碰＞下一位活跃玩家摸牌**；不能吃。
6. 碰：持 2 张同牌，接其他人弃牌形成明刻，碰后直接切 1 张，不另外摸牌；不能碰自己缺门花色。
7. 杠：尾部补摸牌；如补牌直接胡则为杠上花。
8. 3 人胡牌时终局；若牌墙耗尽而**场上仍有至少2位未胡的活跃玩家**，执行查花猪、查大叫（见第7节）。只剩1人时已因3人胡牌结束，不触发流局查牌。

**重要术语**：此版本把“流局结算触发”定义为「牌墙耗尽且仍有至少 2 位活跃玩家」，而不是“整局无人胡牌”。即使之前已有1～2位玩家胡牌，只要牌墙耗尽时场上仍有2人或以上，都要查花猪及大叫。

## 3. 胡牌结构及定缺

- 标准胡：四组面子（顺子/刻子/杠子）加一对将；杠作为一个面子，实际有4张，需连同公开面子判断。
- 七对：14 张组成7对，不能有碰杠；四张相同的牌可视为两个对子并触发龙七对。
- **金钩钓**：玩家已经通过碰/杠公开组成四副面子，手里**只剩1张牌**作为单钓结构，再自摸或胡其他人打出的配对牌而胡。可与清一色、天听在计番层面复合；不能与对对胡复合计算。实现时需分别校验四副面子与最后的将牌、是否持缺门。
- 所有胡牌均必须满足定缺（所有持有和组成的牌不含玩家选定的缺门）。
- **天胡**：庄家开局起手14张（即换三张、定缺完成且庄家首次出牌前）已经可合法胡，直接胡牌。此处采用「起手14张直接胡」的已确认定义；是否允许以换三张前的14张判天胡见待确认事项。
- **天听（已确认）**：仅闲家，换三张完成后起手13张必须听牌；记录当时**完整听牌集合 W0**。此后每次摸牌切牌必须保持原来的听口（处理该次动作后依然是 W0）；**碰牌立即取消天听资格，即便碰后原听口恰好保持不变也一样**；**杠牌本身不会取消天听**，但杠后稳定手牌的听口仍必须等于 W0。引擎必须同时检查碰牌历史与听口集合；由碰牌升级成补杠也不能恢复已取消的资格。天听可与其他允许的牌型复合。后续需定义抢碰/补杠过程中的具体检查时点，初版采用“每轮完成切牌/副露后达到13有效张”的稳定状态作为检查点。

## 4. 番型与计番

### 4.1 番型明细（均为**未封顶的原始番数**）

| 番型 | 原始番数 | 条件或关系 |
| --- | ---: | --- |
| 平胡 | **0** | 一般四组面子+一对将；1倍底分，已确认 |
| 对对胡（大对子） | 1 | 四组刻子/杠子+将牌 |
| 清一色 | 2 | 胡牌各面子/将均同一花色 |
| 七对 | 2 | 门清七个对子 |
| **天听** | **2** | 仅闲家，换三张后13张即听，且后续不换手牌；**允许与其他牌型复合** |
| **金钩钓** | **2** | 碰/杠四副面子后剩一张单钓，自摸或点炮胡；**可加清一色或天听，不可加对对胡** |
| 清对 | 3 | 同时满足清一色和对对胡（单独结构番型，不再叠其子项） |
| 龙七对 | 3 | 七对中含四张同牌，不再叠七对；根数减去用于龙七对的1根 |
| 天胡 | **4** | 庄家起手14张直接胡 |
| 地胡 | **4** | 闲家胡庄家第一次打出的牌 |
| 清七对 | **4** | 同花色七对 |
| 清龙七对 | **5** | 同花色龙七对，扣龙的1根 |

**已经取消“封顶番”这一番型等级**：天胡、地胡、清七对统一为原始4番，清龙七对原始5番；**规则配置上的最高番数上限依然存在**，默认3番，须在全部合法叠番算完之后统一截断。

### 4.2 普通番型互斥，与允许复合的例外

- 基本的**结构型/组合型**胡牌（平胡、对对胡、清一色、七对、清对、龙七对、清七对、清龙七对等）原则上使用最高有效的一个结构牌型，不对其父子关系重复计番。例：清对 3番，不再加对对胡 1番、清一色 2番；清龙七对 5番，不再加清七对等子项。
- **天听 2番是允许复合的特例**，在符合天听条件时可加到其他允许的牌型上，例如天听2 + 清一色2 = **原始4番**。
- **金钩钓 2番是允许部分复合的特例**：
  - 金钩钓2 + 清一色2 = **原始4番**。
  - 金钩钓2 + 天听2 = **原始4番**（需同时真实满足两个条件）。
  - **金钩钓不得与对对胡重复计算**；尤其不能绕过限制，将四组已碰/杠的牌再次算成清对以抬高金钩钓的分数。
  - **金钩钓 + 清一色 + 天听 = 原始6番，已明确允许三重复合**；实际番数还须另加合法根等额外番后统一按房间封顶。
- 其余跨类型复合（如天听+龙七对、天听+天胡）是否全部相加，需要与逻辑可同时成立的条件一并检验；目前天听“可复合其他牌型”为已确认方向，具体互斥表待形成回归案例。
- 金钩钓的四副碰/杠与普通“门清”七对结构上不同，不能误判七对。

### 4.3 另加番

| 另加番 | 值 | 说明 |
| --- | ---: | --- |
| 杠上花 | +1 | 杠后补摸自摸 |
| 杠上炮 | +1 | 杠后补牌，随后打出的牌使人胡；此杠作废 |
| 抢杠 | +1 | 其他人胡补杠的第4张牌；此杠作废 |
| 根 | 每根 +1 | 胡牌中每4张相同计1根；龙七对/清龙七对按规则扣除其用于成龙的1根 |

### 4.4 统一封顶：已确认

按以下管线显式计算：

1. 判胡合法性与定缺；识别成立的结构番型及可复合例外，按明确的**互斥/可叠加关系**计算基础番；
2. 加入可用的 **天听、金钩钓的合法复合番**以及杠上花/杠上炮/抢杠/根等额外番，避免重复；
3. 得到 **原始合计番数** `raw_total_fan`；
4. **最终番数 = min(raw_total_fan, configured_fan_cap)**，默认上限3番；倍数 = `2 ** final_fan`。

例如：金钩钓2+清一色2 = 原始4番；**金钩钓2+清一色2+天听2=原始6番**（尚未加入可能的根等奖励）。默认上限3 → 实结3番/8倍，若上限调到6且无其他附加番，可结6番/64倍。清龙七对原始5番，同理在上限3时按3番结算。

**注意**：因为原始番数可高于3，规则配置应保存 `raw_total_fan` 与 `effective_fan` 两字段，前端可显示“牌型4番，房间封顶3番，实际8倍”。

## 5. 碰杠及支付

| 动作 | 条件 | 支付 |
| --- | --- | --- |
| 碰 | 别人打牌时自身两张同牌，不得碰缺门 | 不单独记分 |
| 明杠 | 别人出牌，自己三张同牌 | 出牌者付 **2×底分** |
| 暗杠 | 自摸形成四张同牌 | 其他每位活跃玩家各付 **2×底分** |
| 补杠 | 已碰三张后再自摸第4张 | 其他每位活跃玩家各付 **1×底分** |
| 吃 | 禁止 | — |

- 杠牌后从墙尾补摸；杠上花额外1番。
- 杠上炮/抢杠：胡牌者额外1番，相关杠**作废**；已入账杠钱须撤销或改为在确认后才入账（具体机制待定）。
- “底分”是否与“房间系数”完全相同，仍待确认；先保持命名分开，待统一后再实施正式计分。

## 6. 胡牌支付与算分示例

- 0番对应1倍、1番2倍、2番4倍、3番8倍；原始4番对应16倍、5番32倍，但**要按房间封顶后的有效番数计实际支付**。
- **点炮或抢杠胡**的一笔支付 = 房间系数 × `2 ** final_fan`；一炮多响逐赢家结算，不额外加底或加番。
- **自摸模式可选（M3.38）**：用户在开局前选择“自摸加底”或“自摸加番”。设底分为 `B`、牌型封顶后为 `f` 番，其他尚未胡的活跃玩家每人分别支付 `B * (2**f+1)` 或 `B * 2**(f+1)`，赢家按实际付款人数收款。自摸支付加成不更改牌型 `raw_fan` 或 `effective_fan`。
- **系数100、2番自摸三家**：加底每家-500，赢家+1500；加番每家-800，赢家+2400。
- **系数200、3番自摸三家**：加底每家-1800，赢家+5400；加番每家-3200，赢家+9600。
- 系数100，点炮0番：赢家+100，点炮者-100。新模式不影响点炮结算。
- 未传新模式字段的旧 API/旧实验保留曾经的一笔 `B*2**f` 倍率，不修改老局历史积分；新网页只提供上述两种可选模式。具体见 [M3.38 v0.50](MATCH_SELF_DRAW_MODES_V0.50.md)。
- 原文提到“最高赢48倍/输40倍”仍只作为经验性陈述保存，不作为程序硬封顶，直到确认其含义。

## 7. 血战结束与流局查花猪、查大叫

**现已确认启动条件**：

- **达到3名赢家**：只余1名活跃者，立刻终局，不进入流局查花猪/大叫。
- **牌墙摸尽、场上还有≥2名活跃未胡玩家**：**无论本局之前是否有人胡过牌，都必须执行**“查花猪 → 查大叫”。

**先查花猪**：

- **没有打光自己定缺的花色，就属于花猪**；不再使用“必须同时持有三门牌”作为必要条件。花猪可只剩两门牌，但其中包含自己的定缺花色。
- 每个花猪分别向每名**非花猪**玩家付 **8×房间系数**。在已胡过人的场景，结算对象以当前仍在场的活跃玩家为准是**建议的待确认实现选项**；用户本次明确的是“场上≥2人才查”，并未单独给出已胡玩家在赔付对象中的身份。
- 花猪不参与随后查大叫。

**后查大叫**：

- 非花猪且未听牌玩家，按每位听牌者**最大可能合法番数**分别向听牌者付款，最高受房间上限3番约束（也可配置）。
- 只要任何玩家仍持选定缺门花色，就不能视为**合法胡牌的听牌者**。
- “最大可能番”应依据可胡牌张、定缺、结构番型与可证实复合关系计算，最后应用可配置封顶；事件限定的天胡/杠上花等不能从孤立13张手牌推定。
- 已胡玩家是否参与查花猪/大叫的收付、明暗杠是否算仍“持有”缺门花色等，仍待确认；不能借这次条件确认自行填充这些细节。

## 8. 牌效训练与测试标准

- 所有训练判胡、听牌与向听均应用**已选缺门**；单题与清一色题的解答采用局部最优切（不退向听、向听数最小 → 有效进张较大 → 胡牌机会及收益）。
- 番数/潜在收益显示要区分**原始番数**与**房间封顶有效番数**，尤其金钩钓清一色4番而默认只实结3番。
- 训练用孤立牌型无法推断庄家身份、天胡/地胡等事件状态；**天听必须核验换三张后原始听口、稳定阶段完整听口不变，且未发生过碰牌；杠牌本身不取消资格**；金钩钓需要四副碰/杠与一张暗手牌，不应把普通14张门清何切题误判为金钩钓。
- 必测：0番平胡×1；天听在换后三家闲家中的判定、原听口保持、碰牌强制失格与杠牌不自动失格；金钩钓2；金钩钓+清一色4；金钩钓+天听4；**金钩钓+清一色+天听6**；金钩钓不可重复加对对胡；天胡起手14张4；地胡4；清七对4；清龙七对5；原始番4/5/6在默认封顶3时均按8倍；根/杠上花等**加完之后才封顶**。
- 必测：牌墙55张、同时换三张/定缺、三类杠钱、杠上炮/抢杠作废、一炮多响、牌墙耗尽且4或3或2名活跃玩家时触发查牌、只余1人时不查、持自己缺门但仅两门仍算花猪。
- 规则相同、同局种子相同，题目/对战必须可复现；对 AI 不暴露对手暗牌，公平随机协议另行验证。

## 9. 尚待明确，不影响本次已确认规则

1. **天听听口已定**：换牌后记录完整听口，后续摸切必须保持相同听口；碰牌取消资格，杠牌本身不取消。仍需在完整对局状态机中界定抢碰/杠中间态是否检查（建议只检查回到可比较的13有效张稳定状态）。
2. **三重金钩钓复合已定**：金钩钓2+清一色2+天听2=6番。它与根等有效附加番在封顶前相加；仍待完整对局测试确认所有不同杠型产生的根与事件附加番边界。
3. **参与流局结算的玩家集合**：有人先胡退出后，是否仍为查花猪的非花猪收款人或查大叫收款人？“只查场上≥2人”已定，但账本参与者仍需确认。
4. **花猪的公开面子范围**：未打光缺门时，已碰/杠公开的缺门牌是否仍视为花猪？（原则上建议计入，但未确认。）
5. **底分是否等于房间系数**；杠上炮、抢杠“此杠作废”如何撤销已经记账的杠钱，抢杠点炮人是谁。
6. **缺门花色是否可杠、有缺门牌时是否必须先出该门**；对特殊事件的过手胡、优先级细则及摸尽最后一张的时点。
7. **根的计算与龙七对多根场景**，以及天听和其他特殊牌型的更多互斥/叠番案例。
8. **VRF/可验证公平**使用哪种承诺、签名、随机派生与验证细则。
9. **最高赢48倍/输40倍**是否仅为经验描述，抑或是整局硬上限。

## 12. 定缺时点再确认（2026-10-16）

- **正式四人局顺序**：完整发牌 → 四家查看手牌 → 四家选3张同花色交换 → 换三张完成 → 四家**同时盖牌定缺** → 庄家先切牌。系统必须在玩家已看到换后三张结果的情况下允许其选择缺门。
- **天缺**：换三张之后若仅持有两门花色，可立即选未持有的第三门为定缺；天缺不构成额外番数/和牌奖励（尚未收到此类规定）。
- **盖牌实现**：此处表示一个**同步、未公开前可保密的声明动作**。尚无“从实际手牌取出哪张作为盖牌标记”的具体细则，开发时先使用独立缺门标记而不是消耗实体牌，避免牌量守恒错误。
- **单人训练**：没有四人换三张流程；改为**发出并预览13张起手牌 → 玩家选择万/条/筒作为定缺 → 开始连续摸切**。若预览时只剩两门，也给出“天缺”提示并建议选择不存在的一门；不把预览天缺误当成完成换三张的正式对局天缺判定。

## 15. M3.2 对局天听和胡牌部分账本（2026-10-16）

- **已落地**：四家换三张并同时定缺后，初始化每名闲家13有效张的完整听口 `W0`；每次稳定摸切后校验原始听口是否完全不变，碰牌立即永久取消资格，杠牌本身不取消但补牌切牌后的稳定听口仍要比较；最终注入计番的天听状态由**可信对局历史**判定，不接受浏览器自报。
- **已落地**：合法自摸、点炮/一炮多响和抢杠胡使用 `score_win()` 计算**原始番、最终封顶番**与倍数，按照`房间系数 × 2 ** final_fan`分别记入四家**胡牌部分零和余额**。庄家开局自摸天胡、闲家胡庄第一张地胡、尾摸杠上花、杠后切出点炮的杠上炮和抢杠事件，在可验证时追加相应的事件番。新账本只在四人 M3.1 响应试验中生效，未改14轮训练原有判分。

## 16. M3.3 独立可冲销杠钱模拟及流局查牌预览（2026-10-16）

- **已实现可测试的独立底分模拟账本**：胡牌房间系数与杠钱底分分别保存，默认不假设二者相同；默认杠钱底分未设置不入账，必须手动开启模拟。明杠由出牌者按2倍底分付款、暗杠按其他活跃者各2倍、补杠按其他活跃者各1倍产生零和流水。杠上炮按**实际杠事件ID**精确冲销，保留最初流水及反向流水；抢杠不产生未成立的补杠付款。**此模拟不代表用户已确认正式的杠钱底分政策**。
- **已实现墙尽预览**：当剩余活跃者≥2时，依据自己定缺花色是否仍在暗手判花猪，另外检查合法听口及可证明的最高封顶番，分别给出先花猪、后查大叫的**只读预览**。付款人暂拟“只含仍活跃玩家”并显式标识为待确认策略，**不把任何预览款项入账**；若缺门出现在公开副露或牌型非稳定状态，暂缓给出确定金额。
- **未确认不改变**：已胡玩家是否参与流局付收、缺门公开副露的花猪定义、杠钱底分与房间系数是否一致，以及全套正式清算边界继续保持待确认。规则仍为 `draft / enabled=false`，详见[M3.3 v0.15](FOUR_PLAYER_KONG_EXHAUSTIVE_V0.15.md)。
