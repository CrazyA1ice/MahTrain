# M3.41：无声 AI 过渡合并与精准语音节拍（v0.53）

## 问题

M3.40 已将一次性运算多轮 AI 改成“每个服务端规则步骤都请求一次”。这修复了整条 AI 决策链阻塞操作的问题，但**暗摸、过牌、尚未完成的响应仲裁**也需要独立 HTTP 往返和通常 450 ms 的占位动画。玩家会感觉“谁也没打牌却一直在停”。

## 本轮改动

`match_continue` 每次最多执行 **8 个单独、合法的规则转移**，但只允许遇到**第一条公开可见／需播报的动作**：打牌、碰、明杠、暗杠、补杠声明／完成、点炮胡、一炮多响、抢杠胡、自摸胡，就立即停止。它同样在出现需要 0 号真人抉择（胡／碰／杠／过）、进入终局或首次达限制时停止，绝不会自动放弃玩家的选择。

这与“将 AI 操作统一瞬间跑完”不同：**每一条需要语音播报的公开动作仍分别停下来，等待浏览器完成牌河更新＋语音播报，再允许后续步骤**。服务端始终用既有规则引擎和各家私有视角决定动作。

浏览器将连续无声动作的占位播放合并为最后一条有效公开动作；若本次没有可播报动作，仍展示最后一个真实公开快照。所有中间阶段的 **真实规则调用后公开牌桌快照**仍进入逐步复盘历史。UI 会在播放说明中注明压缩的无声中间画面数量。

### 例子

| 真实规则转移 | M3.40 | M3.41 |
| --- | --- | --- |
| AI 暗摸一张 | 1 次请求、占位画面 | 与下一次可见出牌合并，暗牌不公开 |
| AI 打出五万 | 再请求、播报“五万” | 本次请求到此停止，牌落下后报“五万” |
| 其他 AI 依次选择“过” | 每次分开请求 | 合并到下一次真实公开动作或玩家选择 |
| 真人有合法胡牌选择 | 停止，等待真人 | 同样立刻停止，不替真人过牌 |
| 下一家公开出牌 | 等上一段声音播放完再请求 | 同样严格等待声音与画面完成后再请求 |

## 保留与限制

- 不改 M3.38 自摸加底／加番、番数封顶、流局方案 A、碰杠优先级、牌背颜色、四面牌河朝向。
- 不缓存或发送对手暗手牌、未公开杠牌种类及未来牌墙，不构造虚假的中间牌桌。
- 每次响应仍有 `server_elapsed_ms` 供诊断。因减少往返，预期静默阶段更流畅，但**未在用户真实设备上测出端到端改善幅度**。
- 仍依赖浏览器本地语音引擎；之前的 `onend/onerror` 与超时防死锁规则继续生效。

## 回归
