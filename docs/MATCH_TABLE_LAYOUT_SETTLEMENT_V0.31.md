# MahTrain M3.19：四边牌桌副露与桌内胡牌结算（v0.31）

## 本轮改造

原 M3.18 已经支持真实动作后的牌桌变化和碰杠胡动画；M3.19 集中调整桌面信息密度。四家牌河与中央牌山保持原位置；上家与下家的副露牌组沿各自侧边纵向成列、各碰杠组独立包边，上方对家和下方本人仍以横向分组排列。侧家副露超出预留空间时，只滚动自己的副露栏，不能把玩家暗手牌背挤到下一行。侧家的暗手背牌保持原来的纵向连续排列。

胡牌座位有“已胡”角标，四家的正牌河、背牌和副露继续按服务端实时公开数据绘制。碰牌3张，杠牌4张。其他玩家暗杠的牌面种类只绘制背牌；自己的暗杠只有本人合法私有视图才能看到牌面。没有新增暗手或真实牌墙的 API。

## 桌内结算

一旦胡牌账本出现真实的结算记录，牌桌底部会显示“四家胡牌结算 · 已入账”。展示四家**胡牌账本 balances** 的正负余额、最近两笔胡牌记录的胡牌类别、胡牌牌型、有效番数、赢家实收和付款者，同时把各自的胡牌积分展示在本人的手牌区或 AI 座位旁。

这里不计算、更不猜测新的积分。完整胡牌流水继续在桌面下方原账本可见。可选的独立杠钱模拟由另一份 kong_ledger 处理，不混入本栏胡牌余额；牌山耗尽后查花猪和查大叫仍只是预览，尚未正式记账，因此不能把本栏称为全部最终结算。

比赛尚未发生任何已入账胡牌时不显示桌内结算，避免四个空白零分卡片占用桌面。播放 M3.17/M3.18 服务器真实公开局面中途，尚未抵达权威最终私有状态时也隐藏本栏，**不允许把未来最终账本当成当时已发生的结果**。

## 修改文件

- `web/index.html`：增加桌内结算容器与本人座位胡牌积分元素，保留已有唯一 ID。
- `web/match.js`：为副露组添加碰/明杠/补杠/暗杠语义样式与必要无障碍说明，渲染四家结算余额与最近两笔胡牌记录。
- `web/app.css`：副露按座位方向成排，侧家副露独立滚动、胡牌座位角标、桌内结算栏四列布局和窄屏两列。
- `tests/test_web_app.py`：桌内结算和副露方向的静态/HTTP 回归。
- `tests/test_match_board_dom.js`：真实生产前端的账本金额、公开暗杠保护、胡牌提示及回放中不提前泄露最终账本回归。

## 操作验收

运行 `git pull origin main`、`python web_server.py` 后，访问 `http://127.0.0.1:8765`，在人机对战模式完成换三张、定缺并开始摸切。观察左右家副露区是否纵向分组、其他人的暗杠是否仍为四张牌背。在有人胡牌后检查桌内四家胡牌积分和对应赢家最近记录；如果启用了试验杠钱，应当与桌内胡牌积分分开。选择慢速、暂停后单步查看 AI 行动，未结束回放时不得先出现未来的胡牌结算。

本轮不改变任何麻将判胡、碰杠、AI 决策、杠钱记账与查花猪/查大叫规则，也未补齐正式血战完整结算或联网对战。真实浏览器视觉体验仍需手工验收。
