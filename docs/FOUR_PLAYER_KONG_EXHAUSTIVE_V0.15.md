# MahTrain M3.3：可冲销杠钱模拟与流局查牌预览（v0.15）

> M3.3 是在四人血战 M3.2 **天听与胡牌部分零和账本**上的增量。新增可独立定价的**模拟**杠钱流水、杠上炮冲销，以及牌墙耗尽时只读的查花猪与查大叫预览；并不等于已经解决全部正式血战结算条款。规则草案仍然是 `draft / enabled=false`。

## 一、杠钱与胡牌房间系数严格分离

目前确认的杠钱规则形式是：明杠的出牌者付 **2×杠钱底分**，暗杠由其他仍活跃者各付 **2×杠钱底分**，补杠由其他仍活跃者各付 **1×杠钱底分**。然而 **杠钱底分与胡牌房间系数是否相同尚未确定**。

因此，新增 `src/mahtrain_core/kong_ledger.py`，**不再默认假设两者相同**：

- 默认 `kong_base=None`：杠事件只登记为 `unpriced`，四家杠钱余额仍是0，原M3.2行为完全兼容。
- 网页用户**主动勾选**“启用独立杠钱模拟”，手工输入独立杠钱底分，例如25。仅此时四人试验局会依据上述杠型、实时活跃玩家集合产生模拟积分流水。
- 新 `kong_ledger` 维护四家独立杠钱余额、每次明/暗/补杠的事件ID、付款人、金额和原始 `charge` 明细。所有账本转移均零和。
- `combined_balances` = **现有已验证的胡牌余额** + **明确开启的模拟杠钱余额**。页面两种余额仍独立呈现，以免误以为杠钱底分经过确认。

### 杠上炮与作废的冲销

杠后尾摸直接出牌而导致别人合法胡时（杠上炮）：

1. 产生该次杠的**唯一事件ID**，将它绑定到对应补摸→切牌动作。
2. 如果该切牌被一个或多个人合法胡，准确找到**这一笔杠**，而不是错误撤销该玩家更早的其他杠。
3. 如果此前按显式杠钱底分进行了模拟入账，就在历史流水末尾追加与原付款等额、方向相反的 `reversal` 明细；保留最初的入账记录供审计，标记事件 `voided`。
4. 如果没有配置杠钱底分，直接将待定事件标记 `voided`，不生成虚构退款。
5. 抢杠胡发生时**补杠根本不成立**，状态机保留原碰刻，也就**不会产生该笔补杠付款**。

所有重复冲销、非法事件ID、付款人重复、非法玩家座位和金额配置均拒绝，不能由普通浏览器擅自提交更改服务器余额的指令。

**边界提醒**：此为开发用独立杠钱**模拟账本**；目前尚不能声称已与用户希望的最终川麻将馆底分参数、所有复合结算责任或现金结算细则一致。

## 二、流局查花猪和查大叫：先计算但不打款

在 `src/mahtrain_core/exhaustive_review.py` 增加只读审查函数，只有 `phase == "wall_exhausted"`（且活跃未胡者仍至少两名）才出现在网页：

1. **花猪判别**：按照缺门是否仍在**暗手牌**中判断，**即使总共只持两门牌**，只要含自身定缺花色，也判花猪。若缺门存在已公开碰/杠副露中，因其是否纳入判定尚未确认，分类改为“缺门副露待确认”，不继续生成确定的付款建议。
2. **合法听口判别**：排除花猪后，根据四组面子加一对/七对等规则与实际定缺计算完整的合法听口；若无合法听口，记为未听牌。
3. **最大可能番数**：对于每一张能合法胡牌的假定进张，复用 `score_win` 评估；考虑**已经由真实对局轨迹验证的天听**，不擅自增加没有发生的天胡、杠上花或抢杠等事件番。先计算原始最大番，再统一按房间封顶，取最大有效番。
4. **阶段顺序**：先提出每个花猪向非花猪赔 **8×房间系数** 的试算记录；花猪不参与第二阶段。再提出非花猪中未听牌者按每位合法听牌者的最高可结番赔付的试算记录。
5. **参与人集合有争议**：当前**只试算仍在场活跃者之间的转账**，会在数据和网页明确显示 `policy="active_only_preview"`、`posted=false`。已胡退出者是否仍有收付款资格，以及缺门公开副露是否归入花猪，仍必须等待用户确认；因此**不在任何积分账本执行转账**。
6. 预览中 `preview_balances` 是单独的假设差额，绝不混进 `win_ledger`、`kong_ledger` 或 `combined_balances`。

未达到流局触发时点，例如第三家胡牌已结束或尚在正常摸切，不展示这份结算预览。遇到非稳定有效张数或缺门副露争议牌例，显式返回待核验状态，并清空待定转账，避免错误输出数字。

## 三、网页使用方法

```bash
git pull origin main
python web_server.py
```

浏览器打开 `http://127.0.0.1:8765` 并 `Ctrl+F5`。在 **「四人血战 · 天听与胡牌部分结算」**：

- 默认只显示胡牌账本、独立杠钱的“未计价”状态。
- 如果只是希望做数值模拟，可在开新局**之前**勾选“启用独立杠钱模拟”，输入**明确的杠钱底分**；这不会更改胡牌房间系数，之后在下方显示杠钱余额、对应事件、原始和冲销流水、两账本合计余额。
- 出现杠上炮时，会在流水中留下 **入账→撤销** 两条可核对记录。
- 如果本局牌墙摸完且至少两名未胡，在页面最下方查看 **“流局查花猪 / 查大叫：待确认结算预览”**，会显示分类、最高听牌番和按**活跃者之间**暂拟的付款金额；这不会更改已经入账的积分。
- 其余三位依旧是规则固定脚本，不是具备真实博弈能力的三档AI；四人试验局只驻留于本机 Python 服务内存，不能当作多人房间。

## 四、验证与后续确认清单

```bash
python -m unittest discover -s tests -v
```

测试模块：`tests/test_kong_and_exhaustive_review.py` 及 `tests/test_web_app.py`。覆盖不同杠型的付款人、独立底分、零和、同人多次开杠只撤销正确一笔、重复冲销保护、流局只有足够活跃玩家触发、花猪与听口最大番、流局金额不入账、公开信息权限和非法客户端金额输入拒绝；继续执行旧版单人/四人规则回归。

待用户确认后才能进入后续 **M3.4 正式杠钱与流局结算** 的关键问题：

1. 杠钱底分是否应与胡牌的房间系数完全一致？若不一致，默认值与配置来源是什么？
2. 血战已有玩家胡牌退出后，他们是否还参与流局“查花猪/查大叫”的**付款或收款**？当前只试算活跃玩家。
3. 公开碰/杠副露里若含有自己选择的缺门花色，是否一律视为花猪？（当前规则不允许碰缺门，仍保留该边界以防将来放宽。）

**M3.3 无法替代这些用户决定，也不提前编造正式终局余额。**
