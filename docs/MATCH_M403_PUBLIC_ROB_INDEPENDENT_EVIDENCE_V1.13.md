# M4.03：24个全新独立初始洗牌种子的公开抢杠风险信号复验

## 为什么又增加独立自然样本

M4.01完成了8种真实108张物理牌构造的合法抢杠场景，同时在自然种子26001真实观察到1次补杠被抢杠。M4.02将真实牌局观察扩展到所有四座位：16独立初始洗牌种子、64局完整对局、256个座位观察位置，得到40个合法补杠候选窗口，但同一座位同牌去重后只有15个真正不同的候选、25个重复提示、11次真实补杠、0次潜在合法抢杠胡标签、0次实际抢杠。因此无法估计风险概率，也没有形成可以安全修改挑战级AI的证据。

M4.03用新种子继续验证**M4.00就已预先定义**的公开风险类别是否能区分真实、但在在线决策时不能直接知道的合法抢杠胡资格，防止因开发组观察到某些案例便临时修改预警定义，造成数据泄漏和自证循环。

## 未筛选、互不重叠的两组初始种子

开发组30000–30011、独立保留组31000–31011，各12独立初始洗牌种子。每个种子进行4次策略位置轮换，每局在所有四个玩家席位观察原本合法的补杠机会，合计**24独立初始种子、96完整自然对局、384个相关座位位置**。

注意：96局的四席轮换沿用了原始随机洗牌种子，不等于96个独立统计单元，更不等于384个独立统计单元。多次同牌重复补杠提示、更不能用于充当独立的抢杠负例。如果不出现自然抢杠正例，不允许事后改种子范围或“只重跑有杠的种子”。

本轮复用经过M4.02验证的实时不可见数据隔离：
- 正式对战只使用公开桌面、当事人的授权手牌和原有AI策略。
- `public_bugang_features` 的公开风险类别与牌河、副露、定缺、剩余墙牌等输入，不访问任意对手暗手或未来墙牌。
- `_sealed_potential_robbers` 读取对手暗手**仅作离线真实合法胡牌标签**；这些标签不进入在线AI或公开网络。
- 真正提出补杠的窗口严格使用**最近一次合法候选**的标签匹配 `bu_gang_declared` 与 `bu_gang/rob_kong` 官方公共事件；多响赢家数可以大于1，但被抢杠次数只能按宣告记一次。
- 每局权威108张物理牌守恒、胡牌＋杠钱＋流局余额之和及四座位零和均被再次核验。
- 输出 JSON 只有统计类别、合法胡牌数、公开座位与官方分数，不含暗牌、具体牌名或可逆牌序。

## 预注册公开风险信号与保守判定

没有为 M4.03 重新寻找最佳分类特征；直接复用M4.00的四分类：

| 类别 | 预先冻结的含义 |
|---|---|
| `dingque_excluded` | 当时所有活跃对手定缺都是补杠牌花色；该张牌的抢杠胡**按规则不可能**，但不能说明总体补杠收益最优 |
| `same_suit_focus` | 至少有一名允许胡此花色的对手有至少两副同花色公开副露，且花色与补杠牌相同 |
| `exposed_pressure` | 允许胡该花色的对手合计有至少两副公开副露，不满足上面更强的同色条件 |
| `unresolved` | 其他公开信息不足的情况；**绝不等于安全** |

作为**事先冻结、仅供统计分析**的定性信号，把 `same_suit_focus/exposed_pressure` 合为“公开预警”；`unresolved` 为“尚无上述预警”，但不能定义为安全；`dingque_excluded` 单独作为**规则确定排除类**，绝不能混入普通阴性“未预警”以提高假设的预测分数。

报告分开保存首次不同候选的真阳性／真阴性、预警与无预警交叉计数、前/后墙牌阶段、AI级别、以及所有自然种子的正反例和真正执行补杠的最近一次合法资格。

**不把独立性按次数夸大：** 满足下列门槛才允许描述性讨论公开预警的关联：
1. 开发组和保留组各至少 **3个不同初始洗牌种子**有自然合法抢杠正例；
2. 两组各至少3个不同初始种子出现可杠、但没有合法抢杠的负例；
3. 两组各至少3个初始种子确实暴露“公开预警”，另外各至少3个种子暴露 `unresolved`；
4. 样本满足门槛也**只准讨论描述性关联**，不把某种公开副露解释为“对手一定能抢杠”，不声称已经估计出人机对战条件下真实抢杠概率，不部署新策略。
5. 低于门槛输出明确状态码，并强制 `calibrated_rob_probability:null`；0正例绝不转换成“风险0%”。

上列3个独立种子只是一道避免极端小样本自欺的**最低证据门槛**，不是正式统计显著性或可推广的可靠精度；本轮不输出伪95%置信区间。

## 重复执行与CI

```bash
python -m unittest discover -s tests -p 'test_m403_public_rob_seed_validation.py' -v
python examples/validate_public_rob_seed_cohorts.py --seeds 12 --output results/m403_validation.json
```

GitHub Actions `.github/workflows/m403-natural-public-rob-signal.yml` 分别运行两组自然完整对局，将原始匿名摘要导出为 `m403-development.json` 与 `m403-holdout.json`，随后独立复验工作流读取**固定文件和固定种子段**进行联合证据门槛分析，保存 `m403-independent-holdout-report.json`。如某组出现正例但另一组没有，联合状态仍不得宣称有效独立风险预测。

## 对生产AI的决定

本轮**保留原挑战级AI碰牌、暗杠、补杠和胡牌策略**。M4.03目标是补足事件稀缺的独立性证据，不是把后验暗手改造成非法的在线“最优动作”。想真正部署优化还须进行全新种子的实际净积分对照，并考虑抢杠胡、牌墙尾牌及查叫结算的整体影响。
