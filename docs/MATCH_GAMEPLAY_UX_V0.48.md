# MahTrain M3.36：手机手牌定位、碰杠胡响应与可靠结算（v0.48）

本轮继续按用户明确的“先优化用户体验，后面再研究”的方向改进四人血战牌桌。不改变已经确认的规则方案A、AI策略、扑克牌编码或服务器选择的隐藏牌；延续 M3.34、M3.35 的四席牌桌与真实积分动效。

## 1. 手机手牌快捷定位

M3.35 让四家桌面在手机竖屏完整显示，同时让14张手牌单独滚动。但在触屏小屏幕上，**选择一张牌后重新渲染会导致手牌定位体验不稳定**，最右侧刚摸的牌可能需要多次左右拖动。新版本在用户手牌上方增加仅手机可见的三按钮：

- **◀ 左侧 / 右侧 ▶**：按照手牌视口约 75% 的距离滚动当前手牌，不触发任何麻将出牌请求。
- **看摸牌 ›**：当本回合确有单独右侧摸牌时，直接定位到手牌最右端；没有摸牌时不可用。
- 中间显示手牌数量和“最右侧是刚摸的牌”说明。
- **保留滚动位置**：点选/取消选牌、出牌二次确认的前端重绘不使屏幕回到手牌最左端；新开一局则重置到左端。相同牌的实体选择索引、摸切/手切区别继续保留。
- 按钮可由键盘焦点操作；真正的手牌仍支持原有触摸滚动与大牌切换。手机导航只调整页面滚动状态，不与麻将 API 通讯，不窥视 AI 手牌。

## 2. 碰杠胡大按钮

进入 `claim_window` / `rob_kong_window` 后，原有“胡这张 / 明杠 / 碰 / 过”由一排小按钮改为更醒目的响应区：
- 将合法服务器选项按**胡、明杠、碰、过**的固定显示顺序摆放（不新增选项）；胡使用金色大按钮，碰杠使用高对比绿按钮，“过”较为低调且文案注明放弃本次机会。
- 移动端每行最多两列，按钮高度不小于 62px。按钮本身仍提交原来的 `match_claim` / `match_rob` 和相同 `choice`，不改变胡牌优先级、抢杠胡判定或其他玩家响应规则。
- 自摸提示同步提高按钮尺寸与视觉识别度，仍由服务器的 `can_self_draw_win` 决定是否出现。

## 3. 防止误读流局分数

在牌桌结算区新增醒目的“**我的已入账积分**”摘要，始终从服务端已确认的 `settled_balances`（不存在时使用胡牌账本）读取：
- 普通胡牌后标明“仅含已确认胡牌积分”；
- 流局方案A已成功入账后明确显示“包含方案A已确认的流局赔付”；
- **牌山耗尽但牌形未核验**时仍可展示已确认的胡牌积分（可能为0），但必须清楚写出“流局赔付尚未核验，不代表最终净积分”，绝不将待核验项算作0元正式赔付。
- 即使本局没有胡牌、牌山已耗尽，也应展示四家当前**已确认的胡牌余额**和未核验状态，避免整个结算区域消失，让玩家误以为系统丢失对局。

## 4. 本地桌布色彩切换

牌桌配置增加 **深蓝桌布 / 绿色桌布** 两种 CSS 风格切换（自带青绿色仍为默认）；没有任何商用桌布、角色素材或外部网络加载。浏览器当前页面内即时切换，不保存用户设置；不会修改手牌、牌河、座位、游戏状态或积分。

## 5. 质量校验

```bash
node --check web/match.js
node tests/test_match_board_dom.js
python -m unittest discover -s tests -v
python web_server.py
```

测试重点：移动端手牌导航绝不发送游戏请求；选中与取消时保持滚动位置、新局重置；有摸牌时才允许跳转右端；胡/碰/杠/过展示优先级不改变服务器动作请求；深蓝桌布切换不涉及隐藏信息；已确认胡牌计分与流局待核验有清晰、不同的标签。原有 M3.35 自摸/一炮多响真实加减分事件、牌墙与暗手隐私继续自动回归。

**后续体验方向**：真实手机手势验收、纵横屏牌桌切换、可选音效/动画强度和更聚焦的终局评分展示。本轮没有宣称已用真实手机硬件进行人工测试，也没有调整 AI。
