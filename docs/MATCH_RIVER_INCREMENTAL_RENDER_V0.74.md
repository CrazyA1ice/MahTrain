# M3.63：四家牌河增量渲染与最新弃牌跨座位同步

## 问题

M3.60–M3.62 已经固定四座位各56个实体格位，并在真实 Chromium 验收旋转、占位及窄屏几何。然而前端 `renderBoard()` 在每个服务器动作与公开回放帧后，仍会调用四次 `renderRiver()`；原实现每次都清空并重建标题、网格及全部可见弃牌。即使这一帧只更新牌墙、AI暗手张数或别家的弃牌，也无条件销毁另外三家原本不变的河牌 DOM，造成额外构建与浏览器布局工作。

## 本轮修改

- **同座位无变化时完全复用原容器、原牌节点**：只对公开字段（全局弃牌序号、牌种、已取走者、胡牌标记、摸切/手切）计算稳定快照，不访问任何对手暗牌。
- **只追加时增量构造**：保留已经显示的牌与绝对网格坐标，仅按该座位新的弃牌数量追加对应单元（含侧边每14张换列的语义容器）。
- **跨座位最新标记正确转移**：别人打出牌时，即使某个座位的牌河内容毫无变化，也要取消该座位原先的“最新一张”高亮；新打牌的座位获得新的高亮。
- **已取走/胡牌/摸手切变化时安全失效**：旧牌公开属性发生变更，或回放回退导致公开历史缩短，则仅重建受影响的牌河。新局、更换牌河 DOM 同样能够重新创建快照。
- **第一张牌清理开局占位**：从0张变成1张时移除“尚无弃牌”字样，不把它和新牌同时画在格子上。

这是一轮**前端渲染效率和画面稳定性**优化，不调换服务端真实规则或AI思考策略，不改变语音播报和回放调速，也不额外暴露三家暗手。

## 自动验证

```bash
node --check web/match.js
node tests/test_match_board_dom.js
node tests/test_match_playback.js
python -m unittest discover -s tests -v
```

DOM 回归增加四组检查：相同公开场况的重复渲染保留四家牌河节点；本家新增牌仅追加格位并取消旧高亮；旧弃牌被碰杠标为已取走时相应牌河重新构造而其他牌河不动；最新弃牌跨座位转移时旧高亮清除且另一侧“手切”标签正确。

原 M3.61–M3.62 的真实 Chromium 几何和 0→56 动态测试继续执行，保护四个方向的固定布局与无滚动规则。

## 验收边界与后续

保留旧牌 DOM 有助于降低回放中不必要的重绘，但本轮没有可靠的真机/浏览器性能对照数据，**不宣称已经量化多少毫秒提速**；AI出牌的主要服务器计算时延也不由这次改动解决。后续适合进一步记录服务器策略运算、网络往返、DOM布局和语音播放之间的独立耗时，并据此选择真正瓶颈。
