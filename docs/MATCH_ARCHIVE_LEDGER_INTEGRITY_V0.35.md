# M3.23：已完成对局档案账本完整性与隐私加固（v0.35）

本轮不改变对局规则、AI、用户对战流程或 JSON 接口路径；修复 M3.22 已完成对局历史的一个潜在安全与数据完整性问题。

## 为什么修改

M3.22 的公开快照、事件、暗杠牌面已做脱敏，但之前的 `sanitize_win_ledger` 只是把白名单顶层键的**原始值**复制出来。若未来某个模块在 `wins[*].payers`、`wins[*].bonuses`、`wins[*].main_pattern` 内混入额外字典或私有字符串，JSON 与本地 SQLite 可能连同私有内容一起保存。即使目前真实 `WinLedger` 返回的是正常数据，也不应依赖这种隐含假设。

## 改动

- 逐笔校验胡牌的赢家、唯一有效付款席位、胡牌方式、已知番型、整数番数、倍率和应付款金额。点炮胡及抢杠胡只允许一位付款者，自摸不改变现有付款规则。
- `bonuses` 只保留 `kong_bloom`、`kong_discard_ron`、`rob_added_kong`、`roots` 及其非负整数值；所有无关私有字段忽略，非法的白名单字段拒绝写入。
- 由每笔实际胡牌流水**重新计算四家余额**，与结算器公布的余额逐项核对。负数或正数均可，但合计必须为零；账面不一致时拒绝归档，而不是保存一个看似成功但错误的历史记录。
- 独立杠钱模拟余额须为四个整数并且零和；可选杠钱底分须符合已有 `KongLedger` 约束。并没有把模拟杠钱变为已正式入账款。
- 添加使用真实 `WinLedger.pay_win` 生成自摸账本的往返测试；覆盖嵌套私有付款字段、私有加分值、未知番型、重复付款席位、金额及零和错误，确保非法记录写入失败而不污染 SQLite。

## 兼容性与范围

数据库 `completed_matches` 的表结构、档案 ID、HTTP API、前端页面与已有 JSON 字段不变；**已保存的旧档案不修改、不迁移**。新记录采用强化校验。这个防护只保证新增记录来自已核验的规则账本；并不将 `wall_exhausted` 的查花猪／查大叫预览等同正式结算，也没有实现联网账户隔离。

## 验收

在项目根目录执行：

```bash
python -m unittest discover -s tests -p 'test_match_archive.py' -v
python -m unittest discover -s tests -v
node tests/test_match_archive_dom.js
```

通过 GitHub PR 检查 CI（Python 3.11/3.13）后再合并主分支。手动完成一局正常人机对战，应能继续自动保存档案、查看历史、比较成绩和下载 JSON；读取既有归档不受影响。
