# M3.93：挑战级 AI 与牌效参考切牌的固定种子配对试验

## 为什么先做离线验证

M3.92 可逐座位统计“实际切牌是否符合牌效参考”。但是，挑战级 AI 的切牌决策会考虑基础番值、牌形潜力与公开风险指标，**低符合率不能直接当作低对战收益**。本轮没有修改正式人机对战 AI 的执行策略，而是设置清晰的可复现实验。

## 试验的两个条件

- **基线**：使用仓库现有 `MahjongAgent("challenge")` 的所有选择。
- **干预**：同一个挑战级智能体照常换三张、定缺、响应、碰杠和计算原始切牌，但在合法出牌前用 M3.92 同口径的 `classic_archive_seat_hint` 第一名替换切牌。其余三家策略和固定初始牌山种子不变。
- 使用 `simulate_match` 的 `offline_agent_overrides`，开启 `offline_kong_base=1`，核验108张守恒、每局官方零和、胡牌/杠钱/流局完整正式结算。**不会更改 `web_server.py`、正式 `MahjongAgent.discard`、模型参数或用户历史数据库**。
- 同一种子做0到3座位轮换：四轮归为同一个独立随机种子集群，而不是当作四个独立样本，更不能把每巡切牌当作独立收益样本。
- 每组报告挑战席位正式净额及干预与基线差额、赢牌次数、放铳事件数。记录干预轨迹中的“原挑战选择与牌效首位不同”次数，以及其中公开风险修正是否改变了挑战候选排序；这只是策略差异关联，不是某次胜负的因果归因。
- 如果挑战级没有多张同向听的候选，则没有 `_last_discard_scores`；明确计入“无法解释原挑战排序”，不虚构防守原因或提升概率。

## 运行

在项目根目录执行：

```bash
python -m unittest discover -s tests -p 'test_m393_challenge_reference_paired.py' -v
python examples/compare_challenge_reference_paired.py --start 8407 --seeds 2 --rotations 4 --output results/m393_reference_paired.json
```

第二行将以**8组成对对局＝16局真实规则仿真**执行，耗时取决于机器。输出为不含双方暗手、牌墙与 token 的研究数据摘要。相同种子和当前代码应产生相同结果。

## 结论边界与后续

- **比较指标是实际游戏正式净额，而非简单切牌参考符合率，也不是理论完美策略。**
- 多轮对战会在第一次不同切牌之后分叉，不能据后续单一巡直接判定风险/牌形造成赢或输。观察样本少时仅用于确认可行性；后续应扩大独立种子数，预注册训练/验证/保留种子及零假设，报告按种子聚类置信区间。
- 无法从本轮证明“统一选参考首位更强”或“现有挑战级更强”。无明确、可复现实证优势之前，不把试验对照策略部署为正式 AI。
