# M3.87 · 四川血战连局庄家继承与四家轮到行动提示

## 规则约定（用户要求）

“四人对战”不再轮流坐庄。开始一段**独立对战**时，首次庄家仍由洗牌随机数独立选择。上一局完成并由玩家点击“下一局”时，以**服务器已裁决的本局胡牌与支付事件**决定下一局庄家：

1. 一炮双响（同一张弃牌被至少两家同时胡），**点炮者**坐下局庄；使用权威公开事件 `multi_ron.source` 判定，而不是按页面显示顺序或看输赢金额猜测。
2. 没有该事件时，若一人向**其余三位不同的胡牌赢家**均支付过胡牌分，不论这些付款来自**自己点炮、自己被抢杠胡还是别人自摸**，称为“输三家”，由该付款者坐庄。用 `win_ledger.wins[].payers` 和 `winner` 计算三位**不同**赢家，重复给同一位付钱不等于“输三家”，杠钱和流局查大叫等不算胡牌付款。
3. 否则由**本局第一位正式胡牌者**坐庄。一次胡多家时胜者相对放牌者的顺序已由规则引擎固定，但同炮双响实际优先判为放炮者坐庄。
4. 若真实流局无人胡牌，则原庄续庄。否则严禁未结束就计算下局庄家。

前两项均覆盖“首胡者也已胡，但庄家按特殊条件转移”的情况。这样保证显示的“下局庄家”与真实下一局发 14 张的座位一致。

## 服务端与身份安全

- `src/mahtrain_core/next_dealer.py` 只接受 `finished/wall_exhausted` 的**公开正式结果**，不读取任意玩家隐藏牌、未来墙或私有策略。优先级明确并输出中文原因标记。
- `FourPlayerOpening(seed,dealer_override=...)`：选庄覆盖是严格 0～3 的可选权威参数；初局不传就完全维持原有的随机庄家。新一局仍重新洗牌，单纯把庄家位置设为经过裁决的座位，四家实体牌始终为 108。
- `web_server._process("match_next",{"match_token":...})`：必须持有当前房间此前的会话令牌、且前局已经结束；客户无法提交自定庄家、洗牌种子、AI 等级或计分规则。继承原本的 AI 等级、房间系数、番数上限、杠钱与自摸配置，并为新局生成自动不重复种子。
- **幂等**：同一结算牌局多次请求“下一局”返回第一次创建的同一后继牌局，不会因为连续点击、HTTP 重试而生成不同庄家/牌墙。
- `match_new` 依旧启动独立随机首局，旧版实验室可选固定种子仅作用于独立新对局，不会影响续局庄家决定。
- 续局会在公开合法的 `private_view(0)` 中显示 `series_round`（第几局）、`dealer_origin`（坐庄原因）；**仅终局**增加 `next_dealer` 和原因，进行中的牌局没有提前赋值。

## 牌桌上的明确头像提示

- 经典 2D 每家原有固定坐标的 `.player` 铭牌内新增 24px 圆形角色头像。四人分别有不同颜色，“我/1/2/3”可辨。轮到当前座位**摸牌或打牌**时，原座位框与头像同时出现暖金色描边、高光，标出小三角“▶”方向；庄家头像固定显示“庄”字标志。
- `claim_window` / `rob_kong_window` 正在处理多个玩家响应，不虚构某个座位是当前正在摸打的玩家，不会错误高亮；已胡者不再高亮。AI 打完一张，下一名真实行动者高亮自动跟随 `turn` 变化。
- 原有备用 Web 对战牌桌已经有角色头像，本轮同步增强暖色轮到谁的牌桌框、头像环光以及“行动中”小字。
- 这些标记使用原 160×30px 人物铭牌空间及原固定桌面缩放机制，不插入屏幕上方移动提示，不改变牌河容量，也不引入新滚动条。
- 经典 2D “再来一局”改为 **“下一局 · 继承庄家”**，结束后标题明确说明 **下局庄家号码和触发规则**；独立“随机新开一局”按钮仍保留在顶部。原备用对战界面也将结算后“再来一局”指向 `match_next`，并在结算摘要中显示相同下局庄家及原因。

## 验证

`tests/test_next_dealer.py` 覆盖：一炮双响优先、输三家（混合自摸和点炮、区分真实不同赢家）、默认首胡、无人胡时续庄、严格禁止提前结算与非法座位、同洗牌种子的随机首局与覆盖庄家、接口等级/配置继承、伪造庄家/种子拒绝、刷新或重复续局幂等、108 张物理牌守恒、终局才公开下一庄以及无隐藏信息输出。

`frontend_2d/test/browser-turn-avatar.mjs` 在真正 Chromium 页面验证：四家姓名/头像在 0、1、2、3 号轮到出牌时轮流高亮，庄家标志固定，牌桌与铭牌在状态切换时不变尺寸，碰杠仲裁时无虚假当前出牌者、结束后展示“下一局庄家：输三家”等原因，点击下一局确实发 `match_next` 而非另起随机首局；同时复跑 M3.84/M3.85 杠牌来源和满四组副露布局。自动编译并将 `frontend_2d/dist` 同步提交，避免源码更新但本地网页不变。

边界：服务器仅在本地进程内保存进行中的会话，关闭服务器后已过期牌局不能凭浏览器随意重建此前隐藏墙或继承庄家。若未来需跨重启连局，应新增只存**合法已结算摘要**的持久系列记录，不得私存完整暗牌数据。
