# M3.80 · 挑战级 AI 碰杠对照的独立种子验证（研究工具）

本轮**不再改变线上 AI 的碰杠或出牌动作**。M3.79 从 4 个独立初始牌序、32 局得到「座位配对平均净分差 +18.9375」的初步结果，四个种子表现为 -100、0、+25、+150.75 分；差异方向不一致。M3.80 的任务是修复前一轮报告将**声明尝试**与**规则裁决实际生效**碰杠混淆、以及将**胡牌、杠钱和流局**混在一个净分中的不足，再使用与先前 810–813 种子不重合的 **900–907** 固定种子复验。

## 固定比较方案

1. 每个种子采用四个座位轮换，每次恰好一名挑战级 AI 为研究对象，其余玩家保持同一批独立固定策略；该座位分别打一局 M3.78 旧碰杠策略与 M3.79 新碰杠策略（常规挑战级出牌、换三张和定缺等保持不变）。共 **8 个独立种子 × 4 座 × 新旧各 1 局 = 64 局**。
2. 完全使用正式 `FourPlayerOpening` 状态机与 `simulate_match`，设置 `room_coefficient=100`、`fan_cap=3`、`kong_base=1`，包括尾墙补摸、抢杠、点炮和真正流局的正式结算。逐局严格核对 `108` 张物理牌守恒、四家各分账的零和性质和 `总净分 = 胡牌账 + 杠钱账 + 流局账`；不接受未终局或对不上账的结果。
3. 每座位输出正式最终净积分、三项分账、胡牌次数、自摸次数、点炮胡次数、放铳事件数（**一炮多响按赢家个数计**）、被抢杠胡事件数，及碰杠**尝试次数**与**已裁决生效次数**。补杠先宣布但被抢杠后未升级时，不算已生效杠。
4. 决策耗时只在存在至少两个合法动作的碰牌响应窗口，或有一个以上可操作杠选项的自身阶段计时；不包括出牌、网络/浏览器等待时间，不以 `pass` 唯一合法选项的常数开销降低平均值。该量是 CI 机器上的墙钟描述统计，**不是严格固定硬件下的算法性能测量**。
5. 同一初始牌序不能保证决策后摸牌轨迹一致；一号种子内四个座位也不是四份独立随机实验。所有均值和抽样区间均先按种子聚合，再对**整个种子簇**采用固定 `Random(3802026)` 的 2000 次非参数 bootstrap；仅 8 个独立种子，95% 区间作探索性描述，不构成严格显著性或强度保证。
6. 严禁将对手暗手、真实未来牌墙、决策后的特定赢牌结果作为在线 AI 输入。数据源只包含已公开的规则事件与正式账本以及单个试验 AI 自己的合法决策计时。

## 运行

在项目仓库根目录执行：

```powershell
python -m unittest discover -s tests -p "test_ai_calls.py" -v
python -m unittest discover -s tests -p "test_ai_call_research.py" -v
python examples/compare_challenge_call_policy.py --seed-start 900 --seeds 8 --json-out call_holdout_900_907.json
```

该命令会输出 64 局的逐座位详细账本、各种子配对差、整种子重抽样区间、尝试/已生效碰杠次数和合法机会决策时延。CI workflow `.github/workflows/challenge-call-policy.yml` 也固定执行此方案并归档原始 JSON，和完整 Python 3.11/3.13 规则测试分开管理。

## 统计使用边界

- **最终净积分**是研究的主要结果；胡牌净入账、杠钱净入账、流局入账是解释性拆分，不能将同一杠上花相关分值再次算为另一个收入项目。
- **点炮事件**按失败方支付对手胡牌的事件计数，**不是**所有弃牌中被胡的概率；没有观察期母数，不能直接宣称「放铳率下降」。
- 同一试验初始牌序配对后，策略改变会引起新的摸牌和行动路径；不能归因于仅一次碰杠而断言因果上精确增加了多少分。
- **95% bootstrap 区间**极可能很宽且样本仅 8 个独立种子；即便均值为正，也不能视为证明挑战级 AI 优于原版。原则上需要预先定稿阈值后、在更多完全独立种子和固定规则版本上再复核。


## 已执行的独立种子结果 · 2026-10-20

研究结论以 GitHub Actions [`39424981153`](https://github.com/CrazyA1ice/MahTrain/actions/runs/39424981153) 归档的 **64 局正式对局原始 JSON** 为准。该运行通过全部研究测试及 64 局真实结算、每局 108 张牌和三项正式零和账本核验。

| 固定种子 | 4 座平均正式净分差：M3.79 - M3.78 |
|---|---:|
| 900 | -275 |
| 901 | +74.75 |
| 902 | 0 |
| 903 | -25 |
| 904 | +25 |
| 905 | +0.50 |
| 906 | -0.50 |
| 907 | +25.25 |

**主要结果**：八个独立种子簇的平均正式净分差为 **-21.875 分**，固定 2000 次整种子簇 bootstrap 的描述性 95% 区间为 **[-99.9688, +31.0625] 分**。区间包含零，无法证实新策略优于旧策略，也不能证实稳定劣于旧策略。这与先前不同样本 810–813 的均值 **+18.9375 分**方向相反，进一步说明不能以调试样本宣传 AI 能力提升。

**说明性拆分（新策略 - 旧策略；每次四座位配对平均）**：

| 正式分账 / 行为 | 8 种子平均差 | 描述性 95% 区间 |
|---|---:|---|
| 胡牌净收入 | -18.7500 | [-56.25, +12.50] |
| 杠钱净收入 | 0.0000 | [-0.1875, +0.1875] |
| 流局净收入 | -3.1250 | [-56.25, +40.625] |
| 胡牌事件 | 0.0000 | [-0.125, +0.125] |
| 自摸事件 | -0.0312 | [-0.125, +0.0625] |
| 放铳事件（含被抢杠） | -0.0312 | [-0.125, +0.0625] |
| 真实生效碰杠次数 | +0.4062 | [+0.1562, +0.7188] |
| 真实生效杠次数 | -0.0625 | [-0.1562, 0.0000] |

32 个座位对比的汇总：旧/新正式总积分分别为 **4301 / 3601**（只是各版本试验 AI 的自身合计，不能脱离场次比较）；旧/新合计的胡牌次数 **22 / 22**，放铳事件数 **6 / 5**，最终实际生效碰杠 **20 / 33**，有效杠 **7 / 5**。新方案**更积极碰牌却并没有在此次 holdout 转化为更高的正式净分**。不应把单个区间或单个事件比例解读为真实「胜率提升」。

**计算耗时（CI 机器上，同一次运行的有限测量）**：旧策略在 **82 次真实可选碰杠机会**中累计 **139.75426 ms**，约 **1.70432 ms/机会**；新策略在 **81 次**中累计 **1332.98624 ms**，约 **16.45662 ms/机会**。这提示新策略需要更细粒度的计算优化，但 CI 机器的缓存、运行环境与不同场况的机会分布不恒定，不可将约十倍比值解读为同一棋面上的严格运行时间比。

**研发决定**：本轮 M3.80 只合并 **研究工具、正式分账输出、统计方法、测试及文档**；M3.79 挑战级 AI 在线策略仍保持原状。现有独立样本**不支持宣传 AI 已因 M3.79 变得更强**。未来若更改碰杠门槛或引入优化，应先针对更积极副露与复杂牌效计算做预先冻结、独立样本复核，并监测点炮损失、净分及决策延迟。

可复现命令：`python examples/compare_challenge_call_policy.py --seed-start 900 --seeds 8 --json-out call_holdout_900_907.json`。GitHub Actions 原始 artifact 有留存期限，长期复现依赖固定代码与该命令。
