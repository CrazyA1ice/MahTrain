# M3.85 · 经典麻将四组副露的固定单行容量与横叠间距

## 发现的布局风险

M3.84 已按真实点杠者的相对位置修复“左、右、对家横牌统一朝右”的错误，并让补杠横牌叠在三张竖牌的中间。但原桌面使用的基础 `shoupai-size` 布局中，`.mianzi` 是多个独立的 `float:right` 元素。侧边玩家的固定副露横向容量只有 560px；满四组副露时，四个明杠的单组物理展示宽度原为 `3×30+42=132px`，四组共 528px，而剩余两张单钓手牌还需约 60px。两项合计至少 588px，因而原界面存在换行、移位、牌张重叠风险。

## 本轮变更

- **单行副露**：仅在牌桌 `.shoupai .fulou` 下采用 `display:flex;flex-flow:row-reverse nowrap`，替代可换行的浮动子副露；`row-reverse` 保留旧版“先出现副露在玩家右侧”的原有顺序，**不反转每组牌中点杠者的左右**。
- **固定间距**：各组副露为不压缩的 `flex:0 0 auto`，组间固定 2px，四组之间不互相挤压。原有整组四家座位 0°、270°、180°、90° 旋转、横牌来源方向、暗杠三背一明、补杠上叠都保持不变。
- **只在四组满副露时压缩**：每组内竖牌从 `30×42` 缩小为 `26×38`，横牌槽宽 38px。四组全是明杠最多 `4×(3×26+38)+3×2=470px`，加两张手牌约 60px，总计约 530px，低于侧边既有的 560px 固定行空间。手里还有三组及以下副露时仍保留 M3.84 的 30×42 视觉大小。
- **比例同步**：横牌原地旋转、上叠偏移、牌背图片宽高统一引用 CSS 自定义尺寸，防止只缩小竖牌而横牌越界。
- **不引入滚动和缩放**：没有修改全局 800×680 牌桌、四边牌河容量或中央手牌/按钮位置；副露依旧属于原桌面固定区域，牌桌尺寸只受窗口尺寸变化影响。

## 自动核验

`frontend_2d/test/browser-multi-meld-capacity.mjs` 在 Chromium 中分别制造五组真实公开数据结构形式的授权展示快照，涵盖四组全明杠、混合明杠/补杠/暗杠/碰、三组、两组、一组。要求四个座位的副露组数和公开脸正确，`flex-wrap=nowrap`、相邻副露不重叠、每组都留在副露可见行内，同时所有副露及隐手的总宽度不超过玩家既定的 560/680px，切换状态时桌面坐标、宽高完全不变。四满组另外生成实际浏览器截图，以便人工检查。

继续跑 `frontend_2d/test/kong-layout.test.mjs` 和 `frontend_2d/test/browser-kong-layout.mjs`，确保 M3.84 左中右横杠、暗杠、补杠未回退。GitHub Actions 验证通过后需**把新 `frontend_2d/dist` 编译内容一起提交**，否则 `web_server.py` 默认加载的静态网页仍会是旧版。
