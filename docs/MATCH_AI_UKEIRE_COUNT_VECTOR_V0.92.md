# M3.81 · 挑战级 AI 牌效计算提速（不改变决策）

## 问题与范围

M3.80 在 8 个独立种子、64 局正式四川麻将结算中，发现新碰杠策略的座位平均净分差 **-21.875**，种子簇 bootstrap 区间跨越零，因此不能证明新碰杠方法变强。另一项性能观测是，合法碰杠选择窗口上新策略约 **16.46 ms/次**，旧策略约 **1.70 ms/次**（同一 CI 环境的非等场况统计，不能解释为严格同条件速度比）。

当前 `effective_draws` 在非听牌的 13 有效张状态下，逐一尝试 27 个牌种的摸牌，再逐个尝试切牌，反复构造 13 张字符串列表、`Counter` 和进行完整 `_validate`；这种重复 Python 开销会在挑战 AI 比较多种碰/杠候选时叠加。

本轮**不修改 AI 的碰牌/明杠/暗杠/补杠决策门槛、优先级、等待集或番值公式**，而是仅优化全项目共用的非听牌有效进张枚举实现。

## 等价性设计

- 非听牌用长度 27 的物理牌张计数向量，直接在枚举「摸牌 → 切牌」时对向量 +1/-1 并调用与 `shanten_13` 共同使用的精确 `_cached_shanten` 核心函数。**不再在每个候选切牌上重建手牌列表/运行重复验证**。
- 切掉刚摸到的牌回到原 13 张状态，不可能让向听下降，直接跳过这个无效候选；对其他切牌完整枚举，严格保留旧逻辑的有效进张定义与排序。
- **只有自身物理牌和副露**决定合法「可枚举摸牌」掩码。暗杠的 4 张物理副本仍全部计入；碰牌、明杠等副露也同样计入，严禁虚构第五张。公开河牌可能进一步降低剩余副本量，但**不参与缓存 key**：它必须在 `_remaining_counts` 阶段每次重新计算。
- 用有界 `@lru_cache(maxsize=16384)` 保存同一种自身牌张向量、已副露数、定缺门和自身合法摸牌掩码的**牌型结构结果**；不缓存其他三家暗手、牌墙或任何公开概率、积分、动态牌河值。即便缓存中出现历史牌型，也不能据此推出当前场况。
- 已听牌 `current==0` 时保留 `winning_tiles` 原始服务端权威胡牌枚举，**不改任何天听保留规则**；仅非听牌计算路径优化。

## 防回归验证

1. `tests/test_ukeire_fast.py` 保留 M3.80 的**独立旧枚举实现**做参照，随机生成符合 108 张物理规则的 0～4 副露、三种定缺及多种公开可见状态，要求整个 `effective_draws` 返回字典完全一致，不允许差一个有效张或剩余副本。
2. 验证**不同公开河牌不复用过时张数**；同一缓存键下牌张顺序不同结果一致；修改先前返回的列表不污染缓存；四张暗杠牌永远不会被当成可摸的第五张。
3. 使用权威 `simulate_match` 自对局，把 `_effective_types_13` 替换成 M3.80 旧版枚举对比优化版在相同随机种子下的**完整动作轨迹、胡牌记录、正式胡/杠/流局结算、公开复盘帧**，不以不同墙钟时延作为失败条件。
4. 新增 `examples/benchmark_ukeire_fast.py` 对相同物理合法样本计时、先比较准确性，再交替运行旧版/优化版并输出原始 JSON。计时在 CI 共享环境内，可能受 Python 缓存和 CPU 负载影响；其描述性平均耗时不是可靠的部署延迟承诺。
5. 原有全部 Python 3.11/3.13 四川规则、AI 回归、浏览器布局和独立研究任务仍通过 CI；只在验证通过后合并主分支。

## 研发决定

先证明**策略完全不变**，再观测局部 CPU 实测收益。后续若要调整碰杠阈值和副露倾向，必须用独立种子而非旧试验数据检查正式净积分、胡牌、放铳和时延；M3.81 绝不宣称原 M3.79 的策略因执行更快而得分更高。


## 实测验证 · GitHub Actions 39435663475

[M3.81 专项验证](https://github.com/CrazyA1ice/MahTrain/actions/runs/39435663475) 成功。共通过 **6 项等价性/防缓存污染/完整对局回归测试**和 **6 项原挑战 AI 碰杠规则测试**。两组固定种子（11、29）真实比赛的胜负、完整行为轨迹、公开复盘、正式 Hu/Kong/流局积分账本均与 M3.80 旧实现逐字段一致。

该次 CI 在 24 个物理合法牌型、3 次重复、每轮交替计时的本地 Python 进程中记录：**旧实现 1.407191 ms/牌型；优化实现 0.091176 ms/牌型**，仅该种基准计时下的局部比值 **15.4337×**，原始 JSON 在 CI artifact `mahtrain-m381-ukeire-parity-and-latency`。它包含缓存受益，同时两实现共享已预热的 `_cached_shanten`。不可据此保证：所有首次出现的牌型都快 15 倍、完整 AI 碰杠决策快 15 倍、联网/浏览器帧率提升、或 AI 战绩提升。其余规则回归由 `Sichuan Rules Kernel Tests` 单独核验。
