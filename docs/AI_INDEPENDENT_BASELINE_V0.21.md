# MahTrain M3.9：独立规则基线与四策略轮换对战（v0.21）

> M3.9 把上一阶段的三档项目内部AI，与**不调用向听或有效进张评估器**的独立规则基线放到真实牌局中对比。基线是新的自编、可审计形状规则，不是第三方机器学习模型；诊断成绩仍使用项目已有牌效评估器。完整四川血战规则仍为 `draft / enabled=false`，不能把实验胡牌事件数直接宣称为正式胜率。

## 一、独立规则基线的实际策略

新增 `src/mahtrain_core/ai_baseline.py` 的 `ShapeBaselineAgent`，与已有 `MahjongAgent` 独立实现完整5个行为接口（换三张、定缺、响应、杠牌、切牌）：

- **换三张**：从当前至少有三张的花色中选数量最少的一门，先换出自家牌中对子/邻张支撑较弱的三张。
- **定缺**：按换后各花色张数选最少的一门，数量相同按固定花色序处理。
- **切牌**：先处理定缺花色；不再持有定缺牌时，计算**自己手牌**每种牌的同牌张数、相邻一张/两张的邻张联系，优先打没有同张或邻张支撑的孤立牌。同分项才用各座位独立的可复现种子做随机选择。
- **胡碰杠**：服务端确认有合法胡牌选择时必胡；碰牌、明杠、暗杠和补杠均主动选择不过杠（简单基线刻意不估计这些操作的收益）。
- **严格隔离**：基线不导入 `src/mahtrain_core/efficiency.py`，不调用 `shanten_13()` 或 `analyze_discards()`，不读取牌墙后续、对手暗手或对手天听基准。它的优劣是可核对的规则，不是训练模型。

这条基线有意简单，只是为了引入**一个独立设计的策略参照**，并非独立的胡牌规则判定器，也不声称是研究界公认的第三方基准算法。

## 二、对照赛制：同一种子四次座次轮换

新增 `src/mahtrain_core/ai_independent_benchmark.py` 与 `examples/benchmark_independent_ai.py`：

- 同一个洗牌种子下打**4局**，每局有四位AI，分别是 `baseline`、`basic`、`advanced`、`challenge`。
- 第0～3轮依次平移四位策略的座位，确保每一个种子里，**每一种策略恰好坐过四个座位各一次**，庄家分配位置也得到对照；共4局仍然**只属于1个独立洗牌种子**。
- 直接调用已有四人规则状态机：看牌后密封换三张、四家换后定缺，庄家切牌、主动摸牌、胡碰杠规则响应，直到三家胡牌或墙耗尽。四种AI用相同的座位授权视图，没有偷看牌墙。
- 输出每策略的参与次数、合法胡牌事件、放铳责任、真实逐次切牌时的最低向听/局部最优次数及比率，进一步计算**在同一批种子下每档相对独立基线的百分点差异**。
- 前述最低向听和局部最优指标仍由**同一个项目内部评估器作为裁判**，不是第二个独立的评分算法。独立性只针对对手策略，不能误称“全套评价独立”。

### 统计与不确定性

- 严格以**独立洗牌种子**而不是“4局轮换”为样本量。
- 少于5个独立种子时只有具体事件次数和描述性差值，区间为 `null`。
- 达到5个独立种子后，默认按**整组4局种子**进行400次有固定种子的配对重抽样，探索性显示每档对基线差异的分位区间。这不是严格的人类实战胜率CI，不能推广到其他规则版本或其他AI对手。

## 三、网页入口

```bash
git pull origin main
python web_server.py
```

浏览器打开 `http://127.0.0.1:8765`，按 `Ctrl+F5`，找到 **「M3.9 · 独立规则基线与三档AI对照」**：

1. 设置起始种子，选择1个种子（4局）或2个种子（8局）。
2. 点击「开始独立基线对照」，服务端在**后台线程**运行，并显示已完成局数；与上一版四AI复盘共享“一次只跑一个任务”的并发限制。
3. 跑完后，四张指标卡分别显示**独立牌形基线、入门、进阶、挑战**的实际胡牌事件、放铳、向听和局部牌效；下面显示三档AI与独立规则基线的差值。
4. 「导出独立种子分组 CSV」下载每种子、每策略的原始计数。网页只返回**aggregate-only 聚合指标**，不会把比赛中的隐藏对手手牌、完整私有决策轨迹、秘密牌墙放进结果接口。
5. 任务完成后只保存在当前本地Python服务内存里，重启消失；网页和CLI都没有官方赛果或终局完整积分保证。

**重要**：网页因单次CPU开销较大，每次最多2个独立种子，无法显示有条件5种子的区间；需要验证探索性区间请走命令行的5个或更多独立种子。

## 四、命令行用法

从仓库根目录运行：

```bash
python examples/benchmark_independent_ai.py --seed-start 11 --seeds 1
```

生成可打开的Excel/WPS报表：

```bash
python examples/benchmark_independent_ai.py --seed-start 100 --seeds 5 \
  --json-out results/independent_m39.json \
  --csv-out results/independent_m39.csv
```

支持1～50个独立洗牌种子；注意**每种子4局**，复杂AI评估需要较长时间，宜分批运行。JSON包含四策略的指标、逐种子计数、差异与（样本足够时的）探索性区间。CSV采用UTF-8 BOM，便于中文桌面表格软件打开。这两个文件只有实际运行命令才生成到本机。

## 五、首轮自动对照实际结果（仅1个独立种子）

[GitHub Actions run 38909057226](https://github.com/CrazyA1ice/MahTrain/actions/runs/38909057226) 已在 Python 3.11/3.13 验收通过，包括184项单元测试、原有训练回归和4场独立规则基线对照。固定种子11轮换4局，均为`wall_exhausted`，每种策略实际参与4次：

| 策略 | 胡牌事件 | 放铳责任 | 最低向听切牌率 | 局部最优切牌率 |
| --- | ---: | ---: | ---: | ---: |
| 独立牌形基线 | 1 | 1 | 85.2% | 73.8% |
| 入门 | 0 | 1 | 69.9% | 49.3% |
| 进阶 | 3 | 0 | 100.0% | 74.5% |
| 挑战 | 2 | 1 | 100.0% | 100.0% |

**这不是实际胜率表**：只有一个独立的洗牌种子，4次换座次仍然相互关联。不能据此证明进阶比挑战更强，也不能推断对真人胜率，更没有任何可靠的区间估计。挑战档的局部最优率100%使用的是与其策略同源的项目牌效评估器。数据可以从该CI的 `ai-independent-python-3.11` / `ai-independent-python-3.13` JSON和CSV附件重新计算。

## 六、验收、边界与后续任务

`tests/test_ai_independent_benchmark.py` 核验：基线模块不导入项目向听函数/牌效评估器、只消费本家手牌且不受伪造的他家暗手/未来墙影响、换三张恰好同花色、碰杠胡合法、四座位轮换严格平衡、逐种子样本与区间、重算一致性，以及**真实完整四人对局108张牌守恒**。

`tests/test_web_app.py` 增加 M3.9 异步后台任务、聚合响应过滤、任务令牌隔离、异常参数和前端静态文件验证；CI在Python 3.11/3.13下各运行1种子×4局并上传 `ai-independent-python-3.11` / `ai-independent-python-3.13` 的JSON和CSV，原有M3.8逐动作复盘与单题、14轮训练均继续回归。

**仍未实现**：外部第三方独立AI、真人大样本对局胜率、公开风险模型的独立测试、正式杠钱底分与已胡玩家参与流局收付的完整规则。M3.9只增加独立规则型对照，不把草案规则下的临时账本当作正式计分系统。

**建议下一步 M3.10**：分别消融挑战档的公开有效进张排序与弱风险平局规则，确认每一项相对独立规则基线和进阶档是否真的提升终局胡牌事件表现；多批次运行≥5独立种子后才能开始谨慎描述不确定性。
