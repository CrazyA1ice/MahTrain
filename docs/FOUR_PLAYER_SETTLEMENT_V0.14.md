# MahTrain M3.2：天听轨迹与胡牌零和账本（v0.14）

> 本版本补齐的是**经牌局状态机证明的天听与胡牌支付规则子集**，不是已经上线的完整四川血战计分引擎。规则基础仍为[四川血战 v0.4 草案](SICHUAN_BLOOD_BATTLE_RULES_V0.4.md)，草案配置 `enabled=false` 不变。本机演示为娱乐训练，不涉及现金交易。

## 一、真实四人局天听跟踪

四家完成**看牌 → 同花色换三张 → 看新牌 → 同时盖牌定缺**以后，服务器才开始初始化天听状态：

1. **仅闲家**有资格。根据各自换牌后13有效张、已声明定缺计算初始完整合法听口 `W0`；起手未听则失格，不可事后补成“天听”。庄家也不具备此资格。
2. 只有本人的 `private_view(seat)` 可看到 `tian_ting.initial_waits`、资格、失格原因及检查次数；**其他玩家的初始听口是私有牌情，不能通过公共事件泄露**。
3. 玩家每次摸切完成、达到**13有效张稳定检查点**后，完整复算当前听口并与 `W0` 比较。听口增加、减少或变更均立即且**不可逆地取消资格**。
4. **碰牌立即取消**，即使以后又听回原始听口也不能恢复。**暗杠/明杠本身不直接取消**；杠后从尾墙补牌、再切牌回到稳定13有效张，比较原始听口。补杠建立在已碰刻基础上，不能恢复因碰而失去的资格。
5. 自摸或点炮结算时，后台只从**可信牌局轨迹的当前资格**注入 `tian_ting_verified`，由 `score_win()` 添加额外2番；客户端无法伪造该字段。

说明：这是对**稳定13有效张节点**的严格校验，不自行实现未确认的“未完结抢碰/抢杠中间态”天听扣除规则。此前 v0.13 的 `tian_ting_tracking=false` 状态已经相应更新。

## 二、当前可正式核算的部分：**胡牌付款账本**

`src/mahtrain_core/settlement.py` 提供 `WinLedger`，`FourPlayerOpening` 在所有合法点炮胡、一炮多响、抢杠胡、自摸完成判定时，逐笔生成真实结算流水。每笔保留：

- 赢家、付款人、点炮来源、胡牌事件类型和牌种。
- 番型名称、叠加项与附加番、**未封顶原始番数**、**房间封顶后的有效番数**、实际倍数。
- 付款规则：`单人付款 = 房间系数 × 2 ** effective_fan`。点炮/抢杠胡由责任出牌者付给每位赢家；一炮多响分别记账；自摸由当时**其他尚未胡的活跃玩家**各付同样的一笔。
- 所有分数均为**本地积分/系数单位**，不是货币。账本 `balances[4]` 逐笔归集，金额总和始终为0；错误座位、重复付款人、不匹配的番数/倍数都会在账本层被拒绝。
- 每局在新建 M3.1 试验模式时可选**房间系数（默认100）**和**最终番数封顶（默认3）**；需要注意这两个数不是“杠钱底分”。服务器端仍验证整数和边界。

### 特殊胡牌事件

- **天胡**：庄家四家定缺后尚未第一次切牌时，手牌直接合法胡，记录可验证天胡事件（原始4番）。
- **地胡**：其他玩家合法胡庄家打出的**第一张牌**，记录可验证地胡事件（原始4番）。
- **天听**：由真实完整 `W0` 轨迹判定，额外+2番；不是用户自己勾选。
- **杠上花**：杠后**尾部补摸**即合法自摸，额外+1番。
- **杠上炮**：杠后补摸并切出的牌被合法胡，胡者额外+1番；杠作废所需的原杠钱撤回**尚未记账，见下文**。
- **抢杠胡**：补杠声明阶段被别人胡第四张牌，仍保持原碰刻，不升级补杠；胡者额外+1番。
- 牌型与根数等仍调用原有 `score_win()`，统一**先累计所有合法番，再封顶**；天胡/地胡/杠上花与天听只凭服务器自己生成的事件上下文判定。

### 举例（演示使用房间系数100、封顶3）

- 庄家自摸合法天胡，原始4番，封顶3番，实结每家800，庄家+2400，另三家各-800。
- 庄家第一张牌被两名闲家分别地胡，双方各原始4番、封顶3番，庄家合计-1600，两名赢家各+800；两个胡牌声明都处理完才进入下一位活跃玩家回合。
- 杠上花和根等加番也参与**封顶前的原始番数计算**；屏幕始终分别显示原始与封顶番数，不会把4番写成3番的“牌型基础番”。

## 三、**未收款的杠钱与未处理的流局支付**

四川血战 v0.4 规则草案已经规定：明杠出牌者付2×底分、暗杠其余活跃玩家各付2×底分、补杠其他活跃玩家各付1×底分，但有两项**仍未被最终确认**：

1. “**杠钱底分**”与用户选定的“**房间系数**”是否应当统一；
2. 杠上炮、抢杠“**杠作废**”时，先记杠钱再撤销还是最后确认才入账，以及多家抢杠胡时责任金额如何合并。

因此 M3.2 **不偷偷把杠钱混入胡牌余额**。凡已完成的明/暗/补杠单独放进公开 `pending_kong_payments` 列表，标记**“未计价、待规则确认”**，不会产生伪造正负余额；抢杠成功且补杠未形成时则不会登记该补杠收款。暗杠对应公开列表不暴露真实杠牌牌种。

牌墙耗尽后的**查花猪、查大叫**也不自动赔付：尽管触发条件已在 v0.4 草案确认，仍未决定已胡玩家的赔付参与范围、缺门公开面子归属等重要账本细节。对局状态仍停在 `wall_exhausted`，前端会明确提示未结算。

**因此页面目前呈现的是“胡牌部分结算”，不能把余额当作整局最终输赢。**

## 四、网页操作与验收

```bash
git pull origin main
python web_server.py
```

打开 `http://127.0.0.1:8765`，按 `Ctrl+F5`。找到**「四人血战 · 碰杠胡响应试验（M3.1）」**：可输入房间系数、番数上限，再按原有流程换三张、同时定缺、摸切与响应。

网页新增：

- **本人天听**：起手完整听口、当前是否有资格、失格原因及复核次数。
- **四家胡牌积分**：四个座位的正负余额，显示房间系数与封顶番数。
- **详细胡牌流水**：每一笔赢家、原始番数、封顶番数、实际倍数、付款人/金额、特殊附加番。
- **杠钱暂缓**：只显示已完成杠的待定事件数量，不把未经确认的金额作为收入。

对局脚本三家依旧是合法动作驱动的**确定性演示程序，而非三档 AI**；所有天听初始听口只通过持有人自己的私有状态展示，不因屏幕上有账本而外泄对手的暗手牌。

### 测试

```bash
python -m unittest discover -s tests -v
```

重点：`tests/test_four_player_settlement.py` 和 `tests/test_web_app.py` 验证天听初始化/不可逆取消、相同听口保留、碰牌取消、自摸天胡、双地胡、一炮多响各自付款、零和账本、杠上花和杠上炮的封顶前附加番、杠钱仍未入账及 HTTP 不能伪造付款信息。GitHub Actions 同时跑 Python 3.11/3.13、网页 JS 检查与旧版训练回归。
