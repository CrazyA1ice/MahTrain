# MahTrain M3.6：三档 AI 全程摸切、自博弈与轮换对照（v0.18）

> **范围提醒：这是四川血战 v0.4 草案下的四 AI 自动对局实验，不是正式胜率榜。** 前一阶段 M3.5 的50个局面只验证单步牌效；本轮支持合法开局、完整逐次响应、摸切至牌墙耗尽或三家已胡，以及逐局审计和座位轮换。规则配置保持 `draft / enabled=false`。

## 1. 做了哪些实际改动

新增 `src/mahtrain_core/ai_tournament.py`，使用已存在的 `FourPlayerOpening` 和 `MahjongAgent`，不新增私有规则或给 AI 开后门。对于每个种子：

1. 同一108张洗牌结果下，各玩家各自收到其座位授权的手牌；四家**看牌后**分别选择三张同花色牌，四家封存完再统一交换，换后分别定缺。
2. 从庄家先打开始，自动处理各家**自己的合法自摸、明暗补杠、切牌**及另外三家对该牌的逐人**过、胡、碰、明杠**选择。补杠抢胡窗口同样由响应者逐人作出决定。必须等待全部活跃人完成响应才允许继续轮转，**不用旧版 `pass_all_claims_demo()` 偷跳牌权**。
3. 三人已胡时终止，或牌墙真正耗尽后标识 `wall_exhausted` 并生成**不入账**的查花猪/查大叫预览；始终检查108张实体牌守恒、原有胡牌账本零和以及未设底分的杠钱不入账。
4. 每次 AI 切牌另用**本人真实暗手+公开可见弃牌/副露**计算切后向听、与最小向听的差距、是否属于局部最优进张选择。记录所有出牌和声称的响应，暗杠种类不向公开事件日志暴露。
5. 同一种子分别完成**三轮策略座位轮换**：座位0–3的难度依次为 `basic/advanced/challenge/basic`、`advanced/challenge/basic/advanced`、`challenge/basic/advanced/challenge`。因此**对每个种子**，每一难度各获得4次座位暴露，且四个座位都至少体验一次每档难度。各难度接触相同初始牌墙和庄家位置，减少座次偏差。

当前每个种子完成3个四人局，默认对比2个种子共6局。这些局不是保证产生三个胡牌者：有的会正常耗尽牌墙。任何规则异常都会触发报错，不会被伪装成正常完成。

## 2. 统计口径（避免误导性胜率）

新增的指标包括：

- **胡牌事件数**：真实完整流程中的自摸、点炮、抢杠胡的合法结果；同一张牌被多人胡会记多个获胜座位。另按每档**参与的座位次数**记录 `win_event_fraction`，仅为“实验座位出现合法胡事件的占比”，**不是正式血战最终胜率**。
- **放铳责任次数**：自身弃牌或补杠事件被别人合法胡的次数；一炮多响按涉及的赢家分别计数。
- **切牌最低向听率 / 局部最优进张率 / 平均向听劣势**：来自**真实的每一轮摸切牌面**，区别于 M3.5 的开局受控测试牌面。
- **胡牌部分积分**：只从已经核验的胡牌付款账本取值。**未确认的杠钱底分不自动赋值、不出款；牌墙耗尽的花猪/查大叫金额只读试算，不算正式净收益**。
- **策略函数耗时**：使用 `perf_counter_ns()`，为具体执行机器及缓存状态下的估计；不会影响用种子复现动作，但不能要求两个环境的毫秒数相等。
- **终局状态**： `finished` 为三个不同座位已胡，`wall_exhausted` 为牌墙耗尽。报告不隐瞒未胡玩家。

严格说明：三档 AI 互相对战，且都来自项目内的启发式模型。比较同一套内部牌效目标仍不足以证明**独立玩家实战胜率、对真人胜率、真实放铳概率或完整比赛净收益**。要做这些结论还需独立多种对手、更多种子和已确认的全套结算规则。

## 3. 如何运行并查看逐局报告

更新代码：

```bash
git pull origin main
```

快速运行2个种子×3轮座次配置＝6局：

```bash
python examples/tournament_ai.py --seeds 2
```

保存所有实际动作/公开事件、各家合法胡牌记录及每座位的汇总 CSV：

```bash
python examples/tournament_ai.py --seed-start 100 --seeds 10 \
  --json-out results/ai_selfplay.json \
  --csv-out results/ai_selfplay.csv
```

`--seeds` 当前上限为100，过大样本会显著增加向听搜索耗时，建议先小批次验证。

- **JSON**：包含每个种子的三轮轮换、每一步的公开响应/切牌/相应牌效、终局状态、局部积分、公开事件、每档耗时，以及总体汇总。**只记录公开牌种**，暗杠只记录杠的类型，不泄漏具体牌。
- **CSV（Excel/WPS 可直接打开）**：每局四行，列出种子、轮次、庄家、座位、难度、终局、该座位胡牌与否、胡牌方式、放铳责任次数和不含杠钱的胡牌部分积分。
- **CI 附件**：GitHub Actions 在 Python 3.11/3.13 下各使用固定种子11–12自动跑6局，分别保存 `ai-selfplay-python-3.11` 和 `ai-selfplay-python-3.13` 的 JSON/CSV。与旧 M3.5 的32种子单次切牌报告独立保存，防止混淆。

报告中的 `trace`（决策日志）在相同环境中应按相同种子可复现；单独的 `timings_ms` 则是测量值，无须跨运行一致。

## 4. 首轮 GitHub Actions 可复核结果（少量样本）

经过 [GitHub Actions run 38896977426](https://github.com/CrazyA1ice/MahTrain/actions/runs/38896977426) 完整验证：Python 3.11、3.13 均通过 **167项单元测试**；M3.5旧版单步基准、全部训练脚本和四人开局兼容测试也成功。M3.6 自动使用**种子11、12，每个种子3次座位轮换，共6局**。三个等级各获得8次座位暴露；其中2局三家胡牌结束，4局牌墙耗尽。

Python 3.11 的实测：

| 档位 | 座位参与 | 合法胡牌事件 | 放铳责任次数 | 最低向听切牌率 | 局部最优切牌率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 入门 | 8 | 0 | 3 | 72.3% | 53.4% |
| 进阶 | 8 | 6 | 3 | 100.0% | 80.7% |
| 挑战 | 8 | 8 | 1 | 100.0% | 100.0% |

**解释边界**：只有2个独立种子，另外3次座次是同一副初始牌的重复实验，不能当成6个独立样本计算置信区间，也不应断言“挑战 AI 的真实胜率为100%”。三档对手均是同项目启发式AI，挑战策略也复用了本项目的局部最优牌效目标。上表的胡牌事件和放铳责任只代表这批局的**实际合法牌局事件**；杠钱默认无底分而不计价，流局支付未入账。

本轮 CI 的四个 Artifacts 中，`ai-selfplay-python-3.11` 与 `ai-selfplay-python-3.13` 各含真实六局的 **JSON行动/公开事件记录** 与 **CSV每座位结算摘要**；原 M3.5 的单步AI基准也仍然独立保存在两个附件中。下载时到对应 Actions 页面最下面的 Artifacts 区域操作，不需要执行别的脚本。

## 5. 自动测试

`tests/test_ai_tournament.py` 针对固定种子执行了实际完整的AI自动打牌：检查三档对各个座位轮换均衡、开局真实108张牌守恒、所有响应合法且不跳过牌权、暗杠公开信息隐藏、切牌牌效不变量、重复运行的事件与积分完全一致、未知种子及轮换输入拒绝、可追溯 JSON 格式，并验证三家胡牌时终止或无牌时流局。

```bash
python -m unittest discover -s tests -v
```

CI 额外运行命令行冒烟，并检查6局里每种难度各有8次座位暴露、每局108张守恒。

## 6. 下一步需进一步补齐

1. **扩大独立随机种子**，计算按种子分组的置信区间。不能把3次轮换当成3个独立的洗牌样本。
2. **加入独立的对手基线**（非本项目三档 AI），避免同源评估器偏差，并对强防守、杠/碰机会成本展开消融。
3. **正式确认全套结算**，特别是杠钱底分与房间系数的关系、已胡者是否参与花猪/大叫的收付；确定后才能报告整局净积分强弱。
4. **完善可视化对局复盘**，在网页中逐步回看每次 AI 的合法出牌、牌效变化与响应优先级（只提供当时公开的牌面，不能泄漏先前隐藏牌）。

**本版本确实运行完整的四人摸切与响应过程，但处于规则草案和启发式 AI 阶段；不宜表述为正式比赛胜率或已完成的商业多人游戏。**
