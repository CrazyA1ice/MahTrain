# MahTrain M3.45：完整自适应牌桌与按需出现的碰杠响应（v0.57）

## 修复目标

用户反馈整个牌桌底部仍显示水平滚动条，需要左右拖动才能看四家；此外碰杠选择在没有实际待决动作时也会持续占据牌桌中央。

### 桌面／平板全宽适配

问题来自上一轮桌面 CSS 的 `min-width:1510px` 与外部 `overflow-x:auto` 组合。仅将滚动条 `display:none` 会让整桌牌被裁掉，不是合格修复。本轮用全宽 `box-sizing:border-box;width:100%;min-width:0` 取代固定最小宽度，外层取消横向平移。701px 以上重新用三栏比例分配两侧玩家／中间牌河，中央上下牌河跨三列，以 **clamp** 对真实手牌、牌背、牌河牌面和间隙按宽度缩放，确保窄桌面时不必拖动整个牌桌。三个 AI 牌背仍为固定默认大牌面，不增加尺寸按钮。左右牌河延续「左上→下、右下→上」的真实出牌时序，不改任何真实事件或取走标记。

700px 以下仍沿用手机紧凑四面桌；**只有手机个人手牌行**可独立滑动以保留选牌准确性，整个牌桌不能左右拖动。

### 弹窗按真实响应机会显示

只在实际有待处理的合法操作时弹出中央选项：

- 别人打出牌后，0号玩家**尚未提交**碰、杠、胡或过，且存在除「过」以外的合法选项；
- 别人补杠时，0号玩家能抢杠胡并尚未响应；
- 自己摸牌后的合法暗杠/补杠可选时，弹出一次带「暂不杠 · 继续出牌」的可关闭操作窗，拒绝后本次牌局状态不会反复弹出；需要时可以点个人操作区的「可杠牌 · 查看选项」重新打开。

仅「过」合法的情况原本就由服务端自动继续，不额外闪出无意义的按钮窗口。提交碰杠胡或过后，前端先关闭窗；服务端响应确认后重新读取状态，即使 AI 还在裁决，因 `claim_submitted` 标记仍不会重新打开同一响应窗。如果 HTTP 操作失败，前端重新渲染真实仍合法的待选操作，方便重试。

### 保留的真实规则

没更改抢杠胡／一炮多响优先级、定缺、交换三张、自摸、杠后补摸、暗杠三盖一翻、真实积分、语音节拍或 AI 的信息可见范围。出牌／碰杠按钮仍然调用相同的服务器 API，不能越权碰或杠。

## 回归覆盖

- 页面 CSS 的全宽无横向拖动断言、700px 以下个人手牌独立滑动；
- 玩家没资格做任何碰杠胡时弹窗隐藏；只允许「过」也隐藏；
- 玩家已经提交响应但 AI 仍在应答时不二次弹窗；
- 可杠提示允许「暂不杠」，再次重绘仍保持关闭，重新点击可杠按钮可打开并正确发送原有杠牌请求；
- 原有四家牌河17张跨列的公开时序、回顾隐私、规则结算、AI 消融不受影响。
