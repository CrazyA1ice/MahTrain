# M3.88：黑色中心记分板约束、完整历史周期统计及终局四家开牌复盘

## 为什么要改

- 经典 2D 中央记分黑板约 280×160px，当前行动、局数、庄家说明、结算文字过长时，原有布局缺少明确的水平收纳边界；本轮让黑板文字在边界内省略/折行，中央操作窗口在其内部纵向滚动，**不改变四边手牌、牌河与黑板的位置尺寸**。
- 此前服务器把所有已完成战局加入累计算分，但 **趋势图仅最近 30 局，列表仅最近 50 局**；这并不满足查看全部历史与按周期筛选。现在整个统计结构都采用同一时间范围，而非只筛选曲线、不筛选分组。
- 旧版 match_archive 故意仅保存公开状态，故**旧档案中的对手暗手无法追溯**。本轮引入严格隔离的终局教学档案，让**本轮及后续新完成对局**可以开四家牌，并比较每次出牌前真实可用的前三切牌；禁止从最终手牌或未来牌墙编造往局信息。

## 历史时间范围

历史档案顶部有四档筛选：**全部、最近一年（滚动 365 天）、最近一月（滚动 30 天）、最近一周（滚动 7 天）**。使用服务端 UTC 归档时间，切换范围后同时刷新：

1. 0 号玩家正式净积分总览、每局正负收益分布及累计净积分曲线；
2. 四个座位的胡牌/杠钱/正式流局/正式结算积分、分布；
3. 根据 1～3 号 AI 难度组合与房间参数分组的正式积分表现；
4. **历史列表每页 50 局的上一页/下一页**，不再只能打开最近 50 局。

统计与曲线均使用当前周期内**所有核验通过的已保存终局**。曲线在每个周期从 0 累计，因此切换窗口前后的累计值不能直接当作一个连贯总资产序列。不同房间底分的合计分数不等于可直接横向比较的竞技水平。

## 终局四家公开 + 逐巡教学

- Python 服务端内部在**每次真实规则动作之前/之后**记录四个座位的当时暗手与公开动作对应关系。实时 HTTP `match_continue`、`match_resume` 和 `public_steps` 完全不含这些内部资料。
- 正式判定为 `finished` 或 `wall_exhausted` 并生成本地 SQLite 归档时，才把终局受控私有历史转换为 `post_round_review` 写入历史报告。归档仅记录各动作当时的**四家手牌**（不保存未来牌墙、随机种子、操作令牌）；无需也不能反向推导对手在未出牌时的行动意图。
- 点开新版档案，逐步按动作编号查看**四家当时的真实手牌**，以及当时公开副露、弃牌河；此前只有背面显示的档案仍保留牌背，提示“创建时未记录暗手，不能还原”，**不伪造完整复盘**。
- 对每个实际 `discard` 事件，取其**出牌前**本人 14 实效张、自己的碰杠、定缺以及当时已经公开的其他牌，用公开牌效算法给出**至少可计算时的前三种切牌**，每种列出切牌种类、切后向听数、剩余有效进张的未知副本数；标出本巡实际切牌的排名与是否并列最优。
- 玩家 0 号的本局整体**最优切符合率** = 可正式评价、已记录的实际切牌中，达到该阶段“最低向听数→最多有效进张副本”最佳档的次数 / 这些可评价切牌总次数。**同等最优并列都算符合**；非完整 14 实效张、规则允许直接胡的阶段不会强行编造成可出牌比较。0～3 号逐巡都可展开看前三切。
- 这一“最优”仅是**现有牌效框架的局部最优**，不等于考虑对手具体隐藏牌、真实后续摸牌、风险或番型上限后的最优期望值。任何更高层面的最佳切牌结论需要另行建模验证。

## 旧数据和安全限制

旧 `privacy="public_board_only"` 档案仍能完整查看以前保存的公开河牌、副露、胡牌、正式结算、时间与积分走势，**但无法显示根本没存过的 AI 暗手**。新版 `privacy="post_round_full_reveal"` 档案仅在终局才出现；正在打牌的所有现场接口保持私牌保密。不采集对手暗手到浏览器 localStorage，不把未完成牌局发给历史查询，也不将隐藏牌用于在线 AI 决策。

注意：公开所有家实际暗手将增加本地 SQLite 归档的磁盘占用；这是用户明确要求的**终局复盘功能**，只有本地历史详情查询能查看。多人联机的权限策略若后续引入须重新审视，本轮仅限本地单机对战。

## 验收

- `tests/test_post_round_review.py`：真实物理手牌归档、旧档案仍公开、异常私有帧拒绝、定缺强制切和前三候选、最优切符合率，以及 7/30/365 天/全部四周期列表、分组、总积分和分页一致。
- `tests/test_match_archive_dom.js`：UI 脚本可管理新周期/翻页，不将旧档案伪造为全暗手复盘。
- `frontend_2d/test/browser-center-overflow.mjs`：真实 Chromium 在冗长下局庄家规则说明下检测黑板和中央按钮不越界，同时复测固定桌面、胡牌、杠牌方向。
- 仓库的完整 Python 单元、真实 HTTP 终局及经典网页集成测试，以及编译后的 `frontend_2d/dist` 都必须通过并上传后才合并。
