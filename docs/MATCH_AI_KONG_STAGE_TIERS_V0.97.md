# M3.86 · 多候选杠的精确向听优先级分层求值

## 核心问题

M3.83 先用精确 `shanten_13` 过滤掉比最佳切牌更差的杠，避免必然拒绝的浪费；但对**仍然可选的多个杠牌**，原算法即使已经存在向听数严格更低、满足天听保护的杠，仍然完整评估普通切牌参考态（若有同向听候选），也会完整评估比最优杠向听数更差的杠候选。这些评分无法改变最终选牌，因为策略的完整字典序中首先比较 `-shanten`，随后才比较价值和已知有效张。

本轮只改变求值顺序与不必要的全量候选计算：**按精确向听数从低到高逐层评估，命中可选层后立即返回该层内按旧版价值排序的最优候选**。如果第一层候选不能保留天听（或原有门槛不满足），继续检查下一层，不得凭“更低向听”无条件杠。

## 完全保留的规则与边界

- 所有合法自摸暗杠 `an_gang` 与自摸补杠 `bu_gang` 选项仍来自服务端的 `kong_options`，不新增自己无法做的杠。
- 继续保留正常出牌最小向听数、定缺强制先切、不退向听、天听原听口严格相同与 75% 有效进张及价值保留阈值；对严格更优向听的候选原本就不适用 75% 的横向比较。
- 对同一向听层的所有可接受候选，必须完整计算有效张与番型价值，再以 `(-shanten, value, ukeire, kind preference, tile index)` 原键排序；**不能碰到该层第一个可用杠就提前返回**。
- 当某个更优向听层已经有可执行杠，后面较差向听层不可能依靠更大番值获胜。因而可直接跳过后续的多次有效张、逐张番型、无收益基准评分；否则按旧逻辑继续到相同向听层，此时仍完整构造各个最优切牌参考态并执行 75% 阈值比较。
- `visible_tiles` 依旧只包含己方合法信息与公开弃牌、副露；不访问对手暗手、未来牌墙，补杠的抢杠决议、杠钱、后续尾摸由 Python 权威引擎处理。

## 对照测试

`tests/test_ai_kong_tiers.py` 内冻结了一份 M3.85 正式 `_challenge_kong` 原函数，仅修改函数名。验证：

- 真实 108 张四川牌局中两种暗杠同时可选，旧版/新版决策完全一致，不突变 `private_view`；
- 真实七对等待与不利杠必须仍被拒绝；
- **混合优先级**合成决策：一张暗杠向听数严格更优，另一张杠即使价值高得多也不能获选；新版不必评分后者和原本无用的基准；
- 天听保护不满足时不能提前退出，必须回退到其他向听层，并准确核验价值阈值；
- **同向听双杠**必须计算两个候选的全部价值，不能为了提速牺牲选牌结果；
- 未来牌墙与对手隐藏手牌的伪造字段无权影响决策；
- 两套真实种子以旧版代理和新版代理分别完成整局，比较每一步行动、公开复盘、赢家、胡牌/杠钱/流局的三账本和 108 牌实体守恒；另复跑 M3.83、M3.82 与原挑战 AI 测试。

`examples/benchmark_kong_tiers.py` 对**完全相同的合法自主杠观察**采用固定预热后新旧交替计时。分别记录每个策略实际调用 `_call_outlook` 的次数及 CPU 耗时中位数。选择场景分别为真实两暗杠及真实七对防退向听；这两个场景未必包含一优一差的混合向听候选，所以不可把它们的微基准差异当成全体对局的性能保证。混合优先级的计算次数则通过定向回归明确证明，避免伪造不存在的测试场景。数据应保留原始 JSON 和 CPU 变化可能是负数的事实。

科研解释：**此轮只减少不可能影响正式选择的牌效运算，不是碰杠策略增强。** 不能由微基准推论 AI 胡牌率、净积分或全对局用时同步增长；此前 M3.80 独立种子实验也不支持笼统宣称激进碰杠更强。
