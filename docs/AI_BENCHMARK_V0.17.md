# MahTrain M3.5：三档 AI 同局面牌效评测与公开风险信号（v0.17）

> 本阶段新增**可重复执行、原始记录可下载**的 AI 切牌能力对照。它不宣称是真实四人对局胜率，也不改变 v0.4 规则草案 `draft / enabled=false` 的事实。三档 AI 仍是启发式策略，并非训练模型。

## 1. 对照评测的严格定义

新增 `src/mahtrain_core/ai_benchmark.py`，命令行 `examples/benchmark_ai.py`。给定一段种子，先用同一开局策略构造**实际108实体牌、合法换三张和四家同时定缺**的牌面。取庄家的14张真实开局手牌作为其中一个待切决策样本；对于仍含缺门的样本，可另生成**合法实体牌守恒的“缺门已清理”控制牌面**：构造器将缺门牌与物理墙中其他花色的牌等量置换，重新检查108张守恒。这种控制牌面只是用来测试非缺门切牌策略，**不代表它是从游戏中实际摸出来的，也不把未来牌墙给任何 AI**。

对每一个非已胡的待切牌面，三档 AI 使用相同的本家暗手、公开弃牌、公开副露和已揭示定缺作独立决策。另以现有 `analyze_discards()` 完整枚举本牌面各个切牌作为**同一局面牌效基准**：

- **最低向听率**：选中的牌是否令切后向听数达到全部合法切牌的最小值。
- **最优有效进张率**：在上述最小向听的前提下，是否同时令尚未看见的有效进张**枚数最大**。
- **平均向听劣势**：实际切后的向听数减本局最小向听数，逐局平均；0最好。
- **有条件进张损失**：只对已经选到最小向听的决策，统计相对最优方案损失的有效进张张数。
- **单次决策耗时**：只计 AI 策略函数调用的本机墙钟耗时（毫秒），和 CPU、Python、缓存状态有关，不是可跨硬件比较的客观常数。

**注意公平比较和评估偏差：挑战档本身就调用了 `analyze_discards()` 的牌效排名，因此在这个同源的牌效基准上达到100%是设计使然，而不是独立证明其真实四人对局胜率更高。** 进阶档优先最小向听，也是预设规则带来的确定优势；本阶段只能判断“是否符合已定义的策略目标”，不能声称挑战档通过了独立外部算法验证。

## 2. GitHub Actions 的首份可复核结果

自动 CI 使用种子 `0..31`，总共32局真实开局种子，对应**50个可以比较的决策局面**（其中包括合法、但非真实经过摸切轨迹的无缺门控制局面；1个已胡局面跳过）。

下表是 GitHub Actions Python 3.11 的一轮真实结果，运行日志及每个决策的原始 JSON/CSV 已在[本轮 CI](https://github.com/CrazyA1ice/MahTrain/actions/runs/38894342677)保留。决策毫秒随运行条件变化，不能当固定性能承诺。

| 档位 | 最低向听率 | 最优有效进张率 | 平均向听劣势 |
| --- | ---: | ---: | ---: |
| 入门（basic） | 72.0% | 50.0% | 0.280 |
| 进阶（advanced） | 100.0% | 68.0% | 0.000 |
| 挑战（challenge） | 100.0% | 100.0% | 0.000 |

### 结果说明

1. 在这些**相同牌面**上，进阶档比入门档更符合“最低向听”目标；挑战档又在同向听的进张张数上获得优势。这仅为**固定牌效目标的对照**。
2. 挑战档运算成本明显更高，因为它要逐一评估切牌后的有效进张。示例 Python 3.11 CI 的平均策略时间约 **24.6毫秒**，进阶档约 **0.08毫秒**，入门档约 **0.013毫秒**；另一次同种子 CI 的具体耗时就会不同。
3. 这些是**50个切牌选择**，不是50局完整血战最终胜负。胜率、平均最终积分、抢杠/杠钱结算收入、真正危险牌放铳概率**一概未在这份对照中估计**。
4. 对照牌面开局没有较多公开副露，因此不足以测量新防守信号对长期赢牌概率的贡献。后续必须在有完整弃牌和碰杠的多回合相同状态下对照、扩大种子与置信区间，再讨论真实难度排序。

## 3. 新增的挑战档公开副露风险规则

在 `src/mahtrain_core/ai.py` 加入 `public_suit_pressure(tile,view)`：

- 仅检查**别的活跃玩家已公开的碰/杠**，忽略其暗手、没有揭示花色的暗杠，以及已经胡牌退出的人。
- 当一位对手**至少两组公开副露都集中在某一种花色**，且该花色不等于此人公开的定缺花色时，把这种花色视为**弱风险信号**。
- **仅在切牌后的向听数完全一样、剩余有效进张也完全一样的情况下**，挑战档才把压力更小的切牌排在前面。这样不会为未经验证的危险概率牺牲已知牌效优势。
- 这是**花色集中度的风险近似指标，不是精确放铳概率，也不能把别人打过的牌称作绝对安全**。所有决策仍由四人规则引擎执行与校验。

自动测试构造了公开副露相同条件下的两张并列切牌，检查弱风险信号能够改变**最后的平局排序**；一旦其中一张有更高有效进张，挑战档应当优先牌效而非风险。

## 4. 使用方法与原始报告

在仓库根目录执行：

```bash
git pull origin main
python examples/benchmark_ai.py --seeds 32 \
  --json-out results/ai_baseline.json \
  --csv-out results/ai_baseline.csv
```

输出包括每个档位的决策总数、最低向听率、最优有效进张率、平均向听劣势、平均策略耗时。

- **JSON**：`seed`、`scenario`、`chosen`、`minimum_shanten`、`chosen_shanten`、`chosen_effective_copies`、`best_effective_copies_at_minimum`、两项最优状态、两项劣势、耗时；可重算汇总并进行统计分析。
- **CSV**：用 `utf-8-sig` 编码，适合用 Excel/WPS 打开，按「档位＋种子＋场景」对应相同的牌面。不同随机种子之间不可错误认作重复试验。
- **GitHub Actions**：Python 3.11 与 3.13 的测试任务都自动运行32种子基准并上传**`ai-benchmark-python-3.11` / `ai-benchmark-python-3.13`** 的 JSON/CSV Artifacts，保留最原始记录；GitHub Actions 的 artifact 保存时长由仓库设置决定。

更多独立种子可运行（不要混用训练/评估样本产生未标注偏倚）：

```bash
python examples/benchmark_ai.py --seed-start 100 --seeds 100 \
  --json-out results/ai_validation.json \
  --csv-out results/ai_validation.csv
```

这些输出文件**只会在你主动执行命令时写入本地**，并不暗示 GitHub 仓库已自动包含这批基准文件。
