# MahTrain M3.34：网游风格人机对战第一轮体验优化（v0.46）

本轮是**用户体验优先**的更新，参考用户提供的三张四人麻将网游截图：中心绿色牌桌、四边玩家信息、清晰醒目的手牌、当前行动/剩余牌数状态、碰杠胡/摸牌高亮与胜负反馈。没有照搬网游素材、人物肖像或商用 UI 资源；桌面背景、边框、座位图标完全基于项目原有 CSS 和已有牌面图制作，**未增加外部图源或网络请求**。

## 本轮已经落地

### 1. 一眼看到“轮到谁、还有多少牌、我缺哪门”

人机对战（不是教学出题）开始后，牌桌前显示4格实时状态栏：

- **当前行动**：开局准备、玩家出牌、其他座位行动、公开动作回放、碰杠胡响应、对局结束。
- **剩余牌山**：严格读取当前公开或真实服务端状态的 `wall_count`，不是自编动画剩余张数。
- **我的定缺**：真实的本人定缺或“待选择”，不显示别人暗牌。
- **操作提示**：根据当前阶段提醒换三张、定缺、碰杠胡、摸切/手切、已胡后等待、对局结束等；回放时只显示公开状态，不将最终暗牌提前混入。

### 2. 牌桌视觉与手牌反馈

- 青绿色高对比桌呢、木色边框、柔和内阴影；牌河与牌墙保持分区，但减少重边框的割裂感。
- 每家增加无真人头像的圆形座位徽章，强化桌上四个方向感；已有“正在行动”“已胡”高亮继续有效。
- 自己的手牌和鼠标/键盘焦点更加醒目；单张摸牌继续固定在玩家右手边，保持明显间隔与金色标签，切牌选中态抬起。
- “放大手牌”按钮可即时切换两套尺寸。大量牌仍会横向滚动，不强制缩小文字或变换牌顺序。

### 3. 常用操作离手更近

- 常驻在牌桌附近的“沉浸牌桌 / 显示详细信息”切换，只收起下方**冗长技术诊断区**。真实规则、出牌操作、胡牌提示、结算、结束复盘均保持可用。
- 常用操作按钮在对局下方采用滚动过程中的粘性定位，并提高点击面积；小屏允许内部滚动，避免盖住全部桌面。
- **“出牌二次确认”**：
  - 默认：鼠标设备可像原来一样单击出牌；`(pointer:coarse)` 触屏设备默认开启安全模式。
  - 开启后，点击手牌只在前端高亮选牌，**没有提交任何出牌请求**；必须再按“确认打出[牌名]（手切/摸切）”才真正提交；可“取消选牌”。
  - 即使刚摸到的牌和手里已有的牌同值，所选的是右侧摸牌就提交 `from_draw:true`，所选的是原手牌就提交 `from_draw:false`；切换模式或新一局会清除暂存选择。
  - 遵循服务器“实际出牌是否允许”的规则校验，不自行推算对手暗牌或牌墙内容。

### 4. 已修正文案

原“牌墙耗尽、待实现查花猪/查大叫”不准确，现表述为“牌墙耗尽 · 方案A流局已结算或等待牌形核验”，与原有正式方案 A 计分及异常牌形延期入账保持一致。

## 验收

```bash
git pull origin main
python web_server.py
node tests/test_match_board_dom.js
python -m unittest discover -s tests -v
```

打开 `http://127.0.0.1:8765`，新开人机对局；测试桌面/手机触控下的放大手牌、沉浸牌桌、实时状态、选牌→取消、选牌→确认、右侧摸牌与同值旧手牌对应的不同 `from_draw`。若开局未结束就点击新开局，保留原来的确认提示。

GitHub CI 在 Python 3.11/3.13 下跑 Node DOM 与 Python 规则测试，要求无新请求泄露暗手，原 AI 对局、麻将规则、公开回放及 SQLite 历史不受影响。

## 尚未涉及

本轮**没有**修改 AI 决策算法、定缺/一炮多响/胡牌番数规则、牌墙内容、商用头像与真实网络房间。窄屏仍可横向滑动完整牌桌（优先保证四家牌墙和河牌可读），尚未制作彻底无需横向滑动的小屏布局；大型动作字幕/胜负弹幕及皮肤自选可排入后续体验版本。
