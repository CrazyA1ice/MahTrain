# M3.61：真实浏览器中的固定牌河与14张手牌验收

## 修复缘由

M3.60 将所有牌河改成固定56格坐标（本家和对家14×4，左右侧4×14），并使用CSS overflow:hidden去掉了内部滚动。原来的 DOM 测试能够证明坐标映射与时序正确，但**无法证明实际 CSS 轨道宽度容得下所有列**。尤其在手机 280—360px 左右，预设的侧面轨道宽度可能大于容器可用宽度，导致第4列被裁掉——禁止滚动不能靠裁切实现。

## 这轮变更

- 移动端：每张河牌的横向槽距（本家14列、左右侧4列）按屏幕宽度提前确定，窄屏采用更小的夹限值，确保**完整的四列侧家槽位在牌河容器中**。
- 桌面端：上一版无条件采用962px的中心牌桌高度；在约701px—1024px的笔记本或平板视口会产生大量无效空白。这版根据预设牌槽宽高，开局前直接计算水平4行与竖向14行的**固定高度**，打牌过程中绝不重新计算。
- 内部：牌河保持固定14×4/4×14坐标。禁止纵向滚动，且必须没有**隐藏的**纵/横轴内容越界；不可只靠 `overflow:hidden` 静默裁切。
- 保留本家手牌 14 张的独立区域：宽屏必须在一行完整显示，窄屏可仅水平滑动本家手牌，四家的牌河一律不滚动、不与手牌交错。
- 已新增 `tests/test_match_layout_browser.js`，依赖独立CI安装的 `playwright-core` 驱动 Chromium；访问真实 `web_server.py` 页面并启动对局后，把**压力测试用的占位河牌**注入四家牌河。压力场景让四家各显示全部56格（仅用于测试单个容器最大容量，**不是声称真实108张牌能同时形成224次弃牌**）。图片、JSON几何数据作为独立CI附件保存，并非正式界面构造器。

## 验收指标

对每个视口，浏览器测量（不能从 CSS 静态猜测）：

1. 整张牌桌在屏幕水平边界内，不出现被裁掉的左右桌边。
2. 4个牌河的 `scrollWidth<=clientWidth` 和 `scrollHeight<=clientHeight`，且 `overflow-x/y` 都是 `hidden`；这不仅禁滚动，也禁止藏住溢出的第4列和第14行。
3. 每一个格位和旋转后的 `.tile` 的 `getBoundingClientRect()` 均在自己的格子、整个河牌容器内；56格一一对应，无相互覆盖。
4. 底家牌河的底边不超过底家手牌的上边。
5. 701px 及以上：14张本家手牌在同一水平容器内，不需要滑动；700px 及以下：允许仅本家手牌独立水平滚动。
6. 所有上述坐标与截图涵盖 280/320/375/390/700/701/1024/1440px，检查手机、断点附近、平板与桌面。

## 运行

```bash
npm install --no-save --no-package-lock playwright-core@1.56.1
python web_server.py
node tests/test_match_layout_browser.js
```

浏览器必须已安装 Chrome/Chromium；GitHub Actions 若没有系统 Chrome 会先安装 Playwright 的 Chromium。浏览器验收后的截图及JSON位于 `test-artifacts/match-layout/`，CI 附件名 `m361-match-layout-browser-screenshots`。本次仍未调整任何麻将规则、AI策略或隐私边界。
