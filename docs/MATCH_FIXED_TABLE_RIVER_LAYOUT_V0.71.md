# M3.60：固定牌桌与四座位真实旋转牌河

## 问题与修复

原有牌桌将各家牌河视为随弃牌数增长的 CSS 行/列，并在靠后的覆盖样式中启用了 `overflow-y:auto`。牌河出现纵向内部滚动、牌槽移动或与玩家手牌视觉挤压。左右河牌只是部分使用转向样式，缺乏稳定且可检验的坐标系统。

修复后，开局时每家牌河逻辑上**预留56个格位**；只在实际公开弃牌时填充对应位置，其余格位保持空白。56 = 55张初始牌墙可能出现的所有摸牌弃牌 + 庄家的首次打牌上限；碰杠抢走的弃牌仍作为已取走占位符留在原格，不再重复绘出实体牌。

## 同一套14×4牌河，按座位旋转

基础坐标使用本家（座位0）视角：第 `index` 张弃牌在 `r=floor(index/14)`，`c=index%14`（`r:0..3`，`c:0..13`）。一行从左向右放十四张，十四张之后换到下一行，固定高度从上向下排列。其他三家只是物理旋转：

| 座位 | 视角 | CSS网格 | 具体1基坐标 (row,column) |
|---|---|---|---|
| 0 | 本家，0° | 4行×14列 | (r+1,c+1) |
| 2 | 对家，180° | 4行×14列 | (4-r,14-c) |
| 3 | 左家，顺时针90° | 14行×4列 | (c+1,4-r) |
| 1 | 右家，逆时针90° | 14行×4列 | (14-c,r+1) |

第一张：本家左上、对家右下、左家右上、右家左下。从玩家本身的位置看，都是**先本人的左→右、再向下换行**，只是坐在屏幕另一侧的人“左右/上下”的屏幕方向不同。四个座位第0、13、14、55张弃牌的坐标已经写入 DOM 测试，按所有56个槽唯一且无重叠检查。

### 视图规范

- `data-river-index`：该玩家第几张弃牌；`data-river-row`/`data-river-column`：永久物理网格坐标；`data-discard-order`：来自服务器的全局公开弃牌事件次序。**几何方向变换不更改服务器数据时序**。
- 浏览器 CSS `grid-row/grid-column` 直接使用固定坐标，禁止让自动换行或 Flex 每次重新分配格位。左右侧牌面分别转90/−90°，上方牌面转180°，本家不转动。
- 摸切、手切、最近一张、胡牌与碰杠移走标识原样保留，被碰杠移走的牌不在牌河重复显示，但也不会导致后续格位前移。
- **牌河没有内部滚动区域**：`overflow:hidden!important`、固定4×14/14×4网格的轨道，行列数量不随牌数变化。主牌桌的中央区域、上/下玩家位置以及积分结算区在开局前具有固定布局高度；打出牌不增加牌桌高度。
- **本家14张手牌与河牌分区**：底部手牌拥有独立固定区域，右侧摸牌有单独间距；浏览器宽度足够时手牌无需滚动且保证不侵入中央牌河。对于很窄的手机，为确保牌面可点击，仍允许**仅本家手牌水平滑动**；牌河从不纵向滑动，也不会覆盖手牌。
- CSS 根据 `701px` 宽度门槛设置桌面与移动设备的预定义轨道尺寸；无须根据网络动作重新测量或调整布局。
