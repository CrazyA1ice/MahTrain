# M3.96：碰、杠、胡、过的合法行动参考与真实终局复盘

## 新增内容

以往仅能对“何切”作排序；玩家面对别人打牌提出的 `碰 / 明杠 / 胡 / 过`、别人补杠时的 `抢杠胡 / 过`，以及自己摸牌后的 `暗杠 / 补杠 / 自摸胡 / 不杠而出牌`，缺少同样明确的操作对照。

M3.96 在真正提供上述合法选项时，为**当事座位**计算有限公开信息下的操作建议，显示：

- 推荐操作（可能为 **“过”** 或 **“暂不杠，正常出牌”**）。
- **所有当次真实合法候选**，含不同类型、不同牌的可执行杠，不能自造胡牌或假操作。
- 每个候选的当时精确四川向听、未知有效张物理副本上界，以及可计算时的听牌基础番值加权参考、理由与限制。
- 胡牌由规则引擎确认合法后优先标记为**能够立即结算的确定机会**；这并不意味着理论上继续游戏绝不会得到更高长期报酬。
- 对其他操作以现有挑战级公开向听与有效张、75%门槛、天听保留、真实合法选项为基础做**弱、局部**策略参考；没有真实未知尾墙，不能宣称概率、全局最优或未来杠上花收益。

实现文件：`src/mahtrain_core/classic_operation_hint.py`。核心函数 `classic_operation_hint(view,seat)` 必须取得该座位的 `private_view(seat)`，无墙牌、对手暗手或未来随机抽牌依赖。用户在线只由 `classic_live_operation_hint` 授权座位0调用。

## 在线界面

- 新增独立只读 POST API：`match_operation_hint`，只接受当前会话令牌作为身份，不接收、信任或允许请求者自报其他座位。旧 `match_hint` 仍然只对应玩家当前何切，未改变响应协议。
- 原版2D牌桌：在出现操作窗口时自动读取，牌桌中央操作标题附“参考动作”，下方独立面板展示详细各选项的评估及理由；不会替玩家自动按“胡”“碰”“杠”。
- 经典网页牌桌：在实际操作弹窗显示推荐、各备选项及误差说明；关闭弹窗或状态推进后丢弃旧状态建议。
- 当服务器拒绝辅助读取、会话结束或网络断开，合法操作按钮仍然保持可用，不因推荐计算失败而阻断牌局。

## 四座位终局复盘

和既有四座位逐巡何切对照同样遵循可信瞬间：记录发生动作**之前**当前决定者的授权视图，保存 `terminal_review.operation_reviews`：

- 座位号、邻近可见步骤序号、实际选择（含 `pass`）、当时的参考选择、合法候选及向听/有效张/基础番值与解释；
- 即使选了“过”但没有独立公开事件，仍记为一次真实操作机会；按**邻近步骤**定位，绝不谎称稍后终局公开的手牌就是当时的决策输入；
- 真实切牌 `cut_review` 及旧归档仍然兼容；早期历史没有操作分数不能凭终局牌面补算；
- SQLite保存前 `sanitize_private_review` 按严格允许列表过滤；允许动作只为 `pass,hu,peng,ming_gang,an_gang,bu_gang`，必须校验候选、实际选择、参考标记、类型、座位和指标，抛弃注入的暗手/未来牌墙字段；
- 仅局终有经过审查的整局暗手回放。对局进行中**不会**提供其他座位的 `private_view`、AI可操作选项或推导出的暗手；实时操作建议也不通过公共动作回放发送。

## 下一步研究

“**最优行动**”还需要在多局真实完整净积分环境下验证。未来要建立严格训练/保留种子分组，比较风险衰减、合法碰后损失未来番型、尾牌杠分和抢杠成本，并把新增公共候选参考与真实胜负收益清楚分开。本轮提供**能够逐项比较并解释的操作推荐**，但不把启发式误写成已证明博弈最优。
