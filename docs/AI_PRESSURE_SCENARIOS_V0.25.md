# MahTrain M3.13：公开副露压力规则的定向合法牌形验证（v0.25）

## 为什么做这轮

M3.12 使用5个独立洗牌种子、25场四人对局，记录到完整挑战档203次切牌与无压力版本186次切牌：尽管有121次候选有效进张并列，公开副露压力并没有**一次**改变切牌。问题可能在于普通对局很难同时满足“其他活跃对手有至少两副同花色公开刻子”与“本人有效进张最大值仍并列”。本轮**不改动 AI 切牌规则**，优先用精确设计的牌形证明其触发条件可实现，并补齐反例。

## 定向场景的约束与真实性

每组输入是**人工构造的某次切牌决策快照**，并非经过游戏引擎从开局逐步重放的真实已发生牌局。快照由14有效张的本家手牌、他人已公开碰牌、定缺声明、已胡标记构成；按照108张万条筒物理牌校验单牌最多4张、公开刻子每副消耗3张、不碰本家缺门及公开刻子不能是对方缺门。未构造或暴露对手暗手、未来牌墙、下注与结算。

固定本家手牌采用“万4/5/6各两张、条4/5/6各两张、万9一张、条9一张”，本家缺筒。该牌形具有对称的万9/条9待形成将牌的结构。对手可公开碰万1与万2（本家无这两张牌）；公共副露压力仅作用于万牌，对应的牌效与向听通过项目**真实** analyze_discards 与 MahjongAgent.discard 计算，绝不 Mock 内部裁判数值。

五种定向场景：
1. 同一活跃对手碰出万1、万2，明确验证完整挑战与关闭压力的真实出牌不同。
2. 该对手只有一副万1明碰，压力规则不应该提前触发。
3. 两名不同对手各碰万1、万2，不能错误拼接成“一人两副同色”。
4. 同一对手公开碰出条1、条2，即使分数可区分，低风险的万牌已因固定牌序优先，不应该改切。
5. 两副万刻子属于**已胡退出的对手**，其副露不能继续被当作活跃威胁。

每组运行公开的实体牌库存校验、真实牌效分析、两个实际 AI 切牌函数和同局面影子诊断，输出是否具有有效进张并列、是否存在压力、是否真正改切等聚合布尔指标。进一步测试超过4张实体牌、公开刻子与定缺冲突、非明碰刻子和非法回合阶段都被拒绝。**物理可行不等于已验证完整状态机可达**，本轮不在文档里把构造快照当作真实完整对局。

## 运行

~~~bash
python examples/probe_pressure_scenarios.py \
  --json-out results/m313_scenarios.json \
  --csv-out results/m313_scenarios.csv
~~~

输出为中文终端统计、UTF-8 JSON 与带BOM的CSV。结果没有隐含的备选切牌牌种、对手手牌或后续牌墙。M3.12 原有的25局随机对局诊断命令保持不变。CI 的 Python 3.11/3.13 完整单测均执行真实算法的定向回归；独立任务另外运行命令行并存档上述两类聚合结果，另外还保留原有5种子×5轮换的完整AI对局回归。

## 分析边界和接下来要做的工作

本轮**证明的是局面级规则条件及行为可达性**，不是“防守真的更好”。即便压力改变了从万9到条9这样的出牌，也无法不看对手暗手就判定哪张必然安全。下一阶段应使用事件驱动合法状态机或无泄漏的受控采样获取更多这类局面，之后再谈被弃牌后的真实放铳风险、局内收益和更强的公开信息防守模型。杠钱及流局结算还不能用于正式胜率宣称。

## 五、已核验的 M3.13 专项实测（2026-10-16）

[GitHub Actions run #38923695373](https://github.com/CrazyA1ice/MahTrain/actions/runs/38923695373) 已通过 Python 3.11 和 3.13 的**各203项单元测试**、原有五种子25场四人回归和定向公开副露快照专项任务。CI 成功归档 `ai-pressure-scenarios-py311`（安全聚合的 JSON/CSV）及独立的 `ai-ablation-multiseed-py311`（历史真实对局分析）。

| 人工构造的本家14张决策快照 | 真实进张并列 | 公开压力可区分 | 开关风险规则后切牌不同 |
| --- | --- | --- | --- |
| 同一活跃对手公开碰万1、万2 | 是 | 是 | **是** |
| 对手只公开碰万1 | 是 | 否 | 否 |
| 两名对手分别碰万1、万2 | 是 | 否 | 否 |
| 活跃对手公开碰条1、条2 | 是 | 是 | 否 |
| 公开双万刻子的玩家已经胡牌退出 | 是 | 否 | 否 |

五个快照的物理牌库存都通过验证，没有使用 Mock 的向听/有效进张值。**五组中2组出现可区分的压力分数，只有1组真正改变了 AI 选择。** 正向例使用对称两花色牌形，完整挑战切条9，关闭风险平局规则切万9（该切牌对照仅在代码级测试中核实；公开聚合结果不导出未打出的另一张隐蔽牌）。

结论：M3.12 在实际随机对局中记录的零触发不是因为规则死代码；规则在人工构造的、物理牌数量可行的明确条件下确实会发挥作用。**但这五组不是完整状态机从开局演化的实战样本，也没有观察反事实切牌的后续胜负。** 下一轮优先尝试通过真正可重放的碰牌—摸牌—弃牌过程获得触发案例，或研究如何在保持对手暗手不可见的前提下改进覆盖率。
