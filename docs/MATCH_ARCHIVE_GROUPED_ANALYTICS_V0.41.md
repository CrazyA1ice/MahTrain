# MahTrain M3.29：历史对局按 AI 难度与房间规则分组（v0.41）

M3.28 已能显示四家长期总分与0号最近30局变化。本轮增加**分组描述统计**，回答“在不同 AI 难度组合/不同房间配置下，历史得分分别是多少”，但**不宣称因果关系、正式胜率或某策略优于另一策略**。

## 新对局公开参数存档

完成对局写入 SQLite 公开档案 JSON 时新增：

```json
"match_config": {"room_coefficient": 100, "fan_cap": 3}
```

这些字段来自服务端 WinLedger，必须分别为正整数、0至12之间的整数，并校验每条胡牌流水的付款金额等于房间系数×倍率，封顶番不大于房间上限。若存在方案A流局付款，还会交叉比对流局配置是否与胡牌配置相符。字段只包含已公开的规则参数，不包括任一家暗牌、随机种子、隐藏牌墙、账号信息、会话令牌；原 SQLite schema、旧 JSON 全部保留。

**旧档案缺少 `match_config` 时绝不猜测当年的房间系数和番数封顶**。它们依旧参与原有的总积分与有AI难度记录的组合分组，但不会纳入需要房间参数的分组，也不会被当作系数100处理。

## 两种分组视图

1. **按 AI 难度组合**：以1、2、3号座位的 `basic / advanced / challenge` 三档完整配置为组键。不是将每种AI单独视作因果变量，同一组可能混有不同的房间配置，因此提供 `rules_variant_count`（含未知配置）。
2. **按房间规则**：以 `room_coefficient`、`fan_cap` 共同分组。相同规则的对局仍可能使用不同AI阵容、庄家及不同牌墙，不能单凭原始分数判断难度或优劣。

每组统计0号玩家的：累计胡牌净额、方案A流局净额、正式总净额（不含可选模拟杠钱）、场均正式净额、正/负/零局数、样本数。另提供**按房间系数折算的场均净额**（有可信配置的对局才可折算），明确这只是去掉房间底分倍率的描述指标，不能消除不同番封顶、AI阵容或随机牌墙造成的影响。少于5局提示“小样本”；不推断标准差或显著性，也不写虚假胜率。

列表统计和 M3.28 赛况维持全部可核验对局为范围，与50条分页无关。新 `scorecard.groupings` 字段仅含预定义难度字符串、公开房间参数、整数分数和样本计数。未能核验的旧档案仍按 M3.28 的 `excluded_games` 处理；能核验但缺少分组参数时单独计 `missing_ai_games` 或 `missing_rules_games`。

## 本地验收

```bash
python -m unittest discover -s tests -v
node --check web/match_archives.js
node tests/test_match_archive_dom.js
python web_server.py
```

在“本地已完成对局档案”中展开分组区域，切换“AI难度组合 / 房间系数与封顶番”，查看各组成绩、少样本提示及历史缺失配置数量。旧档案无新增规则参数属于预期情况；用不同系数新开几局完成后可形成不同的规则组。

**后续**：若要真正比较策略强弱，应分别控制种子、庄家和房间规则，采用至少多种子、多席位轮换的配对实验，而不是把历史零散对局的均值直接作为胜率证据。
