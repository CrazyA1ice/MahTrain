# MahTrain M3.7：四 AI 多回合可视化复盘与统计面板（v0.19）

> 本轮是在已验证的 M3.6 **四个AI全程实际摸切**上提供本地网页、分阶段后台计算、四座位逐动作公开复盘及三档策略指标。只展示“当时公开”而非后验读取任意家的秘密手牌。四人完整规则仍是 `draft / enabled=false`，不能将这些结果作为已经正式定价的胜率排名。

## 一、网页新功能

启动本地服务：

```bash
git pull origin main
python web_server.py
```

访问 `http://127.0.0.1:8765` 并用 `Ctrl+F5` 强制刷新，在页面靠前位置找到 **「M3.7 · 四AI逐步复盘与难度统计」**。

1. 设置**起始种子**和**独立洗牌种子数**，网页一次可选择1或2个种子（分别生成3或6局，已经对每个种子做三轮座位轮换）。
2. 点击 **「开始多回合AI评测」**。计算耗时随机器与种子变化；服务端启动本地后台线程，不把长时间的牌效搜索堵在一次HTTP请求里。网页每隔约1.2秒刷新已完成局数，用户仍可操作其他训练模块。为避免占满本机CPU，当前只允许同时运行一份网页AI评测；最多保留4份会话记录，过期被逐出后需重新计算。
3. 任务完成后显示三档的**胡牌事件数／座位参与次数、放铳责任次数、最低向听切牌率、局部最优切牌率、平均向听劣势**，配有条形进度表示。这些是**真实摸切的局面统计**，不是正式血战胜率。
4. 在下拉菜单中选择一个**种子+轮换**的具体对局，用「上一动作」「下一动作」及**回放进度滑块**逐动作查看每家的**公开牌河、已公开副露、暗手剩余张数、定缺公开状态、剩余牌墙和已胡状态**。牌河中被碰杠/胡走的牌也可以看到已被认领的标记。
5. 点击 **「导出本局公开记录 JSON」**，将当前选中局面的公开快照和逐动作记录保存到本地浏览器；不包括未来墙顺序或对手暗手。

### 关于“每轮牌效变化”

三档AI的最低向听切牌率和局部最优率是从服务端每次的**真实动作前、已授权自家暗手+全局公开信息**计算的，因此面板可显示准确**按档位聚合**的牌效变化。由于本轮默认复盘坚持**公开牌桌模式**，不在每个对手当时的动作里公开私有向听数、有效张列表或私有合法碰杠胡选项。要做具体某家暗牌的事后讲解，应再设计一个明确的教学模式和经确认的信息公开时点，不能默认泄露。

## 二、隐私和数据安全边界

`src/mahtrain_core/ai_tournament.py` 的 `public_replay_frame()` 在每个真实动作执行**之后**从 `FourPlayerOpening.public_state()` 生成独立公开快照；这与引擎内部的完整 `trace` 区分开，后者用于服务端统计与命令行研究，不直接发送给浏览器。

- 公开回放动作只保留 **动作阶段、座位、公开操作、弃牌牌种、公开定缺和公开响应来源**；不下发 `legal_options`、单座位私有 `shanten_after`、`effective_copies` 或未来牌墙。牌墙只显示张数，`draw` 只显示有人摸牌而不会暴露摸到哪一张。
- 公开副露中若有暗杠，牌种仍是 `null`，仅显示**暗杠4张**；用户导出的回放 JSON 也遵循这个限制。
- **四家密封换三张和定缺**直到全部提交完成前，`missing_suits` 始终为 `null`，界面不得提前揭示已提交者的选择；换三张中选中的实际三张也不公开。
- 服务器通过随机任务令牌分别授权查看运行状态与已完成的单局公开记录。无令牌、错令牌、非法局数直接拒绝；输入种子需是32位无符号整数，一次不允许超过2个独立种子。没有在线账户体系或公网共享权限，继续只建议本地使用。
- 后台完整比赛只将事件整理到内存，**不持久化牌墙或私有手牌到网页**；网页导出明确使用已删减的 `steps` 数据。

## 三、主要实现文件

| 位置 | 职责 |
| --- | --- |
| `src/mahtrain_core/ai_tournament.py` | 每步生成原子公开复盘帧（公开牌河/副露/摸切状态），保留原有统计用私有中间计算，提供完成局数回调 |
| `web_server.py` | 后台自博弈任务、局数进度、限制并发、任务令牌、仅返回公开回放，绝不直接下发内部私有轨迹 |
| `web/ai_replay.js` | 难度指标条形对比、轮换对局选择、上下动作、进度滑块、四座位公开牌桌及本地JSON下载 |
| `web/index.html` / `web/app.css` | 独立 M3.7 区域、原有 Mahjong 牌面素材、响应式布局 |
| `tests/test_ai_tournament.py` | 原子快照与事件严格对齐、可复现、暗杠牌种不暴露、无私有向听或摸牌、完整座位轮换 |
| `tests/test_web_app.py` | 后台任务API、前端路由、令牌、非法种子/对局索引、公开快照过滤 |
| `.github/workflows/rules-tests.yml` | Python 3.11/3.13 全量单元测试、JavaScript语法、原有 M3.5基准及 M3.6整局冒烟 |

## 四、仍未完成的项目

- **多种子可信置信区间**：一次网页最多两种子、六局，对照成本可控，但不能拿三轮座次当作独立洗牌样本。真正胜率区间需进一步跑更多独立种子，明确独立外部对手并制定结算口径。
- **真正的含暗手教学模式**：本阶段只开放当时的公开牌桌，不能逐帧还原所有对手真实暗手；这是隐私设计，不是已实现的全知回放。
- **正式杠钱与流局结算**：杠钱底分是否等于房间系数、已胡者是否参与花猪/查大叫、缺门公开副露规则仍待确认。网页版AI统计不包含无法确认的正式净收益。
- **公网多人账户和长期保存**：后台任务与结果只驻留于本地服务进程，重启服务会消失；尚无用户登录、远程共享、后台排队和任务恢复。
- **更强AI**：原三档仍是启发式策略，不是经过人类对战验证的机器学习模型。

**M3.7 不是加入真人对局中的隐藏牌透视，而是让四AI自博弈结果可在浏览器公开地逐动作核验。**
