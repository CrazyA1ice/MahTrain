# M3.46 首页、模块化导航与真实人机对战历史数据图

## 问题与处理

原首页将连续训练、单题、AI研究、人机对战、历史战绩和规则演示全部纵向叠放，导致页面冗长、进入对应功能困难。现在根路径首先显示七张独立入口卡片：人机对战、历史战绩与统计、连续训练、单题训练、训练历史、AI研究、规则演示。点击某个入口只展示对应模块，使用井号路由 `#/match`、`#/archives` 等。每个子模块顶部有明确的「返回首页」入口。模块初始化和已有业务请求保留，切换页面不会销毁正在进行的人机对局、重排暗牌、启动一盘新对局或修改历史存档。

## 历史战绩可视化

在原有通过 SQLite 检验的已完成四人对局积分卡与近30局正式净额走势之外，新增：
1. **本人正净额、负净额、零净额局数占比**，用占比堆叠条展示；这是以单局最终正式净积分符号划分，而不是「胡牌胜率」。
2. **四家胡牌积分 / 流局积分组成**，四行对比、正负分不同方向颜色，并列显示正式总净额。横条按四家分量最大绝对值归一，仅为可视化尺度，不作为赢率/算法优劣推断。

两张图直接使用现有 `/api/match_archives` 返回的 `scorecard.seats`，没有使用随机或示例成绩。原有近30局单局/累计走势图、AI难度组合、房间分组、公开局面复盘继续可用。所有图表只针对核验通过的已完成本机对局，排除旧版缺少可确认账本的记录。实验杠钱不混入正式成绩。0至3号表示当局**座位**，三家AI不是固定不变的同一个人。

## 安全与兼容

首页导航使用原生 JS、CSS，不引入远端图表 CDN，也不更改服务端的私有手牌/牌墙接口。新静态 JS 明确加入服务端 allowlist。历史成绩请求只有打开战绩入口或刷新档案时触发。移动端首页卡片自动排列一列；电脑端三列，优先突出对战。

## 回归

- 路由进入/返回、入口全部可达及原有业务模块不被移除；
- 新 JS HTTP 路由可用；
- 档案统计图只消费真实 scorecard，完整空历史有文案；
- Python 和 Node DOM 回归验证不会泄露暗手及静态脚本缺失。

待真实浏览器验收：多种屏宽下的入口卡片布局、历史记录图表与原有实时对战操作。
