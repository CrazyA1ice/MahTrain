# MahTrain M3.20：多赢家入账动画与牌局结束复盘（v0.32）

## 本轮增加的三项能力

**一炮多响同时入账提醒**：使用后端公开 `win_settlement` 事件中已经提交的座位、胡牌番数、赢家实收额。若同一次真实规则动作包含多名赢家，回放中心在同一个**动作完成后**的公开快照上显示多个入账牌签，逐个以 CSS 动画出现。这里是同一动作的表现顺序，不表示各次赢家之间存在不同的可查询历史牌局状态。普通摸牌、尾摸与暗杠牌种一律继续保密。没有再次执行计分。

**逐笔胡牌详情**：四边牌桌内保留最近两笔实收摘要，增加可展开的全部胡牌记录，包括每笔赢家、胡牌方式、主番型、原始和有效番数、倍率、付款者、每人支付金额、赢家实收及附加番。金额完全来自公开的 `win_ledger.wins`，不是客户端计算。

**结束复盘报告**：仅当服务端最终阶段为 `finished`（三家胡牌）或 `wall_exhausted`（牌山耗尽）且客户端没有在播放公开中间帧时显示。四席各自列出真实胡牌次数、弃牌张数、公开副露组数、胡牌账本净额、可选独立杠钱试验净额；逐笔胡牌流水可查看；关键公开事件时间线最长展示末尾64条，并明确标识截断。没有触发胡牌也生成报告，不伪造收入。

## 正确性与保密边界

- `web/match_playback.js` 对公开事件做严格字段白名单，`win_settlement` 仅取合法赢家座位、非负整数实收及有效番数。不会把附带在事件对象上的隐藏牌墙、其他玩家私有手牌或暗杠牌面复制到前端可视帧。
- 一炮多响发生时，多个 `win_settlement` 仍属于**同一个真实规则步骤**，共用 M3.17 已保存的一个后置公开牌桌快照；页面展示独立入账牌签而不拆分虚构步骤。
- 复盘的胡牌余额与可选杠钱余额分开列示。流局查花猪/查大叫现阶段仍是未入账预览，不能显示为正式罚款、总净分或已支付金额；所有数字必须以服务器已有账本为准。
- 完整回放期间，即使最新 HTTP 响应包含即将发生的胡牌账本或终局信息，页面也不得在对应动作播放完成前显示未来的胡牌详情或终局复盘。

## 改动文件

- `web/match_playback.js`：安全提取同一个规则步骤中的多条已入账胡牌事件，合成一组安全支付提示。
- `web/match.js`：胡牌结算动画、逐笔展开、仅终局显示的四家复盘及关键动作日志。
- `web/index.html`、`web/app.css`：结算牌签、全部胡牌详情、响应式复盘四座位卡片。
- `tests/test_match_playback.js`：多赢家入账与隐藏事件字段不可见。
- `tests/test_match_board_dom.js`：模拟多赢家真实同一步公开入账、回放状态隔离、完整复盘及无胡流局。
- `tests/test_web_app.py`：页面新标识与资源代码检查。

## 手工验收

本地运行 `git pull origin main` 和 `python web_server.py`，访问 `http://127.0.0.1:8765`。进入人机对战、完成换三张与定缺后，选择慢速：多家同时胡牌时核对多个赢家的实收金额，不允许暗杠或未来墙牌露出。牌桌结算区域展开“查看本局全部胡牌详情”；摸切结束时查看四家复盘、真实公开关键动作列表。若牌山耗尽、未发生胡牌，仍应出现复盘但不得出现虚构付款。

本阶段未完善正式血战流局最终支付、未实现联网对战，复盘依据当前真实账本，不等于正式完整对局结算。
