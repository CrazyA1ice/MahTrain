# MahTrain M3.4：三档信息受限策略 AI（网页 v0.16）

> 从 M3.3 的“另外三家只是固定摸切脚本”升级为**三名各有独立决策状态、可以自选难度的启发式策略对手**。这是可玩规则子集上的**第一代规则/牌效 AI**，不是机器学习训练得到的模型，不代表已有完整四人四川血战的结算、规则配置确认、胜率校准或线上多人房间。

## 一、三档难度实际区别

| 对手档位 | 换三张/定缺 | 切牌 | 胡牌/碰杠 |
| --- | --- | --- | --- |
| 入门 `basic` | 从合法同花色三张中基于独立种子随机选择，换后选张数最少的缺门 | 已定义缺门优先；候选内使用可复现随机选择 | 合法胡牌自动胡；其余碰牌概率性尝试，暗/补杠适度尝试 |
| 进阶 `advanced` | 优先处理持牌较少的花色，避免平白丢掉易成型组 | 以**切后向听数最小**为第一排序；一致时采用固定牌序 | 胡必胡；在不退向听的前提下明杠，只有改善向听才碰，尽量保留天听资格 |
| 挑战 `challenge` | 与进阶档相同的基础选换逻辑 | 最小向听数优先；向听相同则最大化**基于本人牌与公开信息计算的有效进张枚数** | 胡必胡；在碰杠时避免明显后退向听，已有天听资格时不轻易碰牌 |

以上是**可以单元测试的规则策略差别**，而不是声称“挑战必胜、入门必输”或伪造胜率与思考深度。没有加入看穿对手暗牌、读取未来牌墙或全知蒙特卡罗。后续可用大量种子和固定基准对局做统计性强弱校准，并接入安全、弃张风险、番数收益等目标。

### 关键牌效限制

- 所有档位**必须由四人状态机批准合法动作**。确认可胡牌时，调用服务端完整规则判胡，不通过 AI 的猜测决定是否符合条件。
- 进阶/挑战档优先保留定缺规划、向听数和已认定天听资格；缺门牌优先切是**当前 AI 的明确启发式偏好**，不能偷换为已确认的全房间强制出牌规则。
- 挑战档在 14 有效张切牌时调用现有 `analyze_discards`；它只使用**本人的暗手/本人已公开面子、所有人可看到的弃牌及他人的公开副露**。弃牌被碰杠后会从“自由弃牌”可见计数里排除，因为该实体已算进公开副露；暗杠只公开牌张数，不公开具体牌种。
- 公开牌、本人暗手与自己的副露合起来计算可见张，**绝不遍历其他座位的隐藏手牌、墙前牌或墙尾牌**来“修正”挑战档有效进张。
- 三位对手各自的 `MahjongAgent` 维护独立伪随机状态，服务器以房间公开种子和座位编号稳定初始化，支持相同随机种子+相同难度+相同玩家操作的重放。种子是开发演示用，**不等于正式公平洗牌的安全协议**。

## 二、实际网页体验

```bash
git pull origin main
python web_server.py
```

打开 `http://127.0.0.1:8765`，按 `Ctrl+F5`。找到 **“四人血战 · 三档策略AI对战试验（M3.4）”**：

1. 你始终操作 **0号座位**，不需要选择其他人身份。分别设置 **1号AI、2号AI、3号AI** 为入门/进阶/挑战，默认三个档位各一人；还可以继续设置房间系数、封顶番数以及自愿开启的独立杠钱模拟。
2. 点击“开始响应试验”，自己看牌后选同一花色三张，AI 各自用其合法策略密封提交换三张；四家全部选好后交换。
3. 看换牌后的手牌、自己选择定缺，AI 使用各自真实换后牌型规划缺门。四家都定缺后，开始庄家先切、其余摸切和互相抢碰杠胡；如果用户有合法胡/碰/杠选项仍由用户自己决定，不会被 AI 自动跳过。
4. 页面展示三家**当前难度及策略简介**。可以持续观察不同种子下入门与挑战的切牌习惯差别，并在自摸、点炮或流局时使用现有积分/流局报告。
5. **AI 只操作自己的座位**；页面只返回0号暗手、公共弃牌、公开副露、现有余额，以及已知难度描述。各家隐藏听口和待摸墙不会下发。

## 三、代码和验收范围

- `src/mahtrain_core/ai.py`：全新三档策略模块，分离 `exchange / missing / response / kong / discard` 行为；引用既有 `shanten_13` 和 `analyze_discards`，不重复发明判胡或牌效排序。
- `web_server.py`：每个房间维护独立 `{1:MahjongAgent,2:...,3:...}`，每次只向 AI 注入它所属座位经过验证的 `private_view(seat)`，并交由正式牌权状态机校验所有动作。新房间参数 `ai_levels` 必须是长度**恰好3**、仅支持 `basic/advanced/challenge` 的列表，默认各一；不允许请求任意座位读取暗牌。
- `web/index.html`、`web/match.js`、`web/app.css`：三家独立难度选择及本局策略说明，保持之前麻将原始牌面与全部复盘面板。
- `tests/test_ai.py`：随机种子重现、108张守恒、三张同花色换牌、合法定缺、合法胡牌优先、固定牌组的最小向听与有效进张、可见牌不重计（含0号碰走的弃牌和暗杠）、注入伪造的对手暗手/未来牌墙不影响切牌判断。
- `tests/test_web_app.py`：校验服务端输入边界、独立选择三家难度、相同种子与操作的状态重放，以及 HTTP 响应没有对手暗牌或未来牌墙。维持 CI 的 Python 3.11/3.13、JS语法、单题与14轮、四人开局冒烟。

## 四、还未完成或尚未确认

- 这只是**三档启发式策略 AI**。尚未训练自博弈模型、没有对他人弃牌风险做有效概率学习、未提供 Monte Carlo 对局搜索，也不能宣称已经达到稳定测量的三个胜率档次。待后续基于公开信息加入攻防决策与独立 AI 评测套件。
- 完整四人规则配置仍为 `draft / enabled=false`。**杠钱底分与胡牌房间系数关系、已胡玩家在流局查牌收付款范围、公开缺门面子归属**均需确认；M3.3 账本只提供显式独立底分模拟和流局只读试算，未突然改成正式支付。
- AI 不代替真人做定缺或选择碰杠胡；固定种子仅供本地验证，不能用作线上公平安全洗牌；尚无账户、多用户身份认证、VRF 或正式公网部署条件。

**下一阶段建议 M3.5：建立 AI 能力的对照评测套件**。先比较各档在多个独立种子和完全相同公开局面上的选择，量化退向听率、有效进张、胜率与运算时间，再加入弃牌风险/收益策略，在测试证据支持后调整难度设计。
