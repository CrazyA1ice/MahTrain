# MahTrain 单人训练 UI v0.3：胡牌诊断、高清牌面与音效

> 当前版本：单人14轮网页原型。继承 `docs/SOLO_TRAINING_V0.2.md` 的升序理牌、自动胡牌/暗杠提示与尾牌补摸。本次修复来自用户提供的截图。**血战规则仍以 v0.4 规则说明为准**；训练界面版本 v0.3 不是川麻规则版本。

## 1. 为什么截图中没有“胡牌”弹窗？

截图左上进度为 7/14，右侧显示 **“本局定缺：万”**，但暗手牌里依然有万子。即使这副牌能构成四面子加一对将，也不能违反定缺而胡牌。

以该截图展示的典型结构为例：

```text
万：1 2 3 6 6
条：1 2 3 4 5 6 7 8 9
暗手总计 14 张
基本结构：123万 + 66万（将）+ 123条 + 456条 + 789条
```

这是一副**结构上已经完成**的牌，但如果当前定缺是「万」，这5张万没有打完，`legal_win=false`，所以不能弹出胡牌确认框；换成定缺「筒」，因手中不含筒，则可以进入合法胡牌提示。

现增加两层判定：

- `diagnose_win()` 分别返回 `structural_win`（四面子一对将/七对的结构完成）与 `missing_suit_tile_count`（尚持有多少张定缺牌）。
- `legal_win` 仅在**牌型成胡且没有缺门牌**时才为真。
- 页面手牌下新增显式提醒：例如“牌型结构已经成胡，但仍有5张定缺「万」，必须先打光”，缺门牌以金色边框标示；打光定缺后，如未形成胡牌则说明“尚未满足胡牌结构”。
- 合法胡牌时继续使用原有自动弹窗“是否胡牌”，杠后补牌亦会重复判定。不会因为结构完整就绕过缺门规则。

本问题已增加标准14张牌回归测试，确保同一结构在不同定缺选择下产生不同判定结果。

## 2. 大尺寸、清晰牌面

原因：仓库原来 `assets/tiles/*.png` 里不少是仅 **约62×80像素**的 JPEG 压缩图片（尽管后缀是 `.png`）；小尺寸显示和浏览器缩放都会影响清晰度，单纯把源图片拉大不能恢复细节。

处理方式：

1. `web/tile_art.js` 新增**27种麻将牌对应的原生 SVG 矢量绘制**（万、条、筒1-9），默认以高清矢量样式展示；放大不会像低分辨率 JPEG 那样模糊。
2. 桌面端主牌尺寸由原 **48×65** 提升至 **64×88**；暗手牌空间与杠区布局也已调整，在小屏幕上自适应换行。
3. 未能操作的牌不再统一透明淡化；定缺牌使用边框标示。标注“本轮摸牌”仅出现在一张对应的牌上，不再给所有同名牌重复贴标签。
4. 页面右上角提供“高清矢量牌面 / 经典原始牌图”切换，可随时对照。经典图依然使用旧素材，清晰程度受源文件分辨率限制。
5. 不更改原 `assets/tiles` 图片资源及文件名。

## 3. 摸牌、切牌、杠牌、胡牌音效

`web/sound.js` 通过浏览器原生 Web Audio 生成短音效，不依赖第三方库、不加载外部音频文件：

| 动作 | 音效 |
| --- | --- |
| 普通摸牌 | 轻柔双音 |
| 点击切牌 | 清脆短促的双层敲击 |
| 确认暗杠 | 三次节奏敲击，随后补摸牌音效 |
| 确认胡牌 | 四音上行提示 |

右上角有**音效开启/关闭**按钮。浏览器一般要求首次用户点击后才能激活音频，服务端判题成功后才播放对应声音。音效仅用于交互反馈，不参与任何规则或概率判断。

## 4. 启动方式

在仓库根目录运行：

```bash
git pull origin main
python web_server.py
```

本地浏览器打开：`http://127.0.0.1:8765`。

如果页面未更新，请先确保已结束旧版 `web_server.py`，重启后按 `Ctrl+F5` 强制刷新。注意不能把端口开放到公网：当前仅是本机开发原型，页面与用户会话存储在本地 Python 进程中。

## 5. 测试与边界

- `tests/test_win_diagnosis.py`：截图同类14张结构成胡、缺门未打光，无法胡；更换成合法定缺后可胡；七对与非完整牌型判定。
- `tests/test_web_app.py`：检查诊断数据、SVG与音效脚本能通过 HTTP 正常加载；原始低分辨率牌图 MIME 仍可识别。
- CI 执行 `node --check web/tile_art.js`、`node --check web/sound.js`、`node --check web/app.js` 及标准库 Python 测试。
- **未宣称高分辨率 JPEG 被修复**：经典旧素材仍是原分辨率；矢量样式是新绘制而非原图精确重制。
- 胡牌判定仍只覆盖完整普通胡与七对（含四同牌视作两对），支持已有明示副露结构，尚未实现十三幺等本项目未定义牌型；单人模式没有明杠、碰牌、补杠或四人完整算分流程。
