# MahTrain M3.22：已完成对局 SQLite 档案（v0.34）

## 功能

本轮在已有 M3.21 **浏览器会话中临时复盘**的基础上，增加**服务器端已经结束的四人真实对局**自动持久保存。对局阶段进入 `finished`（三家胡牌结束）或 `wall_exhausted`（牌山耗尽）后，由本地 Python 服务器在同一次操作中归档真实公开规则步骤、起手公开牌桌、终局公开牌桌、实际已入账胡牌余额与逐笔胡牌账本，以及独立杠钱模拟余额。每个完成会话最多自动归档一次；未完成的人机对局不保存。

新的**四人血战 · 本地已完成对局档案**面板支持：刷新档案列表、查看历史总场数/0号玩家胡牌净额平均数/已入账胡牌总笔数；勾选两局对比0号胡牌账本净额，明确不含杠钱与流局赔付；选择任意已完成对局，重新打开只读公开复盘，按玩家与动作筛选，逐条查看真实牌山张数、四家公开副露、弃牌与暗手背牌张数；下载 `mahtrain_<档案编号>.json` 完整机器可读公开复盘。

## 存储位置与隐私

默认数据库与现有单人训练历史共用 `data/mahtrain_history.sqlite3`，但使用**独立的 `completed_matches` 表**；不修改原有训练历史的 schema/user_version。也可以在启动服务器前通过 `MAHTRAIN_MATCH_DB` 环境变量给四人对局设置单独文件路径。

数据库的对局记录经过双层保护：Python 的 `sanitize_board`/`sanitize_events` 强制公开字段白名单，浏览器重新打开时仍用此前 `MahTrainPlayback.normalizeHistorySteps()` 再次验证。不保存真实洗牌墙、随机种子、会话令牌、任何玩家暗手身份、暗杠真实牌面或私有换三张选择。只展示事件已公开后的牌名以及真实规则动作完成后的公开状态，不能通过档案继续已经结束的游戏。这里是本地单人原型，能访问本机 loopback 服务及数据库的人也能读取档案，没有账号隔离或云同步。

后端每局最多保存末尾2048组已完成规则调用的公开快照；返回 JSON 中提供 `truncated` 告知省略的最早步数。浏览器历史 UI 最多显示最后200个匹配动作。胡牌已入账余额与独立杠钱试验余额分开列示；`wall_exhausted` 后的查花猪/查大叫依旧是未入账预览，不能称作正式完整血战最终结算。

## 技术改动

- `src/mahtrain_core/match_archive.py`：本地 SQLite 表、真实终局校验、严格字段白名单、档案列表与详情及摘要统计。
- `web_server.py`：每局收集公开规则步骤，终局自动落盘并返回 `match.match_archive_id`，新增只读 `GET /api/match_archives?limit=50` 与 `GET /api/match_archives?archive_id=...`。
- `web/match_archives.js`、`web/index.html`、`web/app.css`、`web/app.js`：独立档案列表、成绩对比、历史公开桌面查看与下载 JSON；不会改变 M3.21 当前对局的即时复盘。
- `tests/test_match_archive.py`：重启仍能读取、秘密字段不可存、非法档案号、与旧 SQLite 表共存。
- `tests/test_web_app.py`：真实 HTTP GET、错误响应、静态资源及两种文件视图。
- `tests/test_match_archive_dom.js`：真实前端脚本的列表/两局比较/复盘重开/筛选/导出链接/隐私。

## 验收

本地运行 `git pull origin main`，执行 `python web_server.py`，打开 `http://127.0.0.1:8765`。完成真正四人血战对局后滚动到“本地已完成对局档案”，点击刷新可见新记录。关闭服务器再启动，刷新页面后仍能重新查看该档案；勾选两条历史记录对比0号已入账净额，打开其中一条查看公开动作与牌桌，点击 JSON 导出下载。进行中的对局不会列入档案。

本阶段尚无线上账户或云同步，也没有正式完整血战流局结算。JSON 是结构化数据报告，而不是排版 PDF/HTML；后续可继续优化人类可读导出及跨局统计。
