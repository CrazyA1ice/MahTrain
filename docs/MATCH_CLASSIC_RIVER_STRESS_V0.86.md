# M3.75 · 经典 Majiang UI 四家 56 格牌河与副露互不遮挡

## 确认过的界面问题

E 方案继续使用原版 [kobalab/majiang-ui](https://github.com/kobalab/majiang-ui) 的真实 `He`（牌河）、`Shoupai`（手牌、碰杠副露）及原始万筒条 GIF。原版 Majiang 桌面使用 6 列 × 3 行的短牌河布局；MahTrain 后来将牌河扩展为**14 列 × 4 行的 56 格**，却没有同步搬移四家固定旋转牌河的位置。结果在长局中，左右两家弃牌会进入中央计分区或副露附近，看不清实际牌张。

**本轮不重绘牌图或 Mahjong UI 组件，不修改 Python 规则、AI、杠钱和会话机制。** 只在原版 800×680 坐标系中准确安放四个 56 格区域：

- 自己：靠下，局部从左到右、从上到下；
- 对家：靠上，实际 CSS 180° 旋转，从对家自己的视角由左至右；
- 右家：靠右，实际 CSS 270° 旋转，从右家自己的视角排列；
- 左家：靠左，实际 CSS 90° 旋转，从左家自己的视角排列。

四家牌河均与中央计分区有间隙；容器矩形也不互相重叠。特别修正了**CSS 270° 旋转时右家牌河沿正 X 方向展开**这一点，而不是按相反方向估算坐标。原版四家副露组件不改变，仍按公开碰、明杠、暗杠、补杠显示；不公开对手暗手。

## 验收测试

- `frontend_2d/test/browser-river-capacity.mjs`：用真实 Chromium 和原版 `Majiang UI.He/Shoupai` 进行 **四家各 52 格 → 四家各 56 格**的纯视觉极限压力测试，验证全部牌面图片存在、四家 14列4行坐标顺序正确、被碰牌原位留空、每家两个副露不遮挡自己的弃牌、牌河容器互不重叠及不覆盖中央信息、牌张不跑出固定桌面。
- `frontend_2d/test/bridge.test.mjs`：新增长牌河数据适配测试，四家各 56 格，全部原序位置与原位碰牌留空、数据不变。
- 现有的真实 Python HTTP 完整牌局、胡牌标记、语音、结算表、刷新恢复 Chromium 回归仍继续运行。

**注意：** 四家“同时每家 56 张弃牌”不可能来自只有 108 张实体牌的正常一局，这是故意构造的**前端几何压力测试**，不能把它当作真实四川麻将局面。真实牌局的全局验收依然由 Python 引擎进行。此类极端压力测试的意义是验证任一座位的牌河达到容量极限时，网页不会省略第56张，也不会覆盖相邻玩家或挤动整张牌桌。
