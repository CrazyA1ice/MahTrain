# MahTrain 单人训练界面 v0.4：原始牌面图、看牌后定缺

> **当前界面说明**，取代 v0.3 的“默认矢量牌面”描述。四川血战规则仍以 [v0.4 规则草案](SICHUAN_BLOOD_BATTLE_RULES_V0.4.md) 为准，本说明不是新的血战规则版本。

## 1. 原始麻将图片：已经找到完整素材

仓库现有完整牌图 [`assets/tiles/640x420.jpeg`](../assets/tiles/640x420.jpeg)，文件实际尺寸 **560×420 像素**（虽然名字是 640x420），包含一组明确的九列三行牌面：

- **第一行：筒1～筒9**
- **第二行：万1～万9**
- **第三行：条1～条9**

`web/app.js` 按该对应关系从**同一张完整原图**裁切展示27种牌，保持原来的麻将样式，不再默认绘制新的矢量卡面。裁切映射：列0–8，横向约每60像素递进；第一、二、三行起始坐标分别约25、103、180像素。网页同时保留万→条→筒分组及每门1→9理牌顺序。

新版手牌按钮**约74×97像素**（原版默认64×88），图片通过裁切铺满牌面，不再把小图裱进更大的白色卡框；因此视觉上麻将图案所占面积更大。展示比例会随手机屏幕自适应。

**清晰度说明**：原图中的单张牌面只有约46×60像素，放大后原有压缩细节无法神奇恢复；这里只做比例和裁切优化，没有伪称高清无损修复。若以后需要真正高清的传统美术牌面，可以更换高分辨率原始素材；目前不用逐张截图，也不用重新推断编号对应关系。

## 2. 定缺的真实时点及天缺

**正式四人血战开局**：

1. 所有玩家发牌，庄14张、其他13张。
2. 每位玩家**先看到自己起手牌**，再各自选3张同一花色进行换三张，待交换全部结束。
3. 玩家查看**换后的手牌**，然后四家**同时盖牌选择缺门**，不能在未看牌时定缺。选择记录为本局定缺状态，不从108张实体牌库凭空扣掉一张。
4. 若换后手中**恰好只有两门牌**，称为**天缺**，可直接定第三门缺少的花色。

这里“盖牌”先作为**同时进行的保密定缺声明标记**来设计；原文并没有规定定缺时要真实从手牌取出哪张牌，因此不擅自扣减手牌张数。

**当前单人连续训练（与四人正式流程分开）**：

1. 用户先输入随机种子，点击“**先发牌·看13张手牌**”。
2. 服务端使用该种子生成真实13张起手牌，在页面展示理好的起手牌；**不泄露牌墙之后的顺序**。
3. 用户看牌后手动选择万、条、筒其中一门作为定缺；只有两门花色时，提示“天缺”并可预选手中不存在的那一门（仍需点击确认）。
4. 确认定缺后才开始14轮训练；同一随机种子预览的手牌与开始后的手牌一致。
5. **注意**：单人训练仍**没有实际四家换三张过程**，所以天缺提示只说明本次单人预览手牌的分布，不能冒充完整四人对局的换后三张结果。

服务端 `/api/action` 的 `preview` 操作只返回玩家可看到的13张牌、三门牌数和天缺标记；`new` 操作必须提交一个明确选择的 `missing_suit`，不能再无声地自动替玩家决定缺门。

## 3. 仍然保留的训练能力

- 可点击手牌切牌，14轮连续摸切与每轮牌效说明。
- 满足标准胡/七对且定缺清空时**自动提示是否胡牌**，定缺未打光则显示剩余缺门牌数；不会只看牌型结构就胡牌。
- 手中四张相同牌时主动询问暗杠；确认后4张放进独立杠区且不可切牌，牌墙尾补一张，补摸后重新检查胡牌。
- 摸牌、切牌、暗杠、胡牌等独立音效；可以在页面关闭。
- 手牌、杠区、公开弃牌、切牌解析和最终成绩。
- 本地网页服务仍仅监听 `127.0.0.1:8765`，尚不支持四人正式对战、交换三张UI及真实碰/明杠/补杠。

## 4. 如何体验

在仓库根目录：

```bash
git pull origin main
python web_server.py
```

浏览器打开 `http://127.0.0.1:8765`，必要时先关闭旧服务后按 `Ctrl+F5` 强制刷新。具体操作流程：先点击发牌预览、看牌、选择定缺，最后点击开始训练。

回归测试：

```bash
python -m unittest discover -s tests -v
```

相关源文件：`web/index.html`、`web/app.js`、`web/app.css`、`web_server.py`、`tests/test_web_app.py`。不需要新图或外部依赖。
