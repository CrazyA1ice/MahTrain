# M3.84 · 经典 2D 牌桌：杠牌横牌按真实点杠者摆放

## 用户提出的布局规范

本轮专门修复经典 2D 血战牌桌的**副露牌面方向**。此前 `frontend_2d/src/bridge.mjs` 把日本麻将的 `+ / = / -` 转向标志固定绑定在画面座位上，导致同一家不论左家、右家还是对家点杠，横牌都没有跟随**实际点杠来源**正确变化。本轮不变更 AI 策略或血战麻将胡碰杠、杠钱、尾摸、抢杠规则。

在**每名杠家自己的从左到右视角**依次呈现：

| 类型 | 最终实体牌表现 |
| --- | --- |
| 暗杠 `an_gang` | 四张竖排：前三张牌背朝上，第四张亮牌面（历史未认证公开牌仍全部盖住） |
| 补杠 `bu_gang` | 原先碰出的三张竖排不动；自摸的第四张横着叠放在中间竖牌上方 |
| 明杠 `ming_gang`，左家点 | 三张竖牌 + 一张横牌，横牌在**最左侧** |
| 明杠，右家点 | 横牌在**最右侧** |
| 明杠，对家点 | 横牌**插在三张竖牌之间的中间位置** |

横牌不再按“显示的是 0/1/2/3 号座位”固定方向。明杠方向的计算采用公开的 `discards[].seat`（放牌者）和 `discards[].claimed_by`（吃进碰/杠的赢家）与 `tile`，得到**点牌者相对杠牌者**的坐席方向：`(source-owner+4)%4`，`3→左`、`1→右`、`2→对家`。四边麻将手牌本身的 0°、270°、180°、90° 父级旋转维持不动，因此横牌放置顺序对四位玩家都是各自视角成立。补杠仍可从原公开碰牌的弃牌记录追溯来源，但上叠的**第四张是自己摸的**，不混淆为原碰牌来源。

## 技术改动

- `frontend_2d/src/bridge.mjs`：读取已有官方公开弃牌的 `claimed_by` 与 `seat`，按牌种关联每个公开明杠或已经升级的补杠；既不要求服务器新增隐藏数据，也不篡改旧比赛账本。对于历史档案没有点牌来源的明杠，只显示“来源未知”的中间横牌，**不凭座位编造为右家点杠**。
- `frontend_2d/src/kong-view.mjs`：新的纯布局模型 `kongLayout` 与 DOM 绘制入口 `renderKongMeld`，在 `MajiangShoupai.redraw` 后替换**仅杠牌**的渲染节点。既有碰牌、手牌、摸牌、牌河、定缺、中央按钮保持原组件。
- `frontend_2d/src/mahtrain-bridge.css`：实体麻将牌采用本座位内固定横向单元，横牌 `rotate(90deg)`；补杠第四张叠在中间竖牌上方，不增加牌桌流布局高度；原版四边手牌座位旋转仍然负责整体方向。
- `frontend_2d/test/kong-layout.test.mjs`：检查 **四个座位 × 左／对／右三种来源**，再分别检查暗杠仅一张认证明牌、补杠叠置、未知历史来源、公开弃牌来源识别、非法/隐藏牌不会泄露。
- `frontend_2d/test/browser-kong-layout.mjs`：在实际 Chromium 页面交替模拟四边明杠左／中／右、四边补杠与暗杠，逐个检查横放位置、图像数量、三张牌背一张明牌、整体牌桌不随杠动作变大；保存各方向截图供查看。
- `frontend_2d/dist/`：构建并提交静态网页资源。**仅修改 src 而不更新 dist，不足以让用户 `git pull` 后直接通过本地 `web_server.py` 看到变化**，所以本次明确同步编译产物。

## 验证与注意事项

专项 GitHub Actions `M3.84 classic four-seat kong arrangement and built assets` 在功能测试通过后将 `frontend_2d/dist` 的完整构建资源提交到开发分支。前端构建、所有原有单元测试、座位方向单元测试，以及真正 Chromium 牌桌测试必须全部成功才合并。原规则引擎、AI 决策及计分没有更改，因此本轮不声称玩法强度提升。

浏览器端的 12 个来源方向与多种杠牌场景用的是**授权结构的合成公开视图**，用于验证绘制，不应把它误描述为 12 场自然发生的实战杠牌。实际正式对局仍由 Python 生成公开 `discards`、执行 `declare_kong` 与 `respond_discard`，不在浏览器引入另一套麻将规则。
