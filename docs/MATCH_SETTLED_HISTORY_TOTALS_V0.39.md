# MahTrain M3.27：多局正式积分与历史成绩对照（v0.39）

在 M3.26 已确认并正式入账的方案A基础上，历史档案开始同时展示两项**互不混淆**的指标：

- **胡牌净额**：原有 `win_b0`，只包含实际发生的合法胡牌收付款。
- **正式总净额**：新增 `settled_b0`，等于胡牌净额加方案A流局查花猪/查大叫已入账净额，**不包含可选模拟杠钱**。

## SQLite 兼容迁移

- 新创建数据库的 `completed_matches` 表通过已有 `CREATE TABLE` 初始化，再自动加 `settled_b0 INTEGER` 列。
- 老数据库启动时检测 `PRAGMA table_info`；如果还没有列才执行一次 `ALTER TABLE`，不更改 `PRAGMA user_version`，也不覆盖旧 `record_json`。
- 旧档案新列为 `NULL`，查询时使用 `COALESCE(settled_b0, win_b0)`：它们在当时没有正式流局入账，故正式总净额默认退回当时的胡牌净额。
- 已保存旧档案的公开时间线、胡牌记录、ID、JSON 下载与单人错题本均不迁移、不重写。
- `list_completed` 的 `summary` 新增 `average_player0_settled_balance`；原 `average_player0_win_balance` 保持原含义，便于历史统计不误比较。

## 页面

历史列表新增「0号正式净额（胡牌净额）」；选两局时同时显示正式积分差额与胡牌积分差额。进入单局详情仍能查看方案A逐笔流局流水、四家流局净额与已入账合计。独立杠钱依旧以**试验积分**标注，不加入正式总成绩。

## 测试

- 同一局中 `win_b0=0`、流局收支 `-800` 时，`settled_b0=-800`，同时保持旧胡牌指标为0。
- 真正创建旧版 SQLite 表（无 `settled_b0`），实例化新版归档器后验证迁移无损、空值回退、二次初始化无副作用。
- 浏览器 DOM 两局比较使用正式总净额差值，而胡牌部分作为并列信息保留。
- GitHub Actions Python 3.11/3.13、Node DOM 回归及 AI 基准通过后合并主分支。

本版本不假设有互联网账号、经济体系或正式胜率；只改善本地已完成对局的**可核对积分统计**。
