# MahTrain 项目初版设计稿（v0.1）

> 状态：需求讨论稿｜创建：2026-10-15｜训练评分原则补充：2026-10-16｜本阶段仅明确设计，不代表功能已实现。  
> 目标：四川麻将牌效训练 + 单人对三名 AI 的人机对战。  
> 优先级：先做**可验证的牌型/牌效计算核心**，再做训练交互，最后接入完整对局与 AI。

> **当前规则（2026-10-16）**：以 [四川血战到底规则 v0.4](SICHUAN_BLOOD_BATTLE_RULES_V0.4.md) 和 [v0.4 规则 JSON 草案](../configs/rulesets/sichuan_blood_battle_v0.4.draft.json) 为唯一依据，v0.1～v0.3 已作废。最新确认：天听后续摸切必须保持换三张后完整原始听口，**碰牌取消天听、杠牌本身不取消**；金钩钓+清一色+天听允许**原始6番**，所有番加完后再按房间上限（默认3番）封顶。

## 1. 仓库现状及产品定位

截至本稿编写时，main 分支只有简要 README 与 `assets/tiles/` 的万、条、筒各 1～9 牌面素材（共 27 种牌图，另有参考图片），暂无业务代码、测试、配置或 UI。应优先复用已有牌图，不预设现有实现与技术栈。

MahTrain 是一个面向川麻爱好者的本地优先训练/对战产品：

- **训练系统**：针对给定手牌分析和牌距离、进张/有效牌与概率，玩家提交选择后获得可解释反馈。
- **对战系统**：玩家对阵 3 个不同策略等级的 AI，完整处理规则、操作与多局计分。
- **共享核心**：两部分共享牌表示、牌型判定、向听算法、剩余牌估算及可配置规则，但训练评分目标与实战 AI 策略不强行合一。

### 当前规则依据及训练目标

首套玩法规则唯一当前版本：[v0.4](SICHUAN_BLOOD_BATTLE_RULES_V0.4.md)，[配置](../configs/rulesets/sichuan_blood_battle_v0.4.draft.json)仍为 `draft / enabled=false`；旧配置不允许载入。训练「局部最优切」保持向听优先、有效进张次之，额外关注规则约束内可能的收益。

已实现两项计算核心：`src/mahtrain_core/rules.py`（判胡、听牌、特殊番型与天听历史判定）和 `src/mahtrain_core/efficiency.py`（13有效张向听数、有效进张枚数与下一摸概率、14有效张局部最优切及并列排名），配套[29个固定规则/事件测试牌例](../tests/fixtures/win_fan_cases_v0.4.json)、`tests/test_rule_cases.py`、`tests/test_efficiency.py` 和 CI。**尚未实现连续多摸真实胡牌概率、完整对局状态机、计分账本与页面**。天听、天胡、地胡资格必须由游戏事件历史验证，不能仅凭手牌冒充。

### M3.4：三档信息受限策略AI（2026-10-16）

- `src/mahtrain_core/ai.py` 引入 `MahjongAgent`，分为入门 `basic`（有种子、合法随机切牌/响应）、进阶 `advanced`（最低向听、保留天听/谨慎碰杠）、挑战 `challenge`（最低向听基础上按公开信息最大有效进张）三档，可复现但**还不是经过机器学习训练和强弱统计验证的智能体**。
- 真实四人试验在 `web_server.py` 为1、2、3号座位分别生成状态独立的AI，替换上一版固定脚本。AI决策只获取**当前所属座位已授权的 `private_view(seat)`**；不会传入四人的隐藏手牌集合、未来牌墙或其他座位的天听基准。被碰杠的弃牌不可在公开可见张中重复计数；暗杠牌种仍不对外公布。

- `tests/test_ai.py` 与 `tests/test_web_app.py` 新增可复现性、合法三张换牌、缺门选择、合法胡牌优先、向听/进张最优检查、隐藏数据污染不改变AI决策、HTTP座位隔离和难度配置输入验证。

## 3. 牌效指标与“最优切牌”的定义

### 3.1 基础状态与术语

- 使用 27 维数组表示三门 1～9，每类 0～4 张。牌集、明牌、弃牌、杠牌分别记录，不能仅凭手牌计算实时余牌。
- **向听数**：距离满足当前启用和牌规则还需要的最少改善层级。约定和牌为 -1、听牌为 0、一向听为 1；可在界面显示“已和牌/听牌/一向听”，避免歧义。
- **有效进张**：摸入牌 t 后，按合法切牌/操作可令最小向听数下降的牌种；在听牌时对应直接和牌的牌种。
- **改善牌数量（枚数）**：按当前已知牌计算各有效牌的剩余可摸张数之和，不能只展示有效牌种数。
- **听牌集合**：当前 13 张手牌（及适用副露信息）加入哪类牌能合法和牌；定缺、七对等限制须参与判定。
- 训练题与对战都需记录规则版本和局面快照，确保相同输入得到相同结果。

### 3.2 概率口径（必须在界面写清）

设符合**所选信息模型**的未知可摸牌总数为 N，其中目标有效牌剩余总张数为 E，则：

- 下一次摸到有效牌概率：`P(下一摸有效) = E / N`。
- 只关心未来 k 次抽样至少出现一次该有效牌、且期间牌池不变/不计策略调整时：`P(至少一次) = 1 - C(N-E, k) / C(N, k)`（k≤N）；这**不是**多轮真实打牌的最终胡牌概率。
- 多步“在未来 k 次摸牌前听牌/胡牌概率”须另外基于枚举、动态规划或蒙特卡洛模拟，考虑每步切牌与规则，标明估算方法、抽样数/置信程度。

信息模型分两种：
1. **训练标准模式**：初始完整牌池扣除自身手牌及本训练已明示的牌、历史摸切；剩余牌均等抽样。
2. **对战可见信息模式**：只能扣除本方持牌、公共弃牌与公开副露/杠牌等可见信息；**不读取 AI 暗牌计算玩家实际可见概率**。若做对局回放全知分析，应明确标识。

### 3.3 已确认：训练采用“不退向听”约束下的「局部最优切」（2026-10-16）

**训练策略已确定**：以求稳为基础，任何合法切牌先比较向听数；不为了追求更高番数或远期收益而主动选择会退向听的切牌。在此约束内进一步比较有效进张、胡牌机会与潜在收益；将这种有明确约束的最佳选择称为 **局部最优切**。退向听换取更大潜在收益的打法记为未来的“进阶全局策略”，**不纳入首版训练判题**。

**精确定义（消除摸切阶段比较歧义）**：

1. 仅针对同一个摸牌后 14 张局面，枚举每个**合法**切牌 d，求其切后 13 张状态的向听数 s(d)；合法和牌是单独动作，不纳入何切排序。
2. 记 s_min = min_d s(d)。**不退向听候选集 D_local = { d | s(d) = s_min }**。这里的“不退”是“不比本轮最佳可达到的向听数差”，而不是把 14 张与 13 张不同阶段的向听值直接对比。
3. 首版**基础牌效排名**：只在 D_local 内比较有效进张的**剩余枚数**（亦即当前统一信息模型下下一摸改善概率）；在听牌时比较真实可胡牌张数及概率，必要时参考听牌形状。并列指标相同则承认**多个局部最优切**。
4. **收益感知的局部最优（规则明确后增强）**：依然只在 D_local 内比较；可用限定未来 k 摸的胡牌概率、可能番型及对应收益的加权期望进行排序，例如粗略指标 `P(未来 k 摸胡牌) × E[胡牌得分 | 胡牌]`。这只是便于理解的代理量，正式评分还要依具体番型、点炮/自摸、失分风险、可见信息以及决策策略定义，不能将最高番数单独当成最高期望收益。
5. 初版规则尚未确定时，界面**不输出虚构番数/期望分值**，而应显示“潜在收益分析待规则配置完成”；仍展示向听、有效牌、剩余枚数、概率和局部最优切。需要标注当前采用“基础牌效”还是后续“收益感知”排序。
6. **完全同分的切牌均应判正确**；若收益估算带有随机性，应使用统一种子、采样预算、误差阈值及并列判定机制，避免微小数值噪声导致误判。

**示意（虚构候选指标，用于解释评分逻辑，不是由具体牌例计算得出）**：

| 切牌 | 切后向听数 | 有效进张 | 潜在收益（暂未量化） | 首版处理 |
| --- | ---: | ---: | --- | --- |
| A | 0 | 6 张 | 一般 | 合法局部候选 |
| B | 0 | 10 张 | 可能较高 | 基础牌效局部最优 |
| C | 1 | 20 张 | 可能更高 | 退向听：排除出首版正确答案 |

B 的“局部最优”只表示在当前局面、当前规则及训练目标下的约束最优，不宣称是整场对局的全局最优。未来可以在高级训练中单独开放允许退向听、追求期望得分/风险收益的策略，不影响首版判题含义。

### 3.4 特殊判定

- 判胡和向听须同时支持标准四面子一将、七对及包含四张同牌的龙七对等已收到的牌型，并在判胡时应用**最多两门花色**限制；番型/附加番判定与向听计算分层，天胡、地胡、杠上花等依赖对局事件，不能仅靠手牌胡牌结构判断。
- **已和牌**：14 张牌如已合法和牌，应直接提示“已和牌”，不要硬推何切；清一色何切模式专门包含这一种题型。
- **清一色**：所有持有的手牌仅属于同一花色；如考虑副露，也要检查副露花色，设计初期清一色训练先默认门清。
- 对出现多解、重复牌、四张限制和定缺后不可和牌的边界必须有单元测试。

## 4. 训练系统

### 4.1 普通训练：单题模式

进入页面 → 选择“一向听何切 / 听牌何切” → 生成合规 14 张牌 → 玩家点击选一张切牌 → 提交 → 结果分析 → 下一题。

题目生成建议采用“候选手牌生成 → 规则与向听验证 → 切牌结果枚举 → 难度筛选”，不依赖纯随机碰运气；可设简单/中等/复杂，避免所有候选切牌一样或没有可解释差异。

结果展示：玩家选择与“局部最优切”（允许并列）的对照、每种候选切牌的切后向听数、有效进张列表与剩余枚数、下一摸改善概率，以及判断原因。明确标出会退向听的选项为何不进入标准答案；规则待定时不伪造番数或预期收益。

### 4.2 普通训练：单局 14 次摸切

- 初始随机发 13 张，独立训练牌墙按确定的随机种子洗牌。
- **一轮定义为：摸 1 张 → 形成 14 张 → 玩家选择切 1 张 → 回到 13 张**；共进行 14 轮/14 次切牌，不是连续取 14 张而不出牌。
- 每一轮展示当前向听数、各有效牌、概率及当前进度；做出选择后按本轮合法切牌集合计算“局部最优切”，给出向听约束与牌效差异的反馈，记录 14 轮全过程。
- 初版训练允许“标准 14 轮”即使提前听牌仍可继续（可配置提前和牌结束/继续教学）；当摸入即已和牌时，允许选择“和牌”并根据结束策略处理，不能要求先切牌。
- 已摸出/切出的牌更新可见牌统计；若模拟牌墙内牌量不足须重新发题，不得重复生成超过四张同牌。
- 结束页汇总：最优率、平均有效进张损失、向听变化曲线、重要失误节点、题目种子/可回放记录。初版只模拟个人摸切，不含碰杠与其他三家行动。

### 4.3 清一色：听牌选择

- 只产生合规 **13 张、单一花色、向听数为 0** 的手牌。
- 玩家多选认为能和牌的所有牌种（例如同一花色中的多个数字）；**完整集合**匹配才算全对，可显示漏选/多选。
- 展示每张听牌的剩余枚数及“下一摸和牌概率”；如定缺配置排斥该手牌，生成器必须过滤。
- 可提供限定听牌个数或听口复杂度的难度筛选，后续再增加限时。

### 4.4 清一色：何切

- 生成任意合法 14 张同花色手牌，覆盖未听牌、一向听、听牌和已和牌等状态。
- 玩家可以选择一张切牌，或在合法和牌时选择“已和牌”。
- 按照“不退向听 → 基础牌效 → 待扩展的收益感知”的局部最优切规则比较每种切牌；对于已和牌，明确识别胡牌优先，不把普通何切作为标准答案。
- 首版限制为闭门同花色题；杠后补牌及副露型清一色待扩展。

### 4.5 训练交互与数据

建议入口布局：
```text
训练中心
├─ 普通模式
│  ├─ 单题：一向听何切 / 听牌何切
│  └─ 单局：14 轮摸切
└─ 清一色模式
   ├─ 听牌选择（13 张，多选）
   └─ 何切与已和牌判定（14 张）
```

训练页面上部：模式、题号/轮次、规则预设及当前优化目标。中部：手牌可点击/已选突出；清一色听牌选择提供 1～9 可多选。下部：向听、有效牌、剩余枚数、概率和提交/下一题；结果面板展示分支对照，支持先作答再解析（默认不提前泄露答案）。保留“学习提示”开关以便逐步提示。

建议记录：`session_id`、题目模式、`ruleset_id`、随机种子、题目前后牌状态、玩家选择、最优解集合、评价指标、时间戳、结果与版本号；成绩统计不可只存一个对错值。

## 5. 人机对战系统

### 5.1 基本场景

- 固定四座：真人玩家 1 名，AI 3 名；可设 1、4、8、16 局或自定义局数（局数与“圈数/场”区分）。
- 牌墙、发牌、庄家、轮转、合法操作、碰/杠/和牌、流局、计分等由对局状态机管理。
- 游戏展示：手牌、其他玩家牌背/副露/弃牌、摸切动作、操作按钮、当前回合、剩余牌墙、当前分数、战报与场次总分。
- 支持开始新局、查看本场战绩、回放；暂停/续局与复杂断线恢复可后续开发。

### 5.2 AI 难度设计

| 难度 | 建议策略 | 性质 |
| --- | --- | --- |
| 入门 | 优先合法行动，基础向听判断 + 轻量随机性 | 适合熟悉流程 |
| 普通 | 向听优先，综合有效牌张数、定缺、基本副露/杠决策 | 主力难度 |
| 困难 | 结合剩余牌估计、听牌质量、收益/风险与有限步搜索或模拟 | 扩展阶段 |

所有难度都只接收**对应 AI 真实可观测的状态**，不允许依靠其他玩家隐藏手牌做决策；随机策略可用固定种子复现。难度提升不仅是更高胡牌率，还应体现更低的失误率及更合理的风险控制。算法基线及自动对战胜率需要后续实测，勿事先承诺效果。

### 5.3 多局计分

- 每局结算生成明细账本：事件（自摸、点炮、杠、查叫等）+ 规则来源 + 付款人与收款人 + 变化分数。
- 全场总分 = 各局逐人收支累计；结算前校验零和（如选择的是零和计分玩法）。
- 显示：本局各玩家得失、番型/番数/上限（若启用）、全场积分、历史局表、最终排名。
- 首套对战为**血战到底**：先胡者退出、其他人继续，一炮多响分别收款；牌墙耗尽且≥2未胡活跃玩家，就查花猪和大叫，即使有人此前胡过也一样。之前已胡的人是否参与结算收款仍待明确；详见[规则 v0.3](SICHUAN_BLOOD_BATTLE_RULES_V0.3.md)。血流成河另行规划。
- 收到的计算示例：系数200、自摸3番、三家未胡，赢家+4800、三位各-1600；系数100、自摸2番，赢家+1200、三家各-400；系数100、0番点炮，赢家+100、点炮者-100。以事件账本保证合计收支相抵。
- 结构番型原则上互斥取最高，**天听及金钩钓的获准复合例外单独累加**，再加杠上花/杠上炮/抢杠/根，最后统一按房间番数封顶（默认3番）；杠分作废后的冲账细节仍待确认。

## 6. 可配置规则与 v0.4 计番

- 唯一生效的规则规范：[v0.4](SICHUAN_BLOOD_BATTLE_RULES_V0.4.md)。JSON 配置 [v0.4 草案](../configs/rulesets/sichuan_blood_battle_v0.4.draft.json) 当前禁用，需待更多细则与端到端测试验证。
- 三门108张，庄家起手14张/其余各13张，牌墙55张；换三张强制同色、同步选择、随机方向，之后必须定缺。禁吃、允许碰/杠/一炮多响、血战继续。
- 原始番：平胡0，对对胡1，清一色/七对/天听/金钩钓2，清对/龙七对3，天胡/地胡/清七对4，清龙七对5。
- 结构型基础牌型通常只取合法最高项；**天听可叠加**且必须保持原听口；金钩钓与清一色可叠4番，与天听可叠4番，**三重复合可叠6番**；金钩钓与对对胡不得重复加番。附加根/杠上花/杠上炮/抢杠后整体按房间封顶，默认3番。
- 牌墙耗尽且≥2人仍未胡：查花猪和大叫；花猪认定为仍持有选定缺门的牌，不是必须持有三门。
- 需要对局历史才能确定的天听、天胡、地胡等事件不从单幅牌例直接产生。VRF、杠分冲账、部分查叫参与者与复杂副露裁决仍需测试与规则细化。

## 7. 共享技术设计（建议，非已决定）

### 7.1 推荐架构

建议前端 `React + TypeScript + Vite`，核心计算/服务 `Python + FastAPI`，测试采用 `pytest`；这是为了方便编写和验证牌效搜索算法，并非仓库既有技术选型。后续如需纯前端离线运行，可将确定性算法迁移到 TypeScript/WASM。

```text
Web 前端（训练 / 四人对战 / 战绩 / 设置）
             ↓ 统一 API
应用服务（题目生成、训练会话、对战控制、记分）
             ↓
共享 Mahjong Core
├─ Tile / Hand / Wall：牌表示与牌墙
├─ Rules：配置解析、合法动作、判胡与计分
├─ Shanten：标准/特殊手型向听
├─ Efficiency：有效进张、余牌、概率、候选切牌比较
├─ Trainer：题目生成、判题、连续14轮模拟
├─ Match：四人对局状态机、动作事件与结算
└─ AI：Easy / Normal / Hard 策略接口
             ↓
规则预设 JSON + 训练/对局记录（初期 SQLite）
```

算法不应依赖前端显示对象；同一核心 API 服务于训练答案和 AI 决策，但 AI 的信息视野与训练评分参数独立注入。

### 7.2 核心接口草案

- `POST /api/v1/hands/analyze`：输入手牌、规则、可见牌与目标，返回向听/胡牌状态/进张/概率/“局部最优切”集合及各候选被排除/排序的理由。
- `POST /api/v1/training/questions`：指定模式、难度、随机种子，返回可复现题目（默认不返回答案）。
- `POST /api/v1/training/answer`：提交选择，返回评分、最优集合及解释。
- `POST /api/v1/training/sessions` 与 `POST /api/v1/training/sessions/{id}/action`：建立和推进 14 轮训练。
- `POST /api/v1/matches`、`GET /api/v1/matches/{id}`、`POST /api/v1/matches/{id}/actions`：四人对局及操作。
- `GET /api/v1/rulesets`：列出规则预设与校验信息。

所有写动作由服务端检查回合、持牌和规则合法性，不信任客户端直接提交的计分、向听或牌墙结果。

## 8. 算法正确性与测试

优先写可回归的固定案例，避免 UI 做好后才发现评判错误：

1. 牌合法性：27 牌种、每种不超过 4 张、13/14 张边界、洗牌及摸切守恒。
2. 判胡：普通和牌、七对（按开关）、非和牌、已和牌与定缺不合规。
3. 向听：听牌=0，已和牌=-1，一向听=1；各种候选切牌必须与基准案例一致。
4. 有效进张：只计会改善向听的牌，且每种剩余张数正确，出现四张已见时余数为零。
5. 概率：`0 ≤ P ≤ 1`，信息集合变化导致分母/分子变化合理；对小牌池用手工组合数交叉校验。
6. 单题：存在并列局部最优时都正确；任意高收益但退向听的切牌不得误判为首版标准答案；14 张与 13 张比较需在一致的后切牌阶段完成，不能将不同优化目标混排。
7. 清一色：13 张选择所有胡牌牌种、14 张何切与已和牌分支。
8. 14 轮：13→14→13 的摸切不变量、精确 14 次、提前和牌处理、固定种子可复现。
9. 对战：AI 不见暗牌，强制换三张/定缺，庄家14张/牌墙55张、禁吃、碰杠及其支付、金钩钓与天听等特殊判番、一炮多响独立结算、血战终局及墙尽≥2人时查花猪和大叫；杠钱回滚与已胡者查牌参与范围未确认前不得正式验收。
10. 配置：规则不兼容时阻止启动、旧会话版本固定、关键番型与封顶规则测试。

建议先建立基准测试案例文件（输入/规则/预期向听/有效牌/最优切牌），再扩展题库和 UI。

## 11. 最小验收定义（v0.1 → v1）

- 玩家可进入四类训练子模式，系统不会生成不符合模式的手牌。
- 每次何切结果可解释：列出合法切牌、切后向听、有效牌及各剩余张数、下一摸概率，并明确展示“不退向听”约束下的局部最优切（含并列）与排除理由。
- 清一色听牌题采用完整集合判定；已和牌直接识别。
- 连续训练严格 14 次摸切并正确更新牌池/余牌信息。
- 对战时一名真人与三 AI 可依据已验证的血战规则进行多局：强制换三张与定缺、禁吃、三类杠钱、金钩钓与正确叠番、加番后统一封顶、一炮多响、已胡者退出，墙尽且≥2活跃玩家时查花猪和大叫；AI 不作弊。当前草案未达到正式启用前提。
- 关键算法用固定牌例测试验证，通过后才将训练正确率与 AI 难度作为可信指标。
