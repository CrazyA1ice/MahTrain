# MahTrain M3.17：真实逐动作公开牌桌快照（v0.29）

## 目标

不再只用 M3.16 的桌面中央文字动画描述 AI 行动，而是在每次真实规则动作完成后，由服务端保存那一刻的公开牌桌，让前端依次更新**剩余牌山、四家暗手背牌张数、各家公开副露、四家牌河及已胡状态**。座位与摸切/手切显示仍沿用之前的四边牌桌。

## 可信赖的数据源

`web_server.py` 中 `_match_record` 在每次真实 `FourPlayerOpening` 动作调用前记录公开事件游标，调用成功后执行 `_match_public_step`，从 `game.public_state()` 取一个**动作完成后**的真实公开快照。每组 `public_steps[]` 提供该动作产生的公开 `events` 和白名单 `board`：`phase`、`turn`、`wall_count`、`hand_counts`、`melds`、`discards`、`won`。不包含私有手牌、摸牌牌种、真实牌墙顺序或对手的隐藏定缺选择。

正常摸牌结束后，牌山真实减一、该家背牌真实加一；弃牌结束后，该家背牌真实减一、相应牌河多一张；碰牌/杠牌时，副露及被拿走的牌河状态来自已提交的规则事件结果，而非客户端猜测。已胡退出后的显示也跟随公开 `won` 状态。

**精度边界**：一次规则 API 调用可能内部发出多个事件，例如明杠同时执行了尾部补摸，或一炮多响包含若干单人结算事件。本轮把这些事件归在一次动作完成后的公开快照中展示，不声称中途存在可还原的服务器状态，也不生成虚假的内部帧。客户端仍不能真正暂停服务器 AI 思考：只暂停已执行动作的逐步可视化。

## 隐私与失败回退

前端 `normalizeSteps` 对每次公开快照再次逐字段白名单筛选，强制脱敏对方暗杠并移除任何意外混入的 `hand`、`drawn_tile`、`future_wall`。牌桌回放中自己的旧私有手牌会变暗，并明确注明“手牌牌面在播放结束后同步”；服务端最终私有视图到达时才更新本人的真实手牌与听口。即使跳过，最终仍使用服务端完整的真实权威状态。

服务端最多保留本次请求最近96组公开动作快照，客户端最多回放其中最后80组有可展示事件的动作。没有 `public_steps` 的旧版响应保留 M3.16 的公开事件浮层回退。若因极少数中间动作没有可展示事件而未产生一帧，下一次有意义的真实公开快照会直接展示此时累计的真实桌面状态。

## 改动文件

- `web_server.py`：`_match_record`、`_match_public_step`、在真人与AI规则动作后记录公开牌桌，HTTP 响应新增 `match.public_steps`。
- `web/match_playback.js`：`normalizeBoard`、`normalizeSteps` 与公开事件白名单；每帧完整公开状态都是真实动作后的值。
- `web/match.js`：接收真实公开快照并逐帧刷新牌墙、背牌、副露、牌河；本人私有手牌到最后才更新。
- `web/app.css`：本人手牌在公开回放时变暗，避免被误认成真实历史手牌。
- `tests/test_web_app.py`：真实规则状态机、HTTP 每步数据的公开字段核验。
- `tests/test_match_playback.js`：事件分组、数据白名单与暗杠信息保护。
- `tests/test_match_board_dom.js`：网页实际逐帧牌山、背牌、弃牌的 DOM 变化与跳过状态同步。

## 手动验收

运行 `python web_server.py`，进入人机对战，完成换三张及定缺。切牌后选择慢速，在 AI 摸牌时核对其背牌数增加、牌山减少；AI 打出公开牌时背牌数减少、对应牌河增加。碰杠和胡牌显示按真实公开副露及已胡状态刷新。中途暂停、继续与跳过均不能重复提交真实动作。AI暗杠仍不可见真实牌种。

本阶段未实现逐步恢复每家的真实历史私有手牌、更细粒度的杠内部账本中间状态，以及对服务器 AI 执行流程本身的暂停。不能把公开回放当作完整的墙牌/暗手历史模拟器。
