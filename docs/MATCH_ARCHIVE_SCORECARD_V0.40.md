# MahTrain M3.28：四座位多局战绩汇总与近30局走势（v0.40）

本轮是在已确定**流局方案A为正式规则**的 M3.26/M3.27 基础上，把只能逐局查看的四人对局档案扩展成可持续核对的**本机历史战绩总览**。

## 对局历史统计

- 读取 SQLite `completed_matches` 中**全部**已完成且能核验四家账本的档案，四个固定座位分别汇总：
  - 胡牌已入账净额 `hu_total`。
  - 流局查花猪/查大叫正式净额 `draw_total`。
  - 正式总净额 `settled_total = hu_total + draw_total`。
  - 场均正式总净额、单局正净额/负净额/零净额的局数。
- 仅0号代表玩家；1/2/3号代表**座位**，不是跨局不变的特定 AI，因为每局可重新设置难度。故不得据此断言特定 AI 的长期胜率。
- **独立杠钱模拟不纳入**三项正式金额。单局四家余额以及全历史按座位累加的三项金额都必须零和。
- 不能核验的旧/异常 JSON 档案**不被当作0分**：增加 `excluded_games` 单独计数；`valid_games` 是真实统计样本量。
- 正常 M3.22 旧档案只有胡牌账本时，读取时流局正式净额视为0；M3.26+ 新档案存在流局账本时，重新校验其参与席位、付款金额与零和，并验证 `settled_balances` 与“胡牌＋流局”一致；如果不一致，直接排除该档案。
- 汇总返回给前端的内容仅包含受控的座位号、整数分数、局数、随机档案ID和历史日期，不包含过去或将来的牌墙、任何玩家的暗手或实验种子。

## 0号历史走势

- 固定展示**最近30局可核验的已完成对局**，时间由早到晚。
- 每行以零为轴：左侧负值、右侧正值，同时标注该局正式净额与**从有记录以来累加的正式总积分**。
- 右侧累计成绩包含先前全部核验的历史局数，不是在最近30局重新从零算起。
- 分值比例只在当前展示的近30局内缩放，数值始终文本可读。不使用在线图表服务或向外发送记录。

## 接口与兼容

继续使用原有 `GET /api/match_archives`，在 `list_completed` JSON 响应中新增 `scorecard`：
`valid_games`、`excluded_games`、`seats[4]`、`trend[<=30]`、`zero_sum`。

旧有 `summary`、`matches`、`settled_b0`、胡牌及方案A收支指标均保持原含义。档案 JSON、SQLite 表结构、schema `user_version`、单人错题本都**不再修改**。

## 验收与回归

```bash
python -m unittest discover -s tests -v
node --check web/match_archives.js
node tests/test_match_archive_dom.js
python web_server.py
```

进入本机网站的“**四人血战 · 本地已完成对局档案**”栏目，刷新后可查看四席战绩卡片、最近30局0号正式净额和累计走势图，以及原有两局比较/逐动作复盘。

测试包含：胡牌与流局账本分离加总、四座位零和、近期时间排序和累加、列表分页不影响全历史汇总、无档案/旧档案/损坏档案排除、任意数值篡改不可进入总成绩和前端走势呈现。

**局限**：目前是本机所有完成对局的按座位数据汇总，尚未关联账号身份、锦标赛房间或学习算法，不能误认为正式联赛或固定 AI 战绩。
