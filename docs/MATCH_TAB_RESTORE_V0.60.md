# M3.48：浏览器刷新后安全恢复人机对战（v0.60）

## 场景与目标

之前首页路由只是隐藏正在进行的四人牌桌；**网页刷新会使 JS 中的 match token 丢失**，服务器实际还保留着未完局。M3.48 增加同标签页内的恢复路径。

- 服务端新增 `POST /api/action` / `{"action":"match_resume","match_token":"..."}`，仅能用服务端生成的随机 token 恢复**0号真人座位**的当前私有视图与四家公开局面，不接受自定义 seat，不返回另外三家的暗手、未来牌墙、内部洗牌种子，也不会执行游戏行为或推进 AI。
- 客户端 `sessionStorage["mahtrain.match.session.v1"]` **仅保存随机 token**，不会写入暗牌、其他 AI 手牌、牌墙、训练结果、房间规则或带隐藏信息的复盘。普通游戏初始/每次合法状态同步后保存；对局结束即清理，避免下次刷新误进已结束的对局。标签页之外不承诺恢复。
- 网页加载时，先检查同标签页 token，存在就自动只读恢复；之前的公开语音、动画不会再次播报或模拟执行，牌桌按真实当前服务端视图重画。**本次客户端复盘从恢复时的公开状态开始**，不会补造刷新前未记录的中间公开快照。
- 如果服务器仍有待执行的 AI 回合，恢复后只会在已确认当前状态的前提下延续现有顺序执行流程，并通过 token 校验阻止旧定时器操作新局。若轮到玩家碰/杠/胡/出牌，只呈现真实合法选项，不替玩家操作。
- 服务端重启、内存会话被淘汰，或 token 不再有效时，提示「会话已失效，请重新开局」，只清除本标签页凭证；不会偷偷创建另一局。若只是网络临时中断则保留 token，显示「重新连接原对局」按钮，允许用户重试。
- 用户手动开始新局仍遵循现有未完成对局确认，不恢复旧局的私有历史，不把未完游戏计入正式历史战绩。

## 限制和可靠性说明

这是**页面刷新级**恢复，不是永久存档、跨浏览器或服务端重启恢复。由于服务端内存会话最多缓存32局，旧 token 会失效；服务器重启后不会恢复未完局。另，用户关闭浏览器/标签页或禁用 sessionStorage 时无法保证该凭证仍存在。网页刷新期间已送达服务端的出牌请求可使服务器状态向前推进，恢复显示的是**服务端当前真实结果**，绝不再次提交上一次出牌请求。

## 验收检查

- 新 `match_resume` 请求不修改服务器 `public_state`、任何事件数和活动会话数；
- 虽然请求附加 `seat:3` 也只返回授权的 `seat:0`；
- 无效 token 返回HTTP 400；
- 在交换/定缺后恢复依然返回当前正确行动阶段和 `needs_continue`；
- 在 Node 假 DOM 中模拟重新加载完整 match.js，确认只发送一次 resume、不新开局，14张真人手牌真实复原、令牌只有字符串、不重播过往动作；
- 模拟失效 token，必须显示错误并移除旧凭证，不可凭空生成新局；
- 保留完整 Python 规则、档案及四AI回归。
