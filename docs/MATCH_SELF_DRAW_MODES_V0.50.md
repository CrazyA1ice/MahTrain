# MahTrain M3.38：自摸加底 / 自摸加番双模式（v0.50）

本轮不做手机适配，优先落实用户确认的新计分选择。在四人血战「随机开始一局」上方增加「自摸结算方式」，可选 **自摸加底**（默认）或 **自摸加番**。选择在开局时写入该局服务器账本，游戏中不能通过更改下拉框追溯改变已开局的结算规则。

## 算法和用户示例

设房间底分／系数为 `B`，按牌型和事件加番、封顶后有效番数 `f`，牌型基础倍数 `M = 2 ** f`。

| 类型 | 每位付款人实际付款 | 2番、底分100示例 |
| --- | --- | --- |
| 自摸加底（`add_base`） | `B * (M + 1)` | 每位付500，三家合计1500 |
| 自摸加番（`add_fan`） | `B * (M * 2)` | 每位付800，三家合计2400 |
| 点炮胡或抢杠胡 | `B * M`（不受上述选择影响） | 点炮者付400 |

**番数封顶先于自摸加番**：如果牌型4番、房间封顶3番，基础为8倍，自摸加底每家9倍、自摸加番每家16倍；自摸加番是支付倍数的增量，不改写牌型 `raw_fan`、`effective_fan` 或原牌型 `multiplier`。

只有当时尚未胡牌的其他玩家付款；如果只剩两名活跃者，赢家仅收另外一位的款，不能虚构三家。所有分账逐付款座位入账，保持四家零和。独立杠钱模拟与流局方案A查花猪/查大叫仍沿用既有逻辑，本轮不改它们的倍率；一炮多响分别按点炮规则结算。

## 老版本的兼容

- 网页前端始终提交明确的 `self_draw_mode`，默认 `add_base`。
- 未传该字段的原始 HTTP 客户端、旧测试或既有 AI 分析继续采用内部 `legacy` 旧版倍率（自摸每家 `B*M`），避免无声改变已有实验基线；这是**向后兼容保留的内部枚举**，不在新玩家规则下拉框列为第三种玩法。
- 新完成的本地 SQLite 档案存储已验证模式与实际付款，房间规则分组分析把两种模式列为不同组；历史记录不迁移、不补写、不重算。
- 档案保存时对每笔入账进行零和、付款人数、封顶番数、模式与房间系数的交叉校验；伪造模式或金额不能纳入有效统计。

主要覆盖：2番3家精确倍率、封顶3番真实首轮自摸、点炮/抢杠胡金额不变、无重复付款座位、四家零和、两种 HTTP 设置选择及非法设置拒绝、网页请求携带模式、可审计本地档案以及恶意篡改模式的排除。

**当前边界**：对人机对局启用新规则；历史 AI 配对实验维持旧内部模式，未来若要做两种规则下的正式 AI 积分对照，应固定房间系数、番数封顶和模式后重新采样，并分别报告，不得与旧数据混合。
