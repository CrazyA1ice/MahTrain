# MahTrain M3.8：AI公开决策解释与独立种子配对统计（v0.20）

> 本轮基于已落地的 M3.7 四人AI逐动作公开复盘和 M3.6 实际全回合自博弈。目标是让用户理解**哪些行为能公开解释、哪些统计才属于独立样本**。对局规则继续为 `draft / enabled=false`，AI仍为启发式策略；这里没有正式结算胜率，也没有私有暗手的赛后透视功能。

## 一、每一步的解释是什么，不是什么

`src/mahtrain_core/ai_tournament.py` 新增 `explain_public_action()`，在动作发生后只读取**已经脱敏的公开动作 + 当前公开牌桌**。每一个 `public_replay` 快照都有结构化 `explanation={code,text,scope:"public_policy_only"}`；浏览器复盘页面出现「本步解释（仅公开信息）」。

典型解释：

- **切定缺牌**：已公开这张弃牌属于玩家已经公开的定缺花色，可以说明三档AI都有优先处理定缺牌的规则。
- **入门档切牌**：说明按种子在其可选项内随机选择，不伪造详细进张理由。
- **进阶档切牌**：说明该难度的规则是优先减小切后向听，不对其他玩家公布本人暗手的具体向听值。
- **挑战档切牌**：说明其策略为最小向听→公开信息剩余有效进张→完全并列时考虑公开副露花色集中度的**弱风险信号**，但不会虚构“此步危险概率为x%”。
- **换三张、定缺**：保留密封提交语义，四家全部定缺后才能显示已公开缺门；不展示当时换出的三张或某人密封阶段尚未公开的选择。
- **胡碰杠声明**：所有应答完成以前只能看到「密封响应已提交」；等状态机正式裁决后说明「碰杠胡响应已裁决」，才有公开的最终结果。
- **暗杠、摸牌、自摸**：说明当前公开事件和牌权逻辑，绝不下发暗杠牌种、摸到的牌、私有胡牌手牌或私有听口。

**重要区别**：这是可复核的**规则级/策略级说明**，不是思维链、不是模型潜在推理、也不是某张暗牌对应的真实数值证据。原有独立 `trace` 仍供服务端算汇总指标，网页复盘只接收脱敏的 `public_replay`。

## 二、重新界定「独立样本」

M3.6中一个种子运行三次座位轮换，虽然实际打了三局，但**这三局共享同一初始牌墙排列，不是三个独立洗牌样本**。旧版只按档位整体汇总，本轮新增 `src/mahtrain_core/ai_seed_stats.py`：

1. 首先验证同一种子**正好有轮换0、1、2各一次**，三档对各个座位的参与机会严格平衡（每种子每档4次座位暴露）。
2. 分别计算每个**独立种子**的三档胡牌事件、放铳责任、实际切牌总数、最低向听切牌数、局部最优切牌数及对应比率；再给全体种子做“总成功次数÷总机会次数”的合并比率（不是把不同分母的百分比简单平均）。
3. 直接在**同一批种子**下比较「挑战－入门」「挑战－进阶」，报告**百分点差值**，覆盖胡牌事件/座位暴露、最低向听选择率和局部最优切牌率。共享初始牌序的座位轮换不会作为三个独立观测来重复提高样本量。
4. 独立种子不足 **5** 时，显示 `intervals=null` 和“样本不足”的明确提示，**不输出虚假的区间**。
5. 5个及以上种子时，用固定随机数发生器、默认**400次成组重抽样**，每次一次性抽取一个种子对应的**整组三局**，保持种子内的配对结构，计算探索性2.5%与97.5%分位数区间，包含各档比率和两组挑战档百分点差值。
6. 这一过程只描述**所抽种子的模拟变异**，不能证明真人对战胜率，也无法替代大量独立种子、独立对手、正式流局/杠钱赔付范围和对种子生成机制的审查。即使有5个种子，也只是**探索性区间**，不应表述为精确的95%泛化置信区间。

## 三、实际页面操作

```bash
git pull origin main
python web_server.py
```

浏览器打开 `http://127.0.0.1:8765`，按 `Ctrl+F5`，找到 **「M3.8 · AI决策公开解释与种子对照统计」**：

1. 可以选择 **1（3局） / 2（6局） / 5（15局）** 独立种子；5个种子需要计算15个完整对局，耗时明显更长，请等待后台进度，不要反复启动。
2. 运行结束后原有三档汇总仍然展示，同时显示**按洗牌种子分组表**和三项“挑战－入门/进阶”对照；不足5种子会明确显示无统计区间。
3. 选择具体种子及轮换，逐动作回放公开牌河、副露和新加入的「本步解释」；仍然无法透视各家的暗手。
4. 点击 **「导出种子分组 CSV」** 可下载每种子每档的实际胡牌/放铳/切牌计数和比率。原有「导出本局公开记录 JSON」不变。
5. M3.8的服务器仍**只允许一个后台自博弈任务并发**，最多保存4个本地任务；继续采用随机任务令牌，重启服务后结果消失，不适用于公网多用户认证场景。

## 四、命令行和 CI

原 M3.6 `tournament()` 输出新增 `seed_analysis`，JSON默认包含全部种子分组及可能的探索性重抽样区间。命令行 `examples/tournament_ai.py` 新增 `--seed-csv-out`：

```bash
python examples/tournament_ai.py --seed-start 11 --seeds 2 \
  --json-out results/ai_m38.json \
  --csv-out results/ai_m38_seats.csv \
  --seed-csv-out results/ai_m38_seeds.csv
```

从**5个以上独立种子**观察探索性区间：

```bash
python examples/tournament_ai.py --seed-start 100 --seeds 5 \
  --json-out results/ai_m38_validation.json \
  --seed-csv-out results/ai_m38_validation_seeds.csv
```

输入的种子数可由命令行扩展至100；单局向听/牌效优化比较耗时，建议按小批次运行。各结果只属于该具体本机的模拟环境，并非真人积分排名。

新增 `tests/test_ai_seed_stats.py` 用纯合成的、完全可核算的座位平衡牌例验证**轮换与种子配对区别、百分比求和分母、探索性区间可复现、错误输入拒绝、无弃牌时返回未定义而不是0%**。 `tests/test_ai_tournament.py` 核验逐动作解释只依赖公开牌桌，`tests/test_web_app.py` 核验网页种子界限、脱敏API和新控件。 GitHub Actions 同时在 Python3.11/3.13 下复测原有全部牌局规则，并保留带 `seed_analysis` 的完整对局 JSON 及独立种子 CSV 附件。

## 五、后续 M3.9

- **增加独立基准对手**：当前三档都是内部启发式AI，与本项目同源的牌效评估不构成独立算法比较；可引入明确规则的外部型基准策略，做固定初始牌墙的对照。
- **真正的教学深度**：若要公布特定对手当时的“具体向听/有效张”，必须有明确的赛后全员已结束及教学模式权限，不能污染逐动作公开牌桌回放。
- **正式计分**：杠钱底分与房间系数关系、已胡者参与流局查花猪/查大叫等仍待用户确认；不把模拟盈利当作正式净收益。

**本版本的底线：不会利用更丰富的复盘界面偷偷泄露隐藏信息，也不会将同一种子的三次轮换虚报为三份独立证据。**
