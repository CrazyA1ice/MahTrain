# M3.90 · 完成牌局的逐巡切牌差距解释和分阶段复盘

## 问题与改动范围

M3.88 已支持“全部、近一周、近一月、近一年”的服务器历史数据统计以及终局后解锁当时四家真实手牌。M3.89 增加逐巡切牌列表与前三候选跳转；但如果玩家实际切牌排名第 4 名或更后，原档案仅记录了 `rank` 和 `top3`，**没有保存该实际切牌自己的向听数和有效张指标**，因而无法审计“究竟差多少”。本轮只改变**已完成对局的复盘解释**，不改变任何当前对局选牌、碰杠胡、私牌可见性和积分结算。

### 服务器即时收集、终局才归档

- `web_server._match_record` 在 0 号玩家每次真实打牌前调用已有 `classic_hand_hint(private_view(0))`。它只基于该时刻玩家自己的牌、公开副露和弃牌来评分。此前已经计算好的候选列表现在额外取出实际所切的候选 `played_candidate`（就算其排名第 4 到 27 名）。
- 只保存当时已算好的 `shanten`、`effective_tile_count_upper_bound`、`fan_weighted_unknown_copies` 和 `reference_best`；不增加任何实时提示查询，也不重新回放后偷窥对手暗手或牌墙来计算“完美答案”。
- `sanitize_private_review` 严格检查实际牌必须与该巡真实弃牌一致、评分数字合法，其他字段直接丢弃；拒绝伪造牌和错误值。它依旧只能随**正式终局档案**保存，进行中 HTTP 和公开牌河不会包含该私有回放结构。
- M3.88/M3.89 历史档案仍可打开：已存前三和实际切牌相同者可在界面复用原有真实评价，否则显示“旧档案未保存完整评分，无法计算差距”，绝不虚构数值。

### 可审计的差距类型

新 `web/match_cut_quality.js` 以单独、无副作用的纯函数进行解释，严格依据原策略比较顺序：

1. **向听数退步**：当实际切牌的向听数比第一名更大，优先标记“退向听 N 级”。跨向听阶段不把有效张的简单差额宣称成损失，因为不同阶段的有效张并不直接可比。
2. **同向听数、未听牌**：如果第一名对应的未知有效张副本数大于实际方案，标记“有效张上界少 N 张”。张数是基于手牌与已公开牌的**未知张上界**，不是下一摸改善概率、墙内张数或必赢承诺。
3. **同为听牌**：比较按真实四川胡牌规则算出的“基础倍率 × 各未知胡牌张副本数”总权重；如权重落后则标记“番值加权上界少 N”，同时说明有效张差可以是负数（更多听口也可能输给高番权重的推荐）。不包括未来实际杠上花、海底、风险及完整博弈收益。
4. **最优并列**：依据原有 `reference_best` 与 `optimal` 标记，“符合当前策略并列最优”，不擅自改变第一名的含义。
5. **证据不足**：缺失实际候选数值、旧档案或评分顺序不一致，明确显示不可计算，不靠末局胜负倒推优劣。

### 整局前、中、后段分析

历史复盘的顶层新增**按本局已记录切牌顺序等分**的前段/中段/后段卡片，逐段显示：记录切牌数、符合最优数、向听退步巡数、同向听有效进张减少巡数、听牌番值加权落后巡数、无法评估巡数。不把这三段叫作固定的第几巡，也不对只保存部分步骤的旧版历史假装覆盖全局。原 M3.89 逐巡列表现在附带诊断标签，点击仍跳转真正保存的四家当时手牌和后三名比较。

### 核验与科研边界

- `tests/test_m390_cut_quality.py`：以真实 108 张合法物理手牌调用当前牌效建议并实际打牌，核对 `_match_record` 归档数值与当时实时算法严格相同；且历史完成前不能泄露完整隐藏资料。再检验第 4 名以后实际切牌及非法数据拒绝、旧档案兼容。
- `tests/test_match_cut_quality.js`：独立精确分类——跨向听不计算失真有效张差、同向听数有效张少 8、听牌即使多了 3 张未知张仍可落后 5 点番值权重、边界最佳、旧档案不可计算、六巡分三段。
- `tests/test_match_archive_dom.js`：打开真实历史页面结构，验证 50% 符合率、阶段损失统计、排名第 4 的真实评分文本、点击跳转对应第三步，以及删去新字段时“旧档案缺指标”的行为。
- 复跑 M3.88 全周期统计/终局隐牌权限/旧 SQLite 归档和 M3.89 逐巡导航。

**结论限制**：这里衡量的是当前项目策略在“当时可知公开信息”下的**推荐一致度与近视一步比较**，不是一个理性最优策略的证明，也不能把省下的未知张等同实际墙里的上牌；若未来更换推荐策略，应对存档注明评分版本，避免把不同版本的符合率当作完全可比指标。
