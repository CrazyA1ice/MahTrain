# M4.07：明杠补牌前的公开弃牌危险度研究（v1.17）

## 本轮目标

M4.06 已在 128 局自然终局对照中证明：开发组仅发生两次“明杠改碰牌”，种子簇结果一正一负；独立保留组没有真实干预。现有证据不足以让新策略替换正式挑战级 AI。本轮先把影响明杠后续价值的 **公开危险度** 纳入研究观测，观察自然样本中有多少真实同时可碰、可明杠的决策窗口。

## 决策前证据与严守边界

1. 使用真实规则引擎返回的同一 `claim_window` 中合法 `peng` + `ming_gang`，如果有合法 `hu`、抢杠窗口或只提供一种操作，直接保留原 AI 行动并跳过额外评分。
2. 从合法持牌中移除明杠占用的三张牌，在明杠**尚未从牌墙尾部补牌**时，仅对自己当前剩下的可弃牌种类调用 `read_discard_threat`。还有定缺花色要处理时，只分析本来合法的定缺花色。
3. 输出最小和最大的**启发式公开危险度指数**、该候选范围内仍具潜在响应能力的座位数、牌墙阶段及有两副以上公开副露的活跃对手数量。指数并非点炮概率，不能误当 `P(ron)`。
4. **尚未看到的杠后补牌不会进入候选**。如果新牌被直接打出，可能出现新的弃牌危险度，因此这组最小/最大指数只能描述原有持牌的候选集合，并非“所有未来弃牌的概率界限”。
5. 官方明杠名义付款是 `2 × KongLedger.base`；不设置底分就返回空，不推断现金。按 `WinLedger.room_coefficient × 2**fan_cap` 另外给出**每位对手达到封顶番的理论胡牌支付上限**，以及全部活跃对手都达到上限的极端合计。后者既不是预测损失，也不能与杠钱直接相加减。
6. 杠后弃牌被胡可以冲销对应杠钱；新的研究观测**不修改**这一权威规则、现有碰杠胡响应、挑战级 AI 的出牌算法、网页、API 或已归档牌局。

## 代码、测试与实验

- `src/mahtrain_core/ai_minggang_public_risk_audit.py`：实现授权的明杠弃牌危险度表；`PublicMingGangRiskObserver` 先调用原挑战级行动，再仅记录匿名统计。
- `tests/test_m407_public_minggang_risk_audit.py`：真实 108 张物理牌双选项、未定价/已定价杠钱与理论胡牌上限分离、对手暗手/未来牌墙污染不影响风险、非法状态拒绝、合法胡/抢杠快路径和真实终局对照。
- `examples/audit_minggang_public_risk.py`：固定新开发组 **38000–38003** 和独立保留组 **39000–39003**。两个组共 8 个独立洗牌种子，分别四席轮换，原挑战级 AI 与观察研究 AI 成对完整对战，合计 32 个位置、64 局游戏。两档策略应决策完全一致，官方终局净分及胡/杠/流局账本必须全部相等，否则实验失败。
- `.github/workflows/m407-public-minggang-risk.yml`：Pull Request 自动专项测试、两个独立自然对照组并保存匿名 JSON 审计结果。真实窗口数只有 CI 跑完后才能确认。

本地复现：

```bash
python -m unittest discover -s tests -p 'test_m407_public_minggang_risk_audit.py' -v
python examples/audit_minggang_public_risk.py --cohort development --seeds 4 --output results/m407-development.json
python examples/audit_minggang_public_risk.py --cohort holdout --seeds 4 --output results/m407-holdout.json
```

## 验收标准与局限

- 完全基于授权本人牌、公开弃牌/副露/定缺/房规；风险输出不含任何牌面名称、对手暗手、未来墙牌、目标对手可胡状态或赛后结果。
- 摘要按独立初始洗牌种子分组；不能将多个响应窗口或四个座位视为独立样本。
- **没有真正的候选策略干预，因此不能报告新策略获胜或收益改善。** 本轮首要目标是铺设可重复、不会读取作弊信息的风险研究特征，下一轮才检验其与实际明杠后点炮、杠钱撤销、流局查叫和终局正式净积分的联系。
- 发现自然同时可碰/可明杠窗口仍然稀少时，应增加新独立种子数，而非人工构造情节充当自然样本，亦不能在历史组上调参后称为独立保留验证。
