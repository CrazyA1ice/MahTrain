# MahTrain M3.0：四川血战四人开局与基础轮转预览（网页 v0.12）

> 此阶段是 **正式四人对战状态机的第一步**，不是完整可计分的人机对战。规则依据仍是[四川血战规则 v0.4 草案](SICHUAN_BLOOD_BATTLE_RULES_V0.4.md)；其中未确认的规则不擅自实现，配置仍为 `draft / enabled=false`。

## 1. 已落实的开局硬约束

- 四家、108张实体牌：万1–9、条1–9、筒1–9各4张，无字牌、花牌。每局随机指定庄家。
- 一次随机洗牌后，庄家14张、三个闲家每人13张，**墙剩55张**。庄家首先切牌，不能多摸一张。
- 四家**先看到自己的牌**；每家必须选择**恰好3张同一花色**、且是自己真实持有的实体牌，作为密封的换三张选择。
- 全部4家选择齐以前不交换任何牌；四家都提交后才**原子地同时交换**。每局随机选择顺时针、逆时针、对家之一，源座位 `s` 的牌交换给 `(s + offset) % 4`，其中 offset 分别为1、3、2。庄14张仍为14张，闲13张仍为13张。
- 交换完成后，四家能看交换后的手牌，才开始**同时盖牌定缺**：先密封各自的万/条/筒声明，全部4家提交后一起公开。盖牌在此为**独立声明标记**，不会扣掉实际手牌。换完后恰好只持两门牌的座位标记为“天缺”，无需额外创造/消耗牌张。
- 公开状态可显示庄家、换牌方向、各家持牌数、已经完成多少位密封选择、已公开弃牌、牌墙剩余数；**绝不包含其他玩家的暗手、尚未揭晓的交换牌和定缺声明**。
- 实际开牌、换牌、摸牌、切牌都检查4张上限与108张物理牌守恒，错误阶段、错座位、未持有的牌、重复盖牌等操作报错且拒绝推进。

## 2. 已有的轮转骨架

`src/mahtrain_core/four_player.py` 的 `FourPlayerOpening` 当前具备：

- `select_exchange(seat, tiles)`：四家各自密封的三张同花色换牌。
- `select_missing(seat, suit)`：换后四家同时盖牌定缺。
- `discard(seat, tile)`：庄家开局14张直接切牌；之后轮到当前拥有14有效牌的座位才能切。
- 每次切牌产生 `claim_window`（弃牌响应窗口），**不会偷偷忽略胡/杠/碰**。
- `pass_all_claims_demo()`：只用于演示的显式“所有人都过”，然后顺时针交下一座位摸牌。**此函数并非正式血战的碰杠胡判定**。
- `draw(seat)`：从前墙摸牌，待所有人过牌且确实轮到当前座位才能摸。牌墙耗尽标记为 `wall_exhausted`，但**未实现查花猪、查大叫或任何分数支付**。
- `public_state()`：所有玩家可看的无暗牌信息；`private_view(seat)`：仅供可信 Python 后端读取指定座位的暗手牌。不能凭网页提供的任意座位编号直接返回这一视图；必须有真实座位身份授权机制才能开放多人 API。

## 3. 网页的四人开局演示

本地运行：

```bash
git pull origin main
python web_server.py
```

打开 `http://127.0.0.1:8765` 并强制刷新，在**“四人血战 · 开局规则演示（M3预览）”**区操作：

1. 输入种子，点击“开始四人开局演示”，查看本人0号座位手牌和庄家位置。其他玩家暗手不会发到浏览器。
2. 在手牌中点选**3张同花色牌**；确认后其他3家用**固定脚本**提交，四家才同时换牌，并展示本人交换后的手牌。
3. 根据换后手牌，点击“定缺万/条/筒”；脚本完成另外三家密封定缺后一起揭示。
4. 若轮到本人切牌，点击手牌出牌；其他三家脚本切牌后自动轮回本人。轮转只是演示，**没有策略 AI**，胡、碰、明杠、暗杠、补杠、点炮和自摸结算都还未在四人模式接通，不要作为实战战绩或公平赛事来使用。

网页保留原来完整麻将牌面图和组内1→9升序；不影响现有14轮单人训练、题型训练、SQLite旧成绩或错题重练。此演示会话只存在本地 Python 服务内存中，重启后会丢失。

也可用纯命令行查看自动脚本过程：

```bash
python examples/four_player_opening_demo.py --seed 42 --turns 8
```

其输出会明确标注 `DEMO`，展示开局和108张守恒检查。

## 4. 自动测试

- `tests/test_four_player.py`：验证多种随机种子复现、庄14闲13、55张墙、四家交换前保密、牌量零增减、非法同花色/重复/非本家牌拒绝、四家同时揭示定缺、天缺时点、庄家先打、错误座位不能摸切、切后必须显式响应窗口、16回合守恒、公开/私有信息隔离。
- `tests/test_web_app.py`：本地真实 HTTP 用户座位0选择三张、定缺、观看模拟切牌；其他座位的暗牌不会出现在网页返回值。
- GitHub Actions：Python 3.11/3.13单元测试、Node.js静态网页语法、`four_player_opening_demo.py` 命令行冒烟、全部原有训练冒烟。

运行：

```bash
python -m unittest discover -s tests -v
```

## 5. **下一阶段仍须补齐的四人对战**

1. 弃牌窗口的完整多玩家合法声明：按**胡（包括一炮多响）＞杠＞碰**优先级，检查定缺、明杠/碰牌、取消天听等规则，不能由 Demo all-pass 代替。
2. 暗杠与补杠的完整状态、牌墙尾部补牌、补杠抢杠、杠上炮及已发杠钱的撤销与记账。
3. 赢家退出和血战续局、3家胡牌结束、牌墙耗尽且有至少2活跃玩家时查花猪、查大叫。
4. 按 v0.4 已确认番数/互斥关系的结算账本，并保留仍待用户确认的细则。
5. 真正的客户端座位授权、四人网络隔离、从真实多方交互升级1人对3个AI（基础、进阶、挑战）及可验证公平机制。

**特别注意**：目前的其它三家是无策略的**固定脚本**，不是AI，也没有完整对局合法性。不要把此里程碑命名为“正式四人血战已完成”。
