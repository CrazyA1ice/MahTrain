# MahTrain M3.18：碰杠胡动作链与长回放交互（v0.30）

## 本轮体验

1. **碰、杠、胡突出展示**：绿色碰牌、蓝色杠牌、金橙色胡牌，中心牌桌显示经过安全公开事件白名单筛选的动作类型与牌面，行动座位保持高亮。关键动作停留时间比一般摸牌/弃牌更长（碰1.4倍、杠1.7倍、胡2.2倍），仍可选快速/标准/慢速。
2. **真实的杠与尾摸衔接**：如果同一次规则调用同时发出 `an_gang` / `ming_gang` / `bu_gang` 和 `kong_supplement`，播放中以两个相邻文字标签明确标示动作链“杠牌 → 杠后补摸”。它们共享该次规则调用结束后的**唯一真实公开状态**，牌山与背牌张数不会被伪造出中间数值。暗杠、补摸的隐藏牌面绝不公开。
3. **公开局面差量说明**：按两个真实公开快照对比显示“牌山 -1”“1号牌背 +1”“2号副露 +1组”“牌河 +1”等变化。对照的是已提交的规则动作，不依赖对手隐藏牌。
4. **单步前进**：先暂停，然后按“单步前进”只进入下一条动作快照并继续停住；走到最后一帧后，再按一次完成回放并显示服务端最终的真实桌面。“暂停/继续/跳过”行为仍保留。变速会重新安排下一段时间，不会重提服务器操作。
5. **只看关键动作**：出牌前可以勾选“只看碰杠胡及最终动作”，则跳过普通摸切与无关注释帧，仅播放发生碰、杠、胡的规则动作以及本次响应的最后一个公开快照。最终真实桌面始终会更新，玩家的暗手按上轮规则只在播放结束后同步。
6. **播放参数始终可设置**：将 AI 速度及关键动作过滤选项移动到始终可见的牌桌上方设置栏，不再藏在播放途中出现的弹层里。暂停、单步、继续、跳过仍只在播放期间展示。

## 安全与时间精度

`web/match_playback.js` 继续对公开事件与服务器记录的公开局面做二次白名单，只使用 `wall_count`、`hand_counts`、`melds`、`discards`、`won` 等公有状态。尾摸和普通摸牌仅显示牌背；暗杠的具体牌种被屏蔽。`chain` 是经过白名单渲染的**文字动作链**，不是多份历史真实状态。服务端与 `FourPlayerOpening` 没有因本轮修改；人机 AI 仍在单个 API 调用内执行完整动作，暂停的是客户端播放。

焦点模式会缩短演示总帧数，不修改任何 AI 出牌或牌墙；最后一帧即使不是重要事件也会保留，避免动画结束前丢失最终牌局。动态差量仅在相邻真实快照中计算；过滤后的第一帧可能代表之前多个普通动作已经发生，但不会倒推不可见的单张暗牌。

## 文件与测试

- `web/match_playback.js`：安全动作链、帧的公开差量与重点标签、节奏倍率、`highlightFrames` 以及暂停时 `step()`。
- `web/match.js`：播放设置、关键动作模式、动画颜色类型、动作链/公开差量、单步前进。
- `web/index.html`、`web/app.css`：常驻设置栏、单步按钮和醒目的碰杠胡弹层。
- `tests/test_match_playback.js`：真实事件组合在同一规则完成态、暗牌保护、关键动作筛选、定时倍率和暂停单步测试。
- `tests/test_match_board_dom.js`：真实生产页面脚本的杠→尾摸与胡牌动作链、只看关键动作和单步 DOM 集成测试；保留前轮牌山/背牌/牌河的逐帧回归。
- `tests/test_web_app.py`：HTML 和静态资源的标识和入口检查。

CI 仍验证 Python 3.11 / 3.13、Node 实际 DOM 测试、五个独立洗牌种子×五座位布局共25局和定向压力场景。不会为了 UI 变更修改 AI 强度指标。

## 本地验收

运行 `git pull origin main` 后使用 `python web_server.py`，打开 `http://127.0.0.1:8765`。人机对战在出牌前选择慢速并勾选只看碰杠胡。触发 AI 碰杠胡时，检查桌面中央的动作链及牌山、牌背、副露与牌河；暂停后重复点击单步前进直到结束。然后关闭关键动作模式，验证普通摸切仍然按原顺序播放。AI 明暗杠与尾摸应只按服务器真实动作后的状态显示，不应出现私人牌面泄露。

未实现真正逐操作暂停 AI 规则引擎、完整历史暗手快照或正式的血战流局结算。
