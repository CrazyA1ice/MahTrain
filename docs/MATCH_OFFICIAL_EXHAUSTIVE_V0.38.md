# MahTrain M3.26：方案A正式流局查花猪 / 查大叫结算（v0.38）

**2026-10-17 用户规则确认：仅对尚未胡牌的活跃玩家执行查花猪、查大叫。已胡玩家不再收取或支付流局赔付。** M3.25 的方案B被明确排除，不再作为本局正式付款方式。

## 精确定义与入账时机

- 第三位玩家已胡使游戏进入 `finished` 时，不触发流局赔付。
- 真实牌墙耗尽、对局状态机进入 `wall_exhausted` 时，且至少两位未胡玩家存在，服务端计算本局剩余玩家的合法牌形；仅执行一次流局入账。
- **先查花猪**：尚未打光定缺牌的活跃者，向其他所有非花猪活跃者逐人支付 `8 × room_coefficient`。花猪之间互不支付，也不参与下一阶段。
- **后查大叫**：活跃非花猪中的未听牌者，向各位合法听牌者按该听牌者可以胡的最大封顶番赔付 `room_coefficient × 2^max_effective_fan`。只计算可合法胡牌的听口，未发生的天胡/杠上花等事件不凭空增加番数。
- 已胡玩家无论其退出时手牌、番数为何，均不参与两阶段。赢家的原有胡牌实际入账款仍然保留。
- 底分采用 **胡牌房间系数**，与可选试验性质的杠钱底分完全分开。

## 原子性、零和和例外保护

`finalize_active_only` 仅接收服务器内部重新计算的 `review_exhaustive_draw` 结果，独立验证参与席位、分类、赔付金额、付款顺序、封顶番和四家零和。实际游戏在完成 `wall_exhausted` 转移时调用一次 `_settle_exhaustive_once`；刷新网页、获取状态或重复函数调用不会重复扣款。

缺门副露含所定缺花色、或终局有效手牌不是稳定13张时，**暂缓这整笔流局结算**，返回 `posted=false` 和原因；绝不把未知牌形假装成已合法付款。当前规则引擎正常合法动作原则上不允许缺门副露，但仍保留防御性限制。

用相互独立的公开零和分类账：`win_ledger`（既有胡牌）、`exhaustive_settlement`（新增正式流局）、`kong_ledger`（可选试验杠钱）。`settled_balances` 为 **胡牌 + 流局正式入账**，`combined_balances` 为已入账项目再加上明确启用的模拟杠钱；后者不代表全部是真实结算款。原 `win_ledger` 含义不变。

## 用户界面与持久档案

- 牌桌下方清楚展示已入账的逐笔查花猪、查大叫，四家流局净额、零和状态及正式积分合计。
- 结束报告区分胡牌、流局与试验杠钱。
- SQLite 历史档案在不更改 `completed_matches` 数据表结构及旧指标 `win_b0` 含义的情况下，新增经过严格校验的 `exhaustive_settlement` 和 `settled_balances` JSON 字段；不保存隐藏的手牌、实际牌墙或随机种子。
- 已有历史档案仍可读取，原有的 `win_b0` 列和列表两局比较只涉及胡牌净额。完整流局净额在新档案详情、JSON 报告可见。
