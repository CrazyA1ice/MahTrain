# M3.64：AI公开动作与语音播报统一限制在1.5秒内

## 改动与边界

用户要求在人机对战中将AI出牌节奏与语音播报限制在1.5秒内。前端采用略低于1.5秒的上限留出余量：

- **画面动作停留**：`web/match_playback.js` 将普通动作、碰/杠/胡 `holdScale` 强调停留统一限为 **1400毫秒**。快速180ms、标准450ms（默认）、慢速900ms仍可切换，任何预设与倍数都不得突破上限。
- **浏览器语音播报**：`web/match_voice.js` 在开始每句公开语音时立即启动 **1300毫秒** 截止定时器；音频正常结束/报错后取消计时。超时主动调用 `speechSynthesis.cancel()`，而不是仅解除等待。下一句开始或关闭语音也会及时取消上一句及其定时器；旧句已结束的定时器不会误停新句。
- **兼容性**：以前供显式调用的 `announceFrameWait` 同样按1300ms超时并取消语音，但**正式人机对战只用非阻塞播报**，AI不能等待浏览器 `onend` 后才出牌。语音仍只朗读已公开的牌名，以及“碰”“杠”“胡”。
- **界面**：动作速度说明展示确切毫秒数并改为标准450ms默认；界面说明音频上限和真实服务端计算区别。

## 重要限制

这两个数字是**前端可控的计时上限**，不是服务器AI搜索/决策与HTTP传输的总耗时上限，也不是后台标签页的硬实时承诺。浏览器后台计时器可能受节流，Web Speech引擎停止也可能受平台调度影响。若服务器运算本身超过1.5秒，**不能为了显示速度修改它的真实规则结果或伪装出牌**。当前 `match-request-status` 会显示服务器这一步真实计算耗时，供后续定位慢AI的实际瓶颈。

某次HTTP响应可能包含多个连续公开动作，每个动作各自遵守画面上限；因此整次HTTP响应包含的完整动作回放不保证总计1.5秒。播放速度为0时仍直接展示服务器完成的牌局并仅异步播报语音。

## 验证

```bash
node --check web/match_playback.js
node --check web/match_voice.js
node tests/test_match_playback.js
node tests/test_match_voice.js
node tests/test_match_board_dom.js
python -m unittest discover -s tests -v
```

新自动化测试检查慢速下的杠牌强调动作被截断到1400ms，显式语音等待及正式非阻塞语音的1300ms硬停、旧计时器不干扰新播报，以及正常说话结束能清理计时器。原有动态牌河、碰杠胡和回放隐私测试继续在CI中执行。
