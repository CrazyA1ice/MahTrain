# MahTrain M3.46：功能首页与历史人机战绩看板（v0.58）

## 交互：一页一模块

此前所有功能集中在一个超长页面，难以定位和复盘。新的 `/#home` 功能首页将五个入口集中在五张卡片：

1. `#solo`：连续 14 轮摸切训练、本地训练记录及错题本；
2. `#quiz`：单题专项（何切、听牌、清一色）、单题成绩与错题；
3. `#match`：四人血战人机对战（原四边牌桌、模式、语音、AI 设定均保留）；
4. `#records`：已完成对局战绩、可视化、历史列表、复盘与不同配置比较；
5. `#lab`：AI 决策公开解释、独立基线对照、四人开局规则演示。

首页负责导航，模块间有返回首页／快捷模块入口。采用 URL hash，可刷新页面后回到指定模块；切换模块只变更可见的顶层容器 CSS 类，不清空/重建已有 DOM，也不发新的游戏请求或重置当前内存中的训练、对局状态。注意：**浏览器页面刷新**仍会重置原有服务器会话 token，尚未在本轮实现对局断点恢复；hash 只保存进入哪个功能区。

## 已完成对局的真实数据图表

依托既有 `/api/match_archives?limit=50` 响应的 `scorecard`（后端会扫描、核验全部已保存的本地 SQLite 完成对局），前端 `match_stats.js` 无第三方库动态绘制：

- 已核验对局数、正式积分累计、场均正式净额、0 号座位单局正收益占比；
- **近 30 局累计正式积分折线图**：按数据库已核验历史时间顺序，保留从历史起点持续计算的累计值。SVG 依次画点及路径，点的工具提示标示日期、单局净额、截至该局累计分值，含零基准线；
- **正／负／零净额局数分布**：以**全部**已核验的完成对局为分母，分开展示局数和占比，不将正收益率冒充「胡牌率」或「胜率」；
- 沿用四席总分、胡牌与方案 A 流局拆分、AI 组合／底分规则分组以及逐局详情和公开回放。

**口径保护：** 正式积分只包括胡牌和已正式入账的流局赔付，不包括独立模拟杠钱；对没有可核验账本的旧档案，沿用后端自动排除并显示排除数。折线最多展示最近30个数据点，累计值仍来源于**所有**可核验的历史记录。不同房间底分和 AI 阵容的统计不可直接作为策略强弱比较。没有对局时展示空状态，不造零分实验数据。

## 兼容和验证

无需迁移数据库、下载外部图表库或增加任何外部统计服务。静态 JS 在 `web_server.py` 注册；`web/app.js` 先初始化原模块，再开启导航；`web/match_archives.js` 在成功获取已有 scorecard 后更新战绩图。原训练、对战、公共档案 API 均未改动。

新增 Node 测试：
- `tests/test_module_navigation.js`：五模块卡片／快捷切换、hash 解析、非法地址回首页、不会重置进行中训练；
- `tests/test_match_stats_dom.js`：原始分值→KPI、SVG 趋势点、三种净额占比、无数据状态、公开口径；
- `tests/test_match_archive_dom.js`：真实档案 UI 请求响应到统计图的接线；Python 网站测试验证首页入口/脚本/资产服务；
- GitHub Actions 对新脚本做 Node `--check` 与独立 DOM 测试，并运行原有规则和真实 AI 回归。

```bash
node tests/test_module_navigation.js
node tests/test_match_stats_dom.js
node tests/test_match_archive_dom.js
python -m unittest discover -s tests -v
```
