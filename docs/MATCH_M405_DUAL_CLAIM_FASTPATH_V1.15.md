# M4.05：碰／明杠双选项快速路径与独立配对终局验证

## 前情

M4.04 已实现研究专用的 `pass/peng/ming_gang` 统一一阶牌效候选表，保持合法胡、抢杠胡必胡、天听原听口和线上挑战级原有自身暗杠／补杠全部候选排序不变。在预先冻结的开发32000–32003、保留33000–33003共8个独立种子、64局完整成对终局对照中，开发组**0次实际操作分歧／净分变化0**，保留组**3次操作分歧／平均净分+25**，且正收益集中于**种子33002**。仅4独立种子/组，不足以证明新策略稳定更强。

M4.04 实现对每个可碰或明杠窗口都先运行原挑战级评分，再额外运行统一候选表，即使该窗口只有一种积极行动。M4.05 聚焦真正会改变 `ming_gang` 与 `peng` 排序的情形：**两个积极行动均在同一官方授权窗口合法出现**，其余窗口直接返回原策略决策，避免无收益的额外评分。

## M4.05 精确行动与性能契约

- 真实官方 `claim_options` 同时包含 `peng`、`ming_gang`、没有 `hu`，且 `phase=="claim_window"` 才调用 `optional_claim_slate` **恰好一次**。综合评价包含 `pass`、`peng` 与 `ming_gang`；评估碰牌时必须列举碰后合法切牌，不重复计算被碰走的公开弃牌。
- 仅碰或仅明杠的窗口及只能过牌的窗口，**不调用额外候选评分**，完全保留已经经过验收的原挑战级策略。
- 已有 `hu` 或抢杠 `hu` 时不进入新评分，并强制检查原挑战级确实选择 `hu`；已有认证天听的碰牌禁止和明杠原听口保护仍由同一个合法候选表执行。
- 自身 `an_gang/bu_gang` 继续调用原挑战级对所有本家合法杠候选的评分器，不改变杠后补牌、抢杠多响、胡牌优先及正式结算。
- 受信任实验内记录每个真正双选项窗口的新旧动作**是否有差异**、研究臂是否真的改变了动作、额外评分器调用次数、原挑战级响应耗时与额外候选评分耗时（`perf_counter_ns`）；只输出汇总数和毫秒数，**不导出具体暗牌或任何未来牌墙**。
- 计时是研究运行机器上的*描述性测量*，不对其他硬件给出固定延迟承诺；不能只看总秒数，因为改变碰杠后两条策略路径会改变后续操作次数。确保 `extra_slate_evaluations==dual_active_windows`。

## 预注册独立自然配对

两组从未用于M4.04或M3.95–M4.03的固定初始洗牌种子：

- 开发组：34000–34007，8独立初始洗牌种子
- 独立保留组：35000–35007，8独立初始洗牌种子
- 每种子四种AI位置轮换，比较原挑战级 `baseline` 与研究专用 `dual_fastpath`，其他三席AI类型和参数完全一致。两组合计 **16独立种子×4轮换×2策略=128局正式四川血战对局**，64组成对座位。
- 每局核验牌种108张物理守恒、官方胡牌＋杠钱＋流局结算净分与四席零和；每个独立种子的四位置先求平均，再跨8独立种子求总体均值。
- 附带的研究臂在同一初始洗牌的另一完整对局中改变一次碰/明杠会导致后续墙牌抽取和对手路径随之改变，**不能假定后续牌墙和对手操作相同**。这只是正式终局的配对比较，不是持有未来暗牌知识的在线因果神谕。
- 如果自然双选项窗口很少，或多数种子没有真正操作变化，必须诚实给出零干预数，不按收益重新选择种子；**任何单轮4/8独立种子都不足以声称获得稳定最优AI**。

## 真实物理牌与安全回归

测试包括以完整108张物理牌分发的**真正可碰和可明杠同一窗口**，验证无需额外隐牌即可给出合法动作；单积极操作窗口不调用额外排序；双积极候选恰好算一次；合法胡／抢杠胡必胡；天听保持；两个合法自身杠候选全部交回已有评分器；私造的对手暗手、未来墙牌字段注入不能影响决策；非法候选／无效样本种子／积分账本异常不得静默吞掉。

### 如何运行

```bash
python -m unittest discover -s tests -p 'test_m405_dual_claim_fastpath.py' -v
python examples/compare_dual_claim_fastpath.py --cohort development --seeds 8 --output results/m405_dev.json
python examples/compare_dual_claim_fastpath.py --cohort holdout --seeds 8 --output results/m405_holdout.json
```

GitHub Actions `.github/workflows/m405-dual-fastpath.yml` 会运行专项测试和两组独立配对实验，分别归档 `m405-development-paired` 和 `m405-holdout-paired` JSON。**只有实际改变过行动且收益在更多独立保留种子上经受验证**，下一轮才考虑线上挑战级是否采用这一局部替换；否则正式AI保持原状。
